## 1. BadCase 状态管理（日常最常用）

### 交互式复审 pending badcase
```powershell
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.badcase_status review
```
逐条展示待处理 badcase，自动打开 Langfuse trace 页面，按键标记：`f`=修好 / `i`=误报 / `r`=待修 / `s`=跳过 / `q`=退出。

### 列出 badcase 状态
```powershell

D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.badcase_status list

# 只看待处理的
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.badcase_status list --status pending
```

### 查看状态分布
```powershell
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.badcase_status summary
```
输出各状态数量 + 回归集规模。

### 手动标记某条状态
```powershell

```

## 2. BadCase 采集

### 采集近 N 天的 badcase
```powershell
# 默认扫近 1 天
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.collect_badcase --days 1

# 扫近 30 天，强制重新处理已采集项
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.collect_badcase --days 30 --force
```
差评/低分/异常的 session → 写入 Langfuse Dataset:badcase + 本地状态注册 pending。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--days` | 1 | 扫描近 N 天 |
| `--threshold` | 0.6 | 五维分低于此值视为低分 |
| `--limit` | 200 | trace 扫描上限 |
| `--force` | 关 | 忽略已采集 stamp，全部重处理 |

> **通常不需要手动跑**——每日 02:13 cron 自动执行（`scripts/daily_collect_badcase.ps1`）。

## 3. 真实反馈门禁

### 查看好评率报表
```powershell
# 只看报表，不做门禁判断
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.feedback_gate --days 7 --report-only
```

### 做 A/B 门禁对比
```powershell
# 对比 production vs prod-a，好评率差 > 5% 则 exit 1
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.feedback_gate --days 7 `
    --ref production --cand prod-a --threshold 0.05 --min-rated 5
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--days` | 7 | 统计窗口 |
| `--ref` | production | 基准组 prompt_label |
| `--cand` | prod-a | 对比组 prompt_label |
| `--threshold` | 0.05 | 好评率差值阈值 |
| `--min-rated` | 5 | 每组最少反馈数 |
| `--report-only` | 关 | 只看报表不门禁 |
| `--fail-insufficient` | 关 | 数据不足时 exit 2（默认 exit 0 跳过） |

> **通常不需要手动跑**——每日 02:13 cron 自动执行。

## 4. 离线 A/B 实验

### Langfuse Experiment 离线跑（2026-08-30 新增）

从 Langfuse Dataset 选查询集离线跑实验，结果写回 **Dataset Run + trace/run 级分**，UI 的 Datasets → Runs 可对比多轮。实现见 `docs/langfuse平台/LangfuseExperiment离线实施方案.md`。

```powershell
# 选数据集 + 条数上限（badcase / goodcase / all）
python /app/src/agent/eval/run_experiment.py --dataset badcase --labels production --dataset-limit 50

D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.run_experiment --dataset badcase --labels production --dataset-limit 50

# Prompt A/B + 双门槛门禁（首 label=reference，掉超阈值 exit 1）
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.run_experiment `
    --dataset badcase --labels production prod-a --threshold 0.05

# 语义库 A/B：同 prompt 只换 wrenai 语义库版本（git ref 物化，按位置对应 --labels）
#   两个形态：db=ref（该库当前 git 仓库取 ref）/ db=<path>@<ref>（显式源拉历史版本）
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.run_experiment `
    --dataset badcase --labels prod-a prod-a `
    --semantic chinook_aliyun=v1.0.0 chinook_aliyun=v5.0.0

# 自定义 Dataset Run 名（默认 <label>:<ref>@<时间戳>）
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.eval.run_experiment `
    --dataset goodcase --labels production --run-name "my-exp-$(Get-Date -Format HHmmss)"
```

> 脚本已自动把查询集 `db_name` 归一化为 db_config 配置名（`normalize_db_name`：大小写不敏感 +
> 唯一物理库名兜底），badcase 条目小写 `chinook_aliyun` 会自动归一到 `Chinook_Aliyun`，
> 语义库 A/B 可直接生效（日志可见 `db_name 归一化 … → …`）。
> 归一化只影响语义路由判定；若某条仍走 B，是模型主动选直连（DDL/DML/多语句等），非路由阻塞。

> **Environment 属性**（2026-08-30）：实验 worker 自动注入 `LANGFUSE_TRACING_ENVIRONMENT=experiment`，
> 实验 trace 在 Langfuse UI 的 Environment 列标 `experiment`，与生产（`production`）/ 本机 dev（`development`）
> 一眼区分。该变量由 `env_loader.py` 按 `DEPLOY_ENV` 推导（prod→production，其余→development），
> 显式 export / 配置文件的显式值恒优先。实验 worker 覆盖为 `experiment` 只作用于子进程，不影响后端生产 trace。

结果落点：
- Langfuse UI **Datasets → 选中数据集 → Runs tab**（run_item→trace 关联 + 五维分 + run 级分）；
- Langfuse UI **Experiment 页**（2026-08-31 起，与 Dataset Run 并行）：worker 每条查询自动注入 `langfuse.experiment.*` 属性 → 同一 `--run-name` 的所有 item 归并为一个 Experiment 实体（`experiment_id=exp-<run-name>`），Experiment 页可直接对比多轮。仅当 item 带 dataset_item_id（`--dataset badcase/goodcase/all`）时生效；`--queries` 裸查询不产生实验实体。
- 本地 manifest → `eval/experiment_runs/run_<时间戳>.json`（如 `D:\nl2sql_data\workspace\eval\experiment_runs\`），每臂 JSONL → `.tmp/experiment/exp_<label>.jsonl`。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--dataset badcase\|goodcase\|all` | — | 从 Langfuse Dataset 选查询集，可与 `--queries` 合并去重 |
| `--dataset-limit` | 不限 | 单数据集条数上限 |
| `--badcase-status` | pending,reviewed | 状态过滤，传 `all` 包含全部 |
| `--semantic <db>=<ref>` | — | 语义库版本覆盖，可重复、按位置对 `--labels`；`db=path@ref` 拉显式源历史版本 |
| `--run-name NAME` | `<label>:<ref>@<stamp>` | Dataset Run 名（同 arm 所有 item 同 run_name） |
| `--queries` | — | 自定义查询集 JSON 文件路径 |
| `--labels` | — | 参与对比的 label（首个为 reference；≥2 才对比+门禁，单 label 只出分不门禁） |
| `--judge` | 关 | 追加 LLM-judge 打分（慢，控成本） |
| `--threshold` | 0.05 | 门禁阈值（overall + A 类双门槛） |
| `--timeout` | 1800 | 单 worker 超时秒数 |

## 5. Prompt 同步

### 同步主/子系统 prompt
```powershell
# 同步所有默认 prompt（main_system_prompt + nl2sql_system_prompt）
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.prompt.sync_prompts --all
PYTHONPATH=/app/src python /app/src/agent/prompt/sync_prompts.py --all

# 只同步某一个
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.prompt.sync_prompts --name main_system_prompt --file src/agent/prompts/main_system_prompt.md

PYTHONPATH=/app/src python /app/src/agent/prompt/sync_prompts.py  --name main_system_prompt --file src/agent/prompts/main_system_prompt.md
```

### 同步全部 skill 到 Langfuse
```powershell
D:\code_work_space\llm\nl2sql\.venv\Scripts\python.exe -m agent.prompt.sync_prompts --skills
PYTHONPATH=/app/src python /app/src/agent/prompt/sync_prompts.py --skills
```
把 `shared_skills_dir` 下每个 SKILL.md 同步为 Langfuse prompt `skill/{group}/{name}`。新增 skill 后跑一次，消除 `Prompt not found during refresh` 警告。

| 参数 | 说明 |
|---|---|
| `--all` | 同步所有默认 prompt |
| `--skills` | 同步全部 SKILL.md |
| `--name` + `--file` | 指定单个 prompt 同步 |
| `--label` | 打标签（默认 production + latest） |
| `--commit` | 变更说明 |
| `--force` | 内容未变也强制新版本 |

## 6. 每日自动任务（cron，无需手动）

### 生产（Linux Docker 容器）— 宿主机 cron + docker exec

生产部署在服务器 Docker 容器（weint 192.168.25.64，docker-compose v1 `env_file: .env.prod`
注入生产 LANGFUSE_* 与 AGENT_DATA_ROOT=/app/data），容器内无 cron，由宿主机每日触发。
容器名：`nl2sql-app_langgraph-api_1`；部署目录：`/home/weint/apps/nl2sql/nl2sql-app/`。

```bash
# 宿主机 crontab -e（日志目录需先存在：mkdir -p /home/weint/apps/nl2sql/logs）
13 2 * * * /home/weint/apps/nl2sql/nl2sql-app/backend/scripts/daily_collect_badcase.sh >> /home/weint/apps/nl2sql/logs/nl2sql_collect_badcase.log 2>&1
```

`daily_collect_badcase.sh` 用 `docker exec nl2sql-app_langgraph-api_1` 在容器内依次跑三步——
**采集 → 门禁 → 状态汇总**（数据源是 Langfuse API，不是日志）：

```bash
# ① 采集 BadCase → Langfuse Dataset:badcase
#    扫近 1 天 trace，筛 user-feedback=0 / 五维分<0.6 / ERROR / sql_exec_success=0
#    → create_dataset_item 写入 Dataset:badcase（本地 stamp 去重，同 trace 不重复采）
docker exec nl2sql-app_langgraph-api_1 bash -c 'cd /app && PYTHONPATH=/app/src /app/.venv/bin/python -m agent.eval.collect_badcase --days 1'

# ② 真实反馈门禁（M6）：聚合近 7 天好评率，按 prompt_label 分组对比，
#    candidate 好评率低于 reference−阈值 → exit 1（触发回滚/不放量）；只判断不写数据
docker exec nl2sql-app_langgraph-api_1 bash -c 'cd /app && PYTHONPATH=/app/src /app/.venv/bin/python -m agent.eval.feedback_gate --days 7'

# ③ 状态汇总（P0）：输出 badcase_status.json 各状态计数，提示人工复审待处理数量
docker exec nl2sql-app_langgraph-api_1 bash -c 'cd /app && PYTHONPATH=/app/src /app/.venv/bin/python -m agent.eval.badcase_status summary'
```

容器内 env_file 注入的 LANGFUSE_*（生产项目）自动生效，无需在宿主机配 .env.prod。
