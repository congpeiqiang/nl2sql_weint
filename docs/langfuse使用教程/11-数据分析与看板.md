## 1. Dashboard 总览

Langfuse 的 Dashboard 页面提供以下核心指标的可视化：

### 1.1 指标分类

| 类别 | 指标 | 说明 |
|------|------|------|
| **使用量** | Trace 数量趋势 | 按天/小时的请求量 |
| | 活跃用户数 | 按 user_id 统计 |
| | 活跃会话数 | 按 session_id 统计 |
| **成本** | 总成本趋势 | LLM 调用总成本 |
| | 按模型成本拆分 | 各模型的消耗占比 |
| | 单次查询平均成本 | 成本效率 |
| **延迟** | P50/P90/P99 | 响应时间分位数 |
| | 按步骤延迟拆分 | 哪个步骤最慢 |
| | 首次 token 延迟 | 流式场景的响应速度 |
| **质量** | Score 趋势 | 各评分维度的变化 |
| | 好评率 | user-feedback 正面比例 |
| | 错误率 | 执行失败/异常的占比 |

## 2. 成本分析

### 2.1 模型单价配置

成本计算的前提是在 **Settings → Models** 页配置模型单价：

| 模型 | Input 单价 (USD/1K tokens) | Output 单价 (USD/1K tokens) |
|------|---------------------------|----------------------------|
| gpt-4o | $0.0025 | $0.01 |
| gpt-4o-mini | $0.00015 | $0.0006 |
| deepseek-chat | $0.00014 | $0.00028 |
| qwen-max | $0.002 | $0.006 |

### 2.2 成本看板

```
本月成本总览：$45.23
├── gpt-4o: $32.10 (71%)
│   ├── Input: $12.80
│   └── Output: $19.30
├── gpt-4o-mini: $8.50 (19%)
└── deepseek-chat: $4.63 (10%)

```

### 2.3 成本优化建议

| 优化项 | 方法 | 预期节省 |
|--------|------|----------|
| 降级评估模型 | LLM-Judge 用 GPT-4o-mini 替代 GPT-4o | ~70% |
| 降低采样率 | `NL2SQL_EVAL_JUDGE_SAMPLE` 从 0.3 降到 0.1 | ~67% |
| 截断大文本 | `LARGE_RESULT_TRUNCATE_CHARS=8000` | ~20% output tokens |
| 使用 prompt 缓存 | 长 system prompt 使用 OpenAI cache | ~50% input |

## 3. 延迟分析

### 3.1 延迟分布

```
端到端延迟分布（P50/P90/P99）：
P50: 4.2s
P90: 12.8s
P99: 28.5s

按步骤拆分：
├── Schema Discovery:     1.2s (avg)
├── SQL Generation (LLM): 3.5s (avg) ← 最慢
├── SQL Execution:        0.3s (avg)
├── Result Summarization: 0.8s (avg)
└── Response Generation:  2.1s (avg)
```

### 3.2 延迟异常检测

| 异常类型 | 触发条件 | 排查方向 |
|----------|----------|----------|
| P99 飙升 | P99 > 基线 × 2 | 检查 LLM API 超时、网络延迟 |
| P50 上升 | P50 > 基线 × 1.5 | 检查 prompt 长度、模型切换 |
| 特定步骤慢 | 某步骤延迟突增 | 检查工具执行、数据库查询 |

### 3.3 嵌入延迟

本项目中嵌入模型的延迟特征：

```
嵌入模型（bge-m3）延迟分布：
冷启动: 13~17s（GPU 模型加载）
热调用: 0.3~0.8s（已加载状态）
超时阈值: 4s（超时被掐断 → 降级为纯关键词检索）
```

## 6. 告警与监控

### 6.1 告警规则建议

| 告警 | 条件 | 严重度 | 行动 |
|------|------|--------|------|
| 成本飙升 | 日成本 > 基线 × 3 | 🟡 警告 | 检查是否有异常查询 |
| 延迟飙升 | P99 > 30s | 🟡 警告 | 检查 LLM API 状态 |
| 错误率飙升 | 错误率 > 20% | 🔴 严重 | 立即排查 |
| 好评率骤降 | 好评率 < 50% | 🔴 严重 | 检查最新发版 |
| Langfuse 不可用 | auth_check 失败 | 🟡 警告 | 检查平台状态 |

### 6.2 健康检查脚本

```bash
#!/bin/bash
# health_check.sh - Langfuse 健康检查

HEALTH=$(curl -s http://localhost:3001/api/public/health)
if echo "$HEALTH" | grep -q '"status":"OK"'; then
    echo "✅ Langfuse 健康"
else
    echo "❌ Langfuse 异常: $HEALTH"
    # 发送告警
fi
```

### 6.3 Cron 监控

```bash
# 每小时检查 Langfuse 健康状态
0 * * * * /opt/langfuse/health_check.sh >> /var/log/langfuse_health.log 2>&1

# 每天生成质量报告
0 9 * * * cd /opt/nl2sql && python -m agent.eval.daily_report >> /var/log/daily_report.log 2>&1
```
