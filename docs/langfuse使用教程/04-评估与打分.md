# 04 · 评估与打分

> Langfuse 的 Score 系统是评估 LLM 应用质量的核心。支持四种评估方式：代码打分、LLM-as-Judge、人工评估、用户反馈。

---

## 1. Score 概念

Score 是 Langfuse 中存储评估结果的统一数据对象：

| 属性 | 说明 | 示例 |
|------|------|------|
| `name` | 评分名称 | `"sql-correctness"` |
| `value` | 数值（0~1 或任意范围） | `0.85` |
| `comment` | 说明文字 | `"SQL 语法正确但 JOIN 条件遗漏"` |
| `data_type` | 数据类型 | `NUMERIC` / `BOOLEAN` / `CATEGORICAL` |

Score 可以关联到：

- **Trace** 级别：整次任务的评分
- **Observation** 级别：某个步骤的评分
- **Dataset Run** 级别：实验运行的评分

## 2. 方式一：代码在线打分

在代码中直接调用 SDK 写入评分。

### 2.1 Trace 级评分

```python
with langfuse.start_as_current_observation(
    name="nl2sql", as_type="agent", input=question,
):
    sql = generate_sql(question)
    result = execute_sql(sql)

    # 对整个 trace 打分
    langfuse.score_current_trace(
        name="sql-exec-success",
        value=1.0 if result["error"] is None else 0.0,
        comment="SQL 执行成功" if not result["error"] else f"错误: {result['error']}",
    )
```

### 2.2 Span 级评分

```python
with langfuse.start_as_current_observation(
    name="generate-sql", as_type="generation",
    model="gpt-4o",
) as gen:
    sql = call_llm(question)
    gen.update(output=sql)

    # 对当前 span 打分
    langfuse.score_current_span(
        name="schema-match",
        value=0.8,
        comment="匹配到 3/4 个目标表",
    )
```

### 2.3 多维度打分示例

```python
def evaluate_and_score(question, sql, result):
    # 维度 1：Schema 匹配（确定性，同步）
    schema_score = 1.0 if schema_discovered else 0.3
    langfuse.score_current_trace(
        name="schema_match_score",
        value=schema_score,
    )

    # 维度 2：SQL 安全性（确定性，同步）
    safety = classify_sql(sql)  # read / write / ddl
    safety_score = {"read": 1.0, "full_dump": 0.4}.get(safety, 0.0)
    langfuse.score_current_trace(
        name="sql_valid_score",
        value=safety_score,
    )

    # 维度 3：执行成功（确定性，同步）
    exec_score = 1.0 if result["error"] is None else 0.0
    langfuse.score_current_trace(
        name="sql_exec_success",
        value=exec_score,
    )

    # 维度 4：业务正确性（LLM-as-Judge，异步采样）
    if should_sample():  # 按采样率决定是否评估
        biz_score = llm_judge(question, sql, result)
        langfuse.score_current_trace(
            name="sql_biz_correct_score",
            value=biz_score,
            comment="LLM Judge 评估业务正确性",
        )
```

## 3. 方式二：LLM-as-Judge（UI 配置）

在 Langfuse UI 中配置 LLM 评估器，自动对 trace 进行评估。

### 3.1 前置条件

1. 进入 **Settings → Models**
2. 添加评估用模型（如 OpenAI GPT-4o）的 API Key
3. 确保模型可正常调用

### 3.2 创建评估器

1. 进入 **Evaluations** 页面
2. 点击 **New Evaluator**
3. 配置评估器：

| 配置项 | 说明 |
|--------|------|
| **Name** | 评估器名称，如 `"SQL 业务正确性"` |
| **Target** | 评估目标：所有 trace / 特定名称 / 特定标签 |
| **Model** | 使用的评估模型 |
| **Template** | 评估模板（见下方） |
| **Sampling** | 采样率（0~1），避免全量评估的高成本 |

### 3.3 内置评估模板

Langfuse 提供多个内置评估模板：

| 模板 | 用途 |
|------|------|
| **Hallucination** | 检测输出中的幻觉（与输入/上下文不一致） |
| **Helpfulness** | 评估回答的有用性 |
| **Toxicity** | 检测有毒/有害内容 |
| **Context Relevance** | 检索结果与问题的相关性 |
| **Context Faithfulness** | 回答是否忠实于检索到的上下文 |

### 3.4 自定义评估 Prompt

```text
你是一个 SQL 查询评估专家。请评估以下 SQL 查询是否正确回答了用户的问题。

## 用户问题
{{input}}

## 生成的 SQL
{{output}}

## 执行结果
{{metadata.result}}

请从以下维度评分（0~1）：
1. SQL 语法是否正确
2. 是否正确理解了用户意图
3. JOIN 关系是否正确
4. 聚合和排序是否合理

输出格式：
{
  "score": 0.x,
  "reasoning": "简要说明评分理由"
}
```

### 3.5 查看评估结果

- **Evaluations** 页面：查看每个评估器的运行状态
- **Scores** 页面：按评估器名称筛选，查看分数分布和趋势
- **Traces** 页面：每条 trace 上会显示评估分数

## 4. 方式三：用户反馈（👍/👎）

用户反馈是最权威的评估信号。

### 4.1 前端集成

```python
# 后端 API：接收用户反馈
@app.post("/api/feedback")
async def submit_feedback(thread_id: str, message_id: str, rating: str):
    # rating = "positive" | "negative"
    score_value = 1.0 if rating == "positive" else 0.0

    # 写入 Langfuse
    langfuse.create_score(
        name="user-feedback",
        value=score_value,
        trace_id=trace_id,
        comment=f"用户{rating}反馈",
    )
```

### 4.2 查看反馈

- **Scores** 页面 → 筛选 `user-feedback`
- 可以看到好评率趋势、差评集中在哪些 trace
- 差评 trace 可以直接跳转到详情查看原因

## 5. 方式四：代码评估器（离线批量）

通过 SDK 批量对历史 trace 进行评估：

```python
from langfuse import Langfuse

langfuse = Langfuse()

# 获取历史 traces
traces = langfuse.fetch_traces(
    name="nl2sql-agent",
    limit=100,
    from_timestamp=datetime(2026, 10, 1),
)

for trace in traces.data:
    # 你的评估逻辑
    score = my_custom_evaluator(trace.input, trace.output)
    
    # 写入评分
    langfuse.create_score(
        name="custom-eval",
        value=score,
        trace_id=trace.id,
    )

langfuse.flush()
```

## 6. 评估最佳实践

### 6.1 多维度评估矩阵

| 维度 | 类型 | 成本 | 频率 | 适用场景 |
|------|------|------|------|----------|
| Schema 匹配 | 确定性代码 | 零 | 每条 | 基础质量 |
| SQL 安全性 | 确定性代码 | 零 | 每条 | 安全底线 |
| 执行成功 | 确定性代码 | 零 | 每条 | 可用性 |
| 业务正确性 | LLM Judge | 中 | 采样 30% | 深度质量 |
| 用户满意度 | 真实反馈 | 零 | 用户触发 | 最终判据 |

### 6.2 分数解读

| 分数范围 | 含义 | 行动 |
|----------|------|------|
| 0.8 ~ 1.0 | 优秀 | 保持 |
| 0.5 ~ 0.8 | 一般 | 关注改进 |
| 0.0 ~ 0.5 | 较差 | 优先修复 |
| N/A | 未评估 | 检查采样配置 |

### 6.3 告警与监控

通过 Langfuse Analytics 设置告警：

- 评分均值下降超过阈值 → 触发告警
- 差评率突然上升 → 检查最新发版
- LLM Judge 分数持续走低 → 检查 prompt 或模型
