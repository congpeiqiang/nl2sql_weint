# 09 · 常见问题与排查

> 使用 Langfuse 过程中的常见问题和排查方法

---

## 1. Trace 相关

### 1.1 UI 里看不到新上报的 trace

**可能原因**：

| 原因 | 排查方法 | 解决 |
|------|----------|------|
| 未调用 `flush()` | 检查代码末尾是否有 `langfuse.flush()` | 添加 `flush()` 调用 |
| Host / 密钥配错 | 检查环境变量或代码中的配置 | 确认 `LANGFUSE_HOST`、`PUBLIC_KEY`、`SECRET_KEY` |
| SDK 版本过低 | `pip show langfuse` 查看版本 | `pip install -U langfuse`（需要 v4.x） |
| 网络不通 | `curl http://host:3001/api/public/health` | 检查网络和安全组 |
| `LANGFUSE_ENABLE=false` | 检查环境变量 | 设为 `true` 或删除该变量 |

**快速排查脚本**：

```python
from langfuse import Langfuse

langfuse = Langfuse()
print(f"SDK 版本: {langfuse.version.__version__}")
print(f"Host: {langfuse.host}")
print(f"连通性: {langfuse.auth_check()}")

# 手动上报一条测试 trace
with langfuse.start_as_current_observation(
    name="debug-test", as_type="agent", input="test",
):
    pass
langfuse.flush()
print("已上报，请到 UI 查看")
```

### 1.2 trace 有但缺少 token / 成本信息

**原因**：`as_type="generation"` 的 `model` 参数未填写，或模型未在 Models 页面配置单价。

**解决**：

1. 确认 generation 的 `model` 参数正确：
   ```python
   with langfuse.start_as_current_observation(
       name="llm-call", as_type="generation",
       model="gpt-4o",  # ← 必须填写
   ):
   ```

2. 到 **Settings → Models** 添加模型单价

### 1.3 trace 嵌套不正确（子 observation 跑到了别的 trace 下）

**原因**：OTel context 没有正确传递，特别是在异步线程或跨进程场景。

**排查**：

- 检查子 Agent 的 CallbackHandler 是否正确接收了 `trace_context`
- 检查 `langfuse_parent_trace_id` 和 `langfuse_parent_obs_id` 是否注入
- 日志中搜索 `leaf nesting` 或 `orphan observation`

### 1.4 v4 SDK `langfuse.trace()` 报错

**原因**：v4 SDK 已移除 `trace()` 方法。

**解决**：改用 `start_as_current_observation(as_type="agent")`：

```python
# ❌ v2/v3 写法（v4 已移除）
trace = langfuse.trace(name="my-trace", input="hello")

# ✅ v4 写法
with langfuse.start_as_current_observation(
    name="my-trace", as_type="agent", input="hello",
):
    ...
```

## 2. 评估相关

### 2.1 LLM-as-Judge 没有触发

**可能原因**：

| 原因 | 排查 |
|------|------|
| 评估器未启用 | Evaluations 页面检查状态 |
| 采样率设为 0 | 检查 Sampling 配置 |
| 模型 API Key 未配 | Settings → Models 检查 |
| 模型调用超时/失败 | 查看 worker 日志 |

### 2.2 评分值不显示

**原因**：`value` 类型不匹配。

```python
# ✅ 正确：float
langfuse.score_current_trace(name="test", value=0.85)

# ✅ 正确：int
langfuse.score_current_trace(name="test", value=1)

# ❌ 错误：string（会被当作 categorical）
langfuse.score_current_trace(name="test", value="0.85")
```

### 2.3 用户反馈不写入

**排查步骤**：

1. 确认前端调用了反馈 API
2. 确认 `trace_id` 正确（thread_id → trace_id 的映射）
3. 检查日志中是否有 `user-feedback` 的写入记录
4. Scores 页面筛选 `user-feedback`

## 3. Prompt 管理

### 3.1 启动时 prompt 拉取失败

**日志表现**：

```
[langfuse] prompt 拉取失败，本地兜底: ...
```

**可能原因**：

| 原因 | 解决 |
|------|------|
| `LANGFUSE_PROMPT_ENABLED=0` | 改为 `1` |
| Prompt 在 Langfuse 中不存在 | 先执行 `sync_prompts` 上传 |
| 标签不存在 | 检查 `LANGFUSE_PROMPT_LABEL` 值 |
| 网络问题 | 检查连通性 |

### 3.2 修改 prompt 后不生效

**原因**：Prompt 在**服务启动时**拉取并缓存，修改后需要重启服务。

```bash
# 重启服务
# 停旧进程
netstat -ano | grep ":2026" | grep LISTEN
taskkill //F //PID <pid>

# 重新启动
.venv/Scripts/python.exe start_server.py
```

### 3.3 版本回滚

```python
# 查看当前 production 版本
prompt = langfuse.get_prompt(name="nl2sql_system_prompt", label="production")
print(f"当前版本: v{prompt.version}")

# 回滚到指定版本
langfuse.update_prompt_labels(
    name="nl2sql_system_prompt",
    version=old_version_number,  # 要回滚到的版本号
    new_labels=["production"],
)
```

## 4. 数据集与实验

### 4.1 Dataset Run 在 UI 上看不到

**原因**：Run Item 关联时 `dataset_item_id` 不正确。

```python
# ✅ 正确：使用 item.id
dataset = langfuse.get_dataset("my-dataset")
for item in dataset.items:
    # ... 运行实验 ...
    langfuse.create_dataset_run_item(
        dataset_name="my-dataset",
        dataset_item_id=item.id,  # ← 用 item 的 id
        run_name="my-run",
    )
```

### 4.2 实验运行超时

**原因**：数据集中 Item 太多，或单条处理时间过长。

**解决**：

- 减少数据集大小（分批实验）
- 设置单条超时
- 增加并发（注意 API 限流）

## 5. 连接与部署

### 5.1 自托管 Langfuse 无法访问

**排查步骤**：

```bash
# 1. 检查容器状态
sudo docker compose ps

# 2. 检查端口
curl http://localhost:3001/api/public/health

# 3. 检查日志
sudo docker compose logs -f langfuse-web-1

# 4. 检查 PostgreSQL（宿主机服务）
sudo systemctl status postgresql

# 5. 检查安全组（远程访问）
curl http://your-server:3001/api/public/health
```

### 5.2 内存不足导致 Langfuse 容器崩溃

**排查**：

```bash
sudo docker compose ps  # 查看容器是否 Restarting
sudo docker stats       # 查看内存使用
```

**解决**：

- 增加服务器内存
- 调整容器内存限制（docker-compose.yml 中的 `mem_limit`）
- 清理旧数据：Settings → Danger Zone

### 5.3 ClickHouse 数据查询

```bash
# 进入 ClickHouse 容器
sudo docker exec -it langfuse-clickhouse-1 clickhouse-client

# 查询最近的 traces
SELECT name, timestamp, user_id
FROM events_core
ORDER BY timestamp DESC
LIMIT 10;

# 查询评分分布
SELECT name, avg(value), count()
FROM scores
GROUP BY name;
```

## 6. SDK API 速查

### 6.1 v4 常用 API

| 需求 | 写法 |
|------|------|
| 开启根节点（=trace） | `with langfuse.start_as_current_observation(name="...", as_type="agent", input=...)` |
| 子节点 span | `with langfuse.start_as_current_observation(name="...", as_type="span", ...)` |
| LLM 记录 | `as_type="generation", model="gpt-4o", input=..., output=...` |
| 补输出/元数据 | `obs.update(output=...)` / `obs.update(metadata=...)` |
| trace 级 IO | `langfuse.set_current_trace_io(input=..., output=...)` |
| trace 级打分 | `langfuse.score_current_trace(name=..., value=..., comment=...)` |
| span 级打分 | `langfuse.score_current_span(name=..., value=..., comment=...)` |
| 生成 trace id | `tid = langfuse.create_trace_id()` |
| 刷盘 | `langfuse.flush()` |
| 连通性检查 | `langfuse.auth_check()` |

### 6.2 Dataset API

| 需求 | 写法 |
|------|------|
| 获取数据集 | `dataset = langfuse.get_dataset("name")` |
| 遍历 items | `for item in dataset.items:` |
| 创建 dataset | `langfuse.create_dataset(name=..., description=...)` |
| 添加 item | `langfuse.create_dataset_item(dataset_name=..., input=..., expected_output=...)` |

### 6.3 Prompt API

| 需求 | 写法 |
|------|------|
| 获取 prompt | `prompt = langfuse.get_prompt(name=..., label="production")` |
| 创建版本 | `langfuse.create_prompt(name=..., prompt=..., labels=["staging"])` |
| 更新标签 | `langfuse.update_prompt_labels(name=..., version=N, new_labels=["production"])` |
| 读取内容 | `prompt.prompt`（文本）/ `prompt.config`（配置） |

## 7. 性能优化

### 7.1 减少上报延迟

- `flush()` 是异步批量上报，不会阻塞主流程
- 调整 `flush_interval`（默认 1s）和 `batch_size`（默认 100）
- 大文本截断（`LARGE_RESULT_TRUNCATE_CHARS=8000`）

### 7.2 降低成本

- LLM-as-Judge 设置采样率（`NL2SQL_EVAL_JUDGE_SAMPLE=0.3`）
- 评估用便宜模型（如 GPT-4o-mini）
- 确定性评估优先（零成本）

### 7.3 存储优化

- 定期清理测试数据：Settings → Danger Zone
- 设置数据保留策略（retention policy）
- 大结果截断到合理长度
