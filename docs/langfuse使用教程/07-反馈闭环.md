# 07 · 反馈闭环

> 从用户反馈到问题修复的完整迭代闭环：差评 → BadCase 采集 → 人工复审 → 修复 → 回归验证 → 灰度发布。

---

## 1. 闭环全景

```
                         ┌─────────────────────────────┐
   用户提问 ──→ Agent 执行 ──→ 五维评分写入 Trace        │
                     │              │                    │
                     │   LLM Judge  │  差评/低分/异常     │
                     ▼              ▼                    │
           Langfuse Traces     collect_badcase           │
           + Scores             ──→ Dataset:badcase     │
                     │              │                    │
               前端 👍/👎           ▼                    │
                     │        BadCase 状态机             │
                     │         (pending → reviewed)      │
                     │              │                    │
                     │              ▼                    │
                     │    人工复审 + 标记                │
                     │    (fixed / invalid)              │
                     │              │                    │
                     │              ▼                    │
                     │    run_experiment 回归门禁         │
                     │    (离线 A/B 测试)                │
                     │              │                    │
                     │              ▼                    │
                     │    canary 灰度发布                │
                     │              │                    │
                     │              ▼                    │
                     │    feedback_gate 在线门禁         │
                     │    (真实用户 👍/👎 对比)          │
                     │              │                    │
                     │              ▼                    │
                     │    production 全量发布            │
                     │              │                    │
                     └──────────────┘                    │
                               闭环完成                   │
```

## 2. 用户反馈采集

### 2.1 前端交互

用户在对话界面点击 👍 或 👎 按钮：

```
用户消息: "统计 artist 表有多少艺术家"
Agent 回复: "共 275 位艺术家"
          [👍] [👎]  ← 用户点击
```

### 2.2 后端处理

```python
# 接收反馈 → 写入 Langfuse Score
@app.post("/api/feedback")
async def submit_feedback(thread_id: str, message_id: str, rating: str, comment: str = ""):
    score_value = {
        "positive": 1.0,
        "negative": 0.0,
    }.get(rating, 0.5)

    langfuse.create_score(
        name="user-feedback",
        value=score_value,
        trace_id=find_trace_id(thread_id, message_id),
        comment=comment or f"用户{rating}反馈",
    )
```

### 2.3 查看反馈

- **Scores** 页面 → 筛选 `user-feedback`
- 好评率趋势图
- 差评 trace 列表（点击可跳转详情）

## 3. BadCase 自动采集

### 3.1 采集规则

系统每天自动扫描 trace，将满足以下条件的记录采集为 BadCase：

| 条件 | 阈值 | 说明 |
|------|------|------|
| 用户差评 | `user-feedback = 0` | 用户点了 👎 |
| SQL 业务正确性低 | `sql_biz_correct < 0.5` | LLM Judge 判定不正确 |
| 执行失败 | `sql_exec_success = 0` | SQL 执行报错 |
| Schema 匹配失败 | `schema_match < 0.5` | 未能正确识别表和字段 |

### 3.2 自动采集脚本

```bash
# 每天 02:13 由 cron 自动执行
python -m agent.eval.collect_badcase --days 1 --dataset badcase
```

### 3.3 采集结果

```
[collect_badcase] 扫描 2026-10-13 的 traces...
[collect_badcase] 发现 3 条 badcase:
  - trace 9e0ad44: sql_biz_correct=0.25, 用户差评
  - trace 7f2bc11: sql_exec_success=0, 执行报错
  - trace a3d9e02: user_feedback=0, 差评
[collect_badcase] 已写入 Dataset:badcase（3 条新增，0 条重复）
[collect_badcase] BadCase 状态: pending=3, reviewed=0, fixed=12, invalid=5
```

## 4. 人工复审

### 4.1 查看待审列表

```bash
# 查看 pending 状态的 BadCase
python -m agent.eval.badcase_status list --status pending
```

输出示例：

```
Pending BadCases (3):

1. trace_id: 9e0ad442
   问题: 参演了最多不同类型电影的演员 Top 10
   数据库: imdb
   触发原因: sql_biz_correct_score = 0.25
   采集时间: 2026-10-14 02:13

2. trace_id: 7f2bc110
   问题: 查询所有客户的订单总额
   数据库: chinook
   触发原因: sql_exec_success = 0
   采集时间: 2026-10-14 02:13

3. trace_id: a3d9e021
   问题: 你好
   数据库: imdb
   触发原因: user_feedback = 0
   采集时间: 2026-10-14 02:13
```

### 4.2 逐条复审

```bash
# 交互式复审（自动打开 Langfuse trace 页面）
python -m agent.eval.badcase_status review
```

复审时你需要判断：

| 判断 | 标记 | 说明 |
|------|------|------|
| **真问题** | `fixed` | 确实是 Agent 的问题，需要修 |
| **误报** | `invalid` | 不是 Agent 的问题（如用户测试行为） |

### 4.3 标记

```bash
# 标记为已修复
python -m agent.eval.badcase_status mark 9e0ad442 fixed --note "修复了 JOIN 逻辑"

# 标记为误报
python -m agent.eval.badcase_status mark a3d9e021 invalid --note "用户测试差评，非模型问题"
```

## 5. 修复与回归验证

### 5.1 修改 Prompt

根据复审结论修改 prompt：

```python
# 创建新版本
langfuse.create_prompt(
    name="nl2sql_system_prompt",
    prompt="... 修复了 JOIN 逻辑的 prompt ...",
    labels=["staging"],
)
```

### 5.2 离线回归门禁

```bash
# 用 BadCase 数据集做回归验证
python -m agent.eval.run_experiment \
    --dataset badcase \
    --prompt-label staging \
    --from-badcase \
    --threshold 0.05 \
    --run-name "fix-join-logic-20261014"
```

门禁判据：

```
✅ 通过: candidate 均分 ≥ reference 均分 - 阈值 → exit 0
❌ 退化: candidate 均分 < reference 均分 - 阈值 → exit 1（阻止发版）
```

## 6. 灰度发布

### 6.1 Canary 灰度

```bash
# 设置 canary 比例
LANGFUSE_CANARY_LABEL=staging
LANGFUSE_CANARY_RATIO=0.1    # 10% 流量走新版本

# 重启服务生效
```

### 6.2 在线反馈门禁

灰度期间持续监控真实用户反馈：

```bash
# 对比新旧版本的用户好评率
python -m agent.eval.feedback_gate \
    --reference production \
    --candidate canary \
    --threshold 0.1    # 好评率差异阈值
```

### 6.3 全量发布

```python
# 验证通过后，将 staging 标记为 production
langfuse.update_prompt_labels(
    name="nl2sql_system_prompt",
    version=new_version,
    new_labels=["production"],
)
```

## 7. 完整时间线示例

一个差评从产生到闭环的完整过程：

| 步骤 | 时间 | 动作 | 角色 |
|------|------|------|------|
| 1 | Day 1 15:12 | 用户提问 → Agent 生成错误 SQL | 用户 + Agent |
| 2 | Day 1 15:13 | 五维评分：`sql_biz_correct=0.25` | 自动 |
| 3 | Day 1 15:14 | 用户点 👎 + 评论 | 用户 |
| 4 | Day 2 02:13 | `collect_badcase` 自动采集 | cron |
| 5 | Day 2 09:00 | 人工复审 → 确认是真问题 | 工程师 |
| 6 | Day 2 09:20 | 修改 prompt → 打 `staging` 标签 | 工程师 |
| 7 | Day 2 09:30 | `run_experiment` 离线回归 → 通过 | 工程师 |
| 8 | Day 2 14:00 | canary 灰度 10% | 工程师 |
| 9 | Day 5 09:00 | `feedback_gate` 在线门禁 → 通过 | cron |
| 10 | Day 5 09:10 | `production` 标签全量发布 | 工程师 |
| 11 | Day 6 02:13 | 次日采集确认同类问题不再复现 | cron |
