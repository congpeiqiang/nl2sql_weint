## 1. 概述：结构化输出的多种方式和演进

### 1.1 为什么需要结构化输出

LLM 的原始输出是**一段自由文本**（`AIMessage.content`）。但下游程序需要的是**机器可读的数据**：
一个 Pydantic 对象、一个 dict、一个列表、一个 JSON。结构化输出（Structured Output）解决的就是
「**自由文本 → 类型化数据**」这一步的可靠性问题。

### 1.2 三代技术演进

LangChain 中实现结构化输出的方式，随着大模型能力的演进大致经历了三代：

| 代际 | 机制 | 代表 API | 可靠性 |
|---|---|---|---|
| **第一代：提示词 + 文本解析** | 在 prompt 里告诉模型「请按 JSON/XML/列表格式回答」，然后用 Output Parser 从文本中解析 | `JsonOutputParser`、`PydanticOutputParser`、`XMLOutputParser`、`CommaSeparatedListOutputParser` | 依赖模型自觉，可能夹杂解释文字、Markdown 围栏，解析可能失败 |
| **第二代：函数调用 / 工具调用** | 把 schema 伪装成一个「工具」绑定给模型，模型调用该工具时参数即结构化数据 | `PydanticToolsParser`、`JsonOutputToolsParser`、（旧）`JsonOutputFunctionsParser` | 高。参数由模型的 tool-calling 能力保证为合法 JSON |
| **第三代：提供商原生结构化输出** | 使用 OpenAI Structured Outputs 等原生 `response_format={"type": "json_schema", ...}`，解码阶段就受 schema 约束 | `with_structured_output(method="json_schema")`、`create_agent(response_format=ProviderStrategy(...))` | 最高（strict 模式下语法层面 100% 合规） |

当前（langchain 1.x）推荐的两个统一入口：

- **模型级**：`model.with_structured_output(schema)` —— 内部自动选择上面第二/三代机制并接好解析器；
- **Agent 级**：`create_agent(..., response_format=schema)` —— 由 Agent 框架选择
  `ToolStrategy`（工具调用策略）或 `ProviderStrategy`（提供商原生策略）。

而第一代的各种 Output Parser 依然保留，用于：不支持工具调用的模型、需要流式增量解析、
以及自定义文本格式（XML/列表）的场景。

### 1.3 输出解析器的类继承体系

阅读源码前先看类图（全部位于 `langchain_core/output_parsers/`）：

```
BaseLLMOutputParser[T]                  # base.py，纯抽象：parse_result / aparse_result
│
├── BaseGenerationOutputParser[T]       # base.py，Runnable 化的最小实现（旧 functions 解析器用）
│
└── BaseOutputParser[T]                 # base.py，核心基类：parse / invoke / parse_with_prompt
    │
    └── BaseTransformOutputParser[T]    # transform.py，支持「逐块流式解析」
        │   ├── StrOutputParser         # string.py
        │   ├── XMLOutputParser         # xml.py
        │   └── ListOutputParser        # list.py（逗号分隔 / 编号 / Markdown 列表）
        │
        └── BaseCumulativeTransformOutputParser[T]   # transform.py，支持「累积式流式解析」
            │   ├── JsonOutputParser                 # json.py
            │   │   └── PydanticOutputParser         # pydantic.py
            │   ├── JsonOutputToolsParser            # openai_tools.py
            │   │   ├── JsonOutputKeyToolsParser     # openai_tools.py
            │   │   └── PydanticToolsParser          # openai_tools.py
            │   └── JsonOutputFunctionsParser 等     # openai_functions.py（旧 function_calling 时代，遗留）
```

两种流式基类的区别（详见第 9 章）：

- **Transform（逐块）**：每个 chunk 独立解析、独立产出（字符串、XML 叶子节点、列表项）；
- **CumulativeTransform（累积）**：把已收到的所有 chunk **累加**后做**部分解析**（`partial=True`），
  每次产出「到目前为止解析出的完整对象快照」，可选产出 JSONPatch 增量（`diff=True`）。

## 2. with_structured_output() 方法详解

### 2.1 基类默认实现：function_calling

`BaseChatModel.with_structured_output` 的默认实现（凡是没有覆写它的集成都走这条路）位于
`langchain_core/language_models/chat_models.py`：

```python
# langchain_core/language_models/chat_models.py（节选）
def with_structured_output(self, schema, *, include_raw=False, **kwargs):
    _ = kwargs.pop("method", None)      # 基类忽略 method / strict 参数
    _ = kwargs.pop("strict", None)
    ...
    llm = self.bind_tools(
        [schema],
        tool_choice="any",              # ★ 强制模型必须调用 schema 对应的工具
        ls_structured_output_format={...},
    )
    output_parser: JsonOutputToolsParser
    if isinstance(schema, type) and is_basemodel_subclass(schema):
        # Pydantic 类 → 解析结果直接实例化为 Pydantic 对象
        output_parser = PydanticToolsParser(tools=[schema], first_tool_only=True)
    else:
        # dict/TypedDict/JSON Schema → 只取该 key 工具的 args，返回 dict
        key_name = convert_to_openai_tool(schema)["function"]["name"]
        output_parser = JsonOutputKeyToolsParser(key_name=key_name, first_tool_only=True)
    if include_raw:
        # 组装成 {"raw": ..., "parsed": ..., "parsing_error": ...} 三元组
        parser_assign = RunnablePassthrough.assign(
            parsed=itemgetter("raw") | output_parser, parsing_error=lambda _: None
        )
        parser_none = RunnablePassthrough.assign(parsed=lambda _: None)
        parser_with_fallback = parser_assign.with_fallbacks(
            [parser_none], exception_key="parsing_error"
        )
        return RunnableMap(raw=llm) | parser_with_fallback
    return llm | output_parser
```

**要点解析：**

1. `with_structured_output` 本质上就是一个 LCEL 链：`bind_tools(强制工具) | 工具解析器`。
   它并不是什么黑魔法——理解这一点，出问题时就知道该检查哪一环。
2. **schema 类型决定返回类型**：传入 Pydantic 类返回 Pydantic 实例（会做字段校验）；
   传入 dict / TypedDict / JSON Schema 返回未校验的 dict。
3. **`include_raw=True` 是排障利器**：返回 `{"raw": AIMessage, "parsed": ..., "parsing_error": ...}`。
   解析失败不再抛异常，而是把异常放进 `parsing_error`，可以据此区分
   「模型根本没调工具」和「调了工具但参数不符合 schema」两种失败。

### 2.2 OpenAI 家族实现：三种 method

`ChatOpenAI`（`langchain_openai/chat_models/base.py`）覆写了该方法，签名更丰富：

```python
# langchain_openai/chat_models/base.py（签名节选）
def with_structured_output(
    self,
    schema=None,
    *,
    method: Literal["function_calling", "json_mode", "json_schema"] = "function_calling",
    include_raw: bool = False,
    strict: bool | None = None,
    tools: list | None = None,
    **kwargs,
): ...
```

三种 `method` 的机制与接线（源码实现节选）：

```python
# langchain_openai/chat_models/base.py（实现节选）
if method == "function_calling":
    tool_name = convert_to_openai_tool(schema)["function"]["name"]
    bind_kwargs = self._filter_disabled_params(     # ★ disabled_params 在这里生效
        **{"tool_choice": tool_name,               # 强制调用 schema 工具
           "parallel_tool_calls": False,           # 禁止并行调用，保证只有一个结果
           "strict": strict, ...}
    )
    llm = self.bind_tools([schema], **bind_kwargs)
    output_parser = PydanticToolsParser(tools=[schema], first_tool_only=True) \
        if is_pydantic_schema else JsonOutputKeyToolsParser(key_name=tool_name, first_tool_only=True)

elif method == "json_mode":
    # 只保证输出是合法 JSON，不保证符合 schema —— 必须自己在 prompt 里写清字段
    llm = self.bind(response_format={"type": "json_object"}, ...)
    output_parser = PydanticOutputParser(pydantic_object=schema) if is_pydantic_schema else JsonOutputParser()

elif method == "json_schema":
    # OpenAI 原生 Structured Outputs：解码阶段受 schema 约束
    response_format = _convert_to_openai_response_format(schema, strict=strict)
    llm = self.bind(response_format=response_format, ...)
```

选择建议（按提供商**文档化的能力**选，而不是猜测）：

| method | 约束强度 | 适用条件 | 注意 |
|---|---|---|---|
| `json_schema` | 最强（strict=True 时语法级保证） | 提供商文档明确支持 Structured Outputs | 不支持的模型会**警告并自动降级**为 `function_calling`（见源码 2470-2479 行的 warning） |
| `function_calling` | 强（依赖模型 tool-calling 质量） | 提供商支持工具调用**且支持强制 `tool_choice`** | 部分 OpenAI 兼容后端拒绝强制 `tool_choice`，报 400（见 13 章陷阱 2） |
| `json_mode` | 弱（只保证是 JSON） | 提供商只支持 JSON mode | 必须在 prompt 中描述 schema，并在应用层校验+重试 |

`strict` 参数（仅 OpenAI 系）：

- `True`：模型输出**保证**严格匹配 schema，同时会按 OpenAI 的
  [supported schemas](https://platform.openai.com/docs/guides/structured-outputs/supported-schemas) 校验你传入的 schema（不是所有 JSON Schema 特性都支持）；
- `False`：不做校验也不做保证；
- `None`（默认）：不向 API 传 `strict` 字段。

### 2.3 Agent 级结构化输出：create_agent(response_format=...)

`langchain/agents/structured_output.py` 定义了 Agent 的响应格式策略体系。
它与模型级的 `method` 参数**不是一回事**，不能混用概念。

**支持的 schema 类型**（`_SchemaSpec.__init__`，源码 175-192 行）：

```python
# langchain/agents/structured_output.py（节选）
if isinstance(schema, dict):
    self.schema_kind = "json_schema"          # JSON Schema dict
    self.json_schema = schema
elif isinstance(schema, type) and issubclass(schema, BaseModel):
    self.schema_kind = "pydantic"             # Pydantic 模型
    self.json_schema = schema.model_json_schema()
elif is_dataclass(schema):
    self.schema_kind = "dataclass"            # dataclass
    self.json_schema = TypeAdapter(schema).json_schema()
elif is_typeddict(schema):
    self.schema_kind = "typeddict"            # TypedDict
    self.json_schema = TypeAdapter(schema).json_schema()
else:
    raise ValueError(f"Unsupported schema type: {type(schema)}. ...")
```

三种策略：

```python
# langchain/agents/structured_output.py（节选）
ResponseFormat = ToolStrategy[SchemaT] | ProviderStrategy[SchemaT] | AutoStrategy[SchemaT]
```

**(1) `ToolStrategy`** —— 把 schema 变成一个「结构化输出工具」，模型通过调用该工具给出答案。
支持 `Union` / JSON Schema `oneOf` 的**多变体**（模型可在多个 schema 中选一个），
并带错误处理/重试语义：

```python
# langchain/agents/structured_output.py（节选）
@dataclass(init=False)
class ToolStrategy(Generic[SchemaT]):
    handle_errors: bool | str | type[Exception] | tuple[type[Exception], ...] | Callable[[Exception], str]
    """错误处理策略：
    - True: 捕获所有错误，用默认错误模板反馈给模型重试
    - str:  捕获所有错误，用这段自定义文字反馈重试
    - type[Exception] / tuple: 只捕获指定异常类型
    - Callable[[Exception], str]: 自定义函数，返回反馈给模型的错误信息
    - False: 不重试，异常直接向外抛
    """

    def __init__(self, schema, *, tool_message_content=None, handle_errors=True):
        ...
        def _iter_variants(schema):
            """展开 Union 与 JSON Schema oneOf，得到叶子 schema 列表"""
            if get_origin(schema) in {UnionType, Union}:
                for arg in get_args(schema):
                    yield from _iter_variants(arg)
                return
            if isinstance(schema, dict) and "oneOf" in schema:
                for sub in schema.get("oneOf", []):
                    yield from _iter_variants(sub)
                return
            yield schema

        self.schema_specs = [_SchemaSpec(s) for s in _iter_variants(schema)]
```

**(2) `ProviderStrategy`** —— 使用提供商**原生**结构化输出。`to_model_kwargs()` 生成
OpenAI 风格的 `response_format`：

```python
# langchain/agents/structured_output.py（节选）
def to_model_kwargs(self) -> dict[str, Any]:
    json_schema = {"name": self.schema_spec.name, "schema": self.schema_spec.json_schema}
    if self.schema_spec.strict:
        json_schema["strict"] = True
    return {"response_format": {"type": "json_schema", "json_schema": json_schema}}
```

**(3) `AutoStrategy`** —— 直接传 schema 类时的默认行为，由框架根据**模型能力元数据**
自动在前两者间选择。

解析与校验统一走 `_parse_with_schema`（json_schema 直接返回 dict，其余用
`TypeAdapter(schema).validate_python(data)` 校验），失败时抛出该模块定义的异常体系：

```python
# langchain/agents/structured_output.py（节选）
class StructuredOutputError(Exception):
    ai_message: AIMessage                        # 出错时的原始 AI 消息，便于排障

class MultipleStructuredOutputsError(StructuredOutputError):
    """期望一个结构化输出，模型却调用了多个结构化工具"""

class StructuredOutputValidationError(StructuredOutputError):
    """工具调用参数不符合 schema"""
```

**使用示例：**

```python
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy, ProviderStrategy
from pydantic import BaseModel, Field

class WeatherReport(BaseModel):
    """天气播报稿。"""                       # ★ docstring 会成为工具的 description
    city: str = Field(description="城市名")
    summary: str = Field(description="一句话天气总结")

# 方式一：直接传 schema → AutoStrategy，框架按模型能力自动选择
agent = create_agent(model="openai:gpt-4o", tools=[], response_format=WeatherReport)

# 方式二：明确用提供商原生结构化输出（strict 模式）
agent = create_agent(
    model="openai:gpt-4o",
    tools=[],
    response_format=ProviderStrategy(WeatherReport, strict=True),
)

# 方式三：明确用工具调用策略，并自定义「解析失败时反馈给模型的话」
agent = create_agent(
    model="openai:gpt-4o",
    tools=[],
    response_format=ToolStrategy(
        WeatherReport,
        handle_errors="输出不符合 WeatherReport 格式，请重新调用该工具，所有字段必填。",
    ),
)

result = agent.invoke({"messages": [("user", "北京今天天气如何？")]})
# result["structured_response"] 即 WeatherReport 实例
```

## 3. JSON 输出解析器

### 3.1 JsonOutputParser

`langchain_core/output_parsers/json.py`。它是**不依赖函数调用**时最可靠的文本→JSON 解析器，
继承自 `BaseCumulativeTransformOutputParser`，因此**天然支持流式**：流式模式下逐次产出
「到目前为止已解析出的部分 JSON 对象」。

核心源码：

```python
# langchain_core/output_parsers/json.py（节选）
class JsonOutputParser(BaseCumulativeTransformOutputParser[Any]):
    """流式模式下产出部分 JSON 对象；diff=True 时产出 JSONPatch 增量。"""

    pydantic_object: Annotated[type[TBaseModel] | None, SkipValidation()] = None
    """仅用于生成格式说明（get_format_instructions）；为 None 时不做任何校验。"""

    def _diff(self, prev, next):
        return jsonpatch.make_patch(prev, next).patch   # diff 模式：产出 JSONPatch 操作

    def parse_result(self, result, *, partial=False):
        text = result[0].text.strip()
        if partial:
            try:
                return parse_json_markdown(text)   # 部分解析：能解析多少算多少
            except JSONDecodeError:
                return None                        # ★ partial 模式失败返回 None（流式跳过该帧）
        else:
            try:
                return parse_json_markdown(text)
            except JSONDecodeError as e:
                msg = f"Invalid json output: {text}"
                raise OutputParserException(msg, llm_output=text) from e   # 完整模式失败抛异常
```

**要点解析：**

1. **`parse_json_markdown` 的容错**（`langchain_core/utils/json.py`）：先直接 `parse_partial_json`，
   失败再尝试从 ```` ```json ... ``` ```` Markdown 围栏里抠出 JSON。所以模型输出
   ```` 「```json\n{...}\n```」 ```` 也能解析成功——这是它比裸 `json.loads` 可靠的关键。
2. **⚠️ 大坑：`pydantic_object` 不做校验！** 在 langchain-core 1.x 中，
   `JsonOutputParser(pydantic_object=Foo)` 的 `pydantic_object` **只用于生成
   `get_format_instructions()` 里的 schema 说明**，`parse_result` 并不会用 `Foo` 校验数据。
   要「解析 + 校验」请用 `PydanticOutputParser`（第 4 章）。
3. `SimpleJsonOutputParser` 是它的向后兼容别名（源码 131 行）。

### 3.2 格式说明（format_instructions.py）

`get_format_instructions()` 返回的文本应拼进 prompt。当前版本的模板比旧版严格得多：

````python
# langchain_core/output_parsers/format_instructions.py（全文节选）
JSON_FORMAT_INSTRUCTIONS = """STRICT OUTPUT FORMAT:
- Return only the JSON value that conforms to the schema. Do not include any additional text, ...
- Do not wrap the JSON in Markdown or code fences (no ``` or ```json).
- Do not prepend or append any text (e.g., do not write "Here is the JSON:").
- The response must be a single top-level JSON value exactly as required by the schema ...

Here is the output schema (shown in a code block for readability only — do not include any
backticks or Markdown in your output):
```
{schema}
```"""
````

`JsonOutputParser.get_format_instructions()` 会把 Pydantic 模型的 JSON Schema
（去掉 `title`/`type` 两个冗余键后）填进 `{schema}` 占位符：

```python
# langchain_core/output_parsers/json.py（节选）
def get_format_instructions(self) -> str:
    if self.pydantic_object is None:
        return "Return a JSON object."
    schema = dict(self._get_schema(self.pydantic_object).items())  # 拷贝，避免改原 schema
    if "title" in schema: del schema["title"]
    if "type" in schema:  del schema["type"]
    schema_str = json.dumps(schema, ensure_ascii=False)            # 中文说明不被转义
    return JSON_FORMAT_INSTRUCTIONS.format(schema=schema_str)
```

### 3.3 基础用法

```python
from langchain_core.output_parsers import JsonOutputParser

parser = JsonOutputParser()          # 不带 pydantic_object：纯 JSON 解析，不校验

# parser 是一个 Runnable，可以直接 invoke 字符串 / AIMessage
result = parser.invoke('```json\n{"name": "张三", "age": 30}\n```')
print(result)   # {'name': '张三', 'age': 30}   ← Markdown 围栏被自动剥掉
```

## 4. Pydantic 输出解析器

### 4.1 PydanticOutputParser

`langchain_core/output_parsers/pydantic.py`。它 **继承自 `JsonOutputParser`**，
在其之上叠加了一层 Pydantic 校验：先按 JSON 解析，再实例化模型。

```python
# langchain_core/output_parsers/pydantic.py（节选）
class PydanticOutputParser(JsonOutputParser, Generic[TBaseModel]):
    """Parse an output using a Pydantic model."""

    pydantic_object: Annotated[type[TBaseModel], SkipValidation()]   # ★ 此处为必填

    def _parse_obj(self, obj: Any) -> TBaseModel:
        try:
            if issubclass(self.pydantic_object, pydantic.BaseModel):       # Pydantic v2
                return self.pydantic_object.model_validate(obj)
            if issubclass(self.pydantic_object, pydantic.v1.BaseModel):    # Pydantic v1 兼容
                return self.pydantic_object.parse_obj(obj)
            raise OutputParserException("Unsupported model version ...")
        except (pydantic.ValidationError, pydantic.v1.ValidationError) as e:
            raise self._parser_exception(e, obj) from e

    def _parser_exception(self, e, json_object) -> OutputParserException:
        json_string = json.dumps(json_object, ensure_ascii=False)
        name = self.pydantic_object.__name__
        # 错误消息带上模型名、原始 JSON、ValidationError 详情 → 排障信息非常全
        msg = f"Failed to parse {name} from completion {json_string}. Got: {e}"
        return OutputParserException(msg, llm_output=json_string)

    def parse_result(self, result, *, partial=False):
        try:
            json_object = super().parse_result(result, partial=partial)  # 先 JSON 解析
            return self._parse_obj(json_object)                          # 再 Pydantic 校验
        except OutputParserException:
            if partial:
                return None      # ★ 流式部分解析：不合规的中间态直接返回 None（跳过这一帧）
            raise
```

**要点解析：**

1. **同时兼容 Pydantic v1 与 v2**：v2 用 `model_validate`，v1 用 `parse_obj`。
2. **校验失败被包装为 `OutputParserException`**（而不是裸 `ValidationError`），
   消息里带完整的原始 JSON 与 pydantic 错误详情，且 `llm_output` 字段保留原文，
   便于「把错误喂回给模型重试」（见第 11 章）。
3. **流式（partial）语义**：中间帧只要还不满足 schema 就返回 `None`，
   由累积基类过滤掉——所以流式模式下你可能收到 `None`，最终帧才是完整对象。
4. `OutputType` 属性直接返回 `pydantic_object`，LCEL 类型推断更准。
5. 格式说明用的是本模块私有的 `_PYDANTIC_FORMAT_INSTRUCTIONS`（比 JSON 版模板少一段
   STRICT 前缀，但同样内嵌完整 schema）。

### 5.1 工具调用解析器（openai_tools.py，现役）

这一族解析器处理的是**模型发起的工具调用**（`AIMessage.tool_calls` 或
`additional_kwargs["tool_calls"]`），是第二代结构化输出的落地件，也是
`with_structured_output(method="function_calling")` 内部实际使用的解析器。

**底层函数 `parse_tool_call`**——把 OpenAI 原始 tool_call dict 解析为标准结构：

```python
# langchain_core/output_parsers/openai_tools.py（节选）
def parse_tool_call(raw_tool_call, *, partial=False, strict=False, return_id=True):
    arguments = raw_tool_call["function"]["arguments"]
    if partial:
        try:
            function_args = parse_partial_json(arguments, strict=strict)  # 流式：容忍不完整 JSON
        except (JSONDecodeError, TypeError):
            return None
    elif not arguments:
        function_args = {}          # ★ 无参数工具：arguments 为 None/空串时给空 dict
    else:
        try:
            function_args = json.loads(arguments, strict=strict)
        except JSONDecodeError as e:
            msg = (f"Function {raw_tool_call['function']['name']} arguments:\n\n"
                   f"{arguments}\n\nare not valid JSON. Received JSONDecodeError {e}")
            raise OutputParserException(msg) from e
    parsed = {"name": ..., "args": function_args or {}}
    if return_id:
        parsed["id"] = raw_tool_call.get("id")
        parsed = create_tool_call(**parsed)
    return parsed
```

注意 `strict` 参数的含义与直觉相反：它直接透传给 `json.loads(strict=...)`。
`strict=False` 表示**放宽** JSON 规范——允许字符串内部出现控制字符（裸换行、制表符等）。
模型输出里带未转义换行的中文长文本时，`strict=True`（默认）会解析失败。

```python
    tools: Annotated[list[TypeBaseModel], SkipValidation()]

    def parse_result(self, result, *, partial=False):

        if not json_results:
            return None if self.first_tool_only else []
        # 名字 → 类 的映射：优先用 model_config["title"]，否则用 __name__

                        for tool in self.tools if issubclass(tool, BaseModel)}
        ...
        for res in json_results:
            if not isinstance(res["args"], dict):
                if partial: continue                     # 流式：参数还没成形，跳过

                raise OutputParserException(f"Unknown tool type: {res['type']!r}. ...") from e
            try:
                pydantic_objects.append(tool(**res["args"]))
            except (ValidationError, ValueError):
                if partial: continue                     # 流式：字段不全，跳过这一帧
                # ★ 输出被 max_tokens 截断是 ValidationError 的常见原因，专门给出提示

                    generation.message.response_metadata.get("stop_reason") == "max_tokens"
                    for generation in result if isinstance(generation, ChatGeneration)
                )
                if has_max_tokens_stop_reason:
                    logger.exception(_MAX_TOKENS_ERROR)   # "请增大 max_tokens 或缩短 prompt"
                raise                                    # 完整模式下裸抛 ValidationError
        ...
```

## 6. XML 输出解析器

`langchain_core/output_parsers/xml.py`。`XMLOutputParser` 继承
`BaseTransformOutputParser`（**逐块**流式，不是累积式），输出为嵌套 dict。

### 6.1 完整解析：parse()

```python
# langchain_core/output_parsers/xml.py（节选）
class XMLOutputParser(BaseTransformOutputParser[dict[str, Any]]):
    tags: list[str] | None = None            # 期望的标签列表，仅用于生成格式说明
    parser: Literal["defusedxml", "xml"] = "defusedxml"   # ★ 默认用 defusedxml（防 XML 攻击）

    def parse(self, text: str) -> dict[str, str | list[Any]]:
        # 1. 剥掉 ```xml ... ``` Markdown 围栏
        match = re.search(r"```(xml)?(.*)```", text, re.DOTALL)
        if match is not None:
            text = match.group(2)
        # 2. 剥掉 <?xml encoding=...?> 声明行
        encoding_match = self.encoding_matcher.search(text)
        if encoding_match:
            text = encoding_match.group(2)
        # 3. ElementTree 解析并转 dict
        text = text.strip()
        try:
            root = et.fromstring(text)
            return self._root_to_dict(root)
        except et.ParseError as e:
            raise OutputParserException(f"Failed to parse XML format from completion {text}. Got: {e}",
                                        llm_output=text) from e

    def _root_to_dict(self, root):
        """XML 树 → Python dict：叶子节点变 {tag: text}，非叶子递归成列表"""
        if root.text and bool(re.search(r"\S", root.text)):
            return {root.tag: root.text}
        root_tag = []
        for child in root:
            if len(child) == 0:
                root_tag.append({child.tag: child.text})
            else:
                root_tag.append(self._root_to_dict(child))
        return {root.tag: root_tag}
```

**安全性**：默认 `parser="defusedxml"`，需要 `pip install defusedxml`（未安装会抛
`ImportError`）。defusedxml 是标准库 ElementTree 的安全包装，防御 XML 炸弹、
外部实体注入（XXE）等攻击——**解析 LLM 输出这种不可信 XML 时必须保持默认值**。

### 6.2 流式解析：_StreamingParser

XML 的流式解析是一个精巧的**拉取式（pull）解析**实现，核心是标准库的
`ET.XMLPullParser(["start", "end"])`：

```python
# langchain_core/output_parsers/xml.py（节选）
class _StreamingParser:
    def __init__(self, parser):
        self.pull_parser = ET.XMLPullParser(["start", "end"], _parser=parser_)
        self.xml_start_re = re.compile(r"<[a-zA-Z:_]")   # 用于跳过 XML 之前的废话
        self.current_path: list[str] = []                # 当前元素路径栈
        self.current_path_has_children = False
        self.buffer = ""                                 # 未处理文本缓冲

    def parse(self, chunk) -> Iterator[AddableDict]:
        self.buffer += chunk
        if not self.xml_started:
            # 找到第一个 "<字母" 才开始解析 → 模型说 "好的，以下是XML：" 也能容忍
            if match := self.xml_start_re.search(self.buffer):
                self.buffer = self.buffer[match.start():]
                self.xml_started = True
            else:
                return
        self.pull_parser.feed(self.buffer)
        self.buffer = ""
        for event, elem in self.pull_parser.read_events():
            if event == "start":
                self.current_path.append(elem.tag)
                self.current_path_has_children = False
            elif event == "end":
                self.current_path.pop()
                if not self.current_path_has_children:
                    yield nested_element(self.current_path, elem)  # ★ 只产出叶子元素
                if self.current_path:
                    self.current_path_has_children = True          # 父节点不重复产出
                else:
                    self.xml_started = False                       # 根节点闭合，可解析下一段
        # ParseError 且路径栈为空 → 当成 XML 结束后的垃圾尾巴，忽略
```

产出的每个元素是 `AddableDict`（可相加合并的 dict），配合 LCEL 流会自动拼装成完整嵌套结构。

### 6.3 用法示例

```python
from langchain_core.output_parsers import XMLOutputParser

parser = XMLOutputParser(tags=["poem", "line"])     # tags 只影响格式说明文本

# 完整解析
data = parser.invoke("<poem><line>床前明月光</line><line>疑是地上霜</line></poem>")
print(data)
# {'poem': [{'line': '床前明月光'}, {'line': '疑是地上霜'}]}

# 流式解析：每闭合一个叶子标签就产出一块
for chunk in parser.transform(model.stream("写一首关于月亮的五言绝句，用XML格式")):
    print(chunk)
# {'poem': [{'line': '床前明月光'}]}
# {'poem': [{'line': '疑是地上霜'}]}   ← AddableDict，可用 sum() 合并
```

## 7. List 输出解析器

`langchain_core/output_parsers/list.py`。基类 `ListOutputParser` 继承
`BaseTransformOutputParser[list[str]]`——**每次产出一个单元素列表**，
方便下游流式逐项消费。

### 7.1 基类的流式缓冲逻辑

```python
# langchain_core/output_parsers/list.py（节选）
def droplastn(iter, n):
    """丢掉迭代器最后 n 个元素 —— 用来保证「只产出完整的项」"""
    buffer = deque()
    for item in iter:
        buffer.append(item)
        if len(buffer) > n:
            yield buffer.popleft()

class ListOutputParser(BaseTransformOutputParser[list[str]]):
    def _transform(self, input):
        buffer = ""
        for chunk in input:
            buffer += chunk            # 累积文本
            try:
                done_idx = 0
                # 关键：最后一个匹配可能还不完整（chunk 恰好在项中间断开），所以丢弃最后 1 个
                for m in droplastn(self.parse_iter(buffer), 1):
                    done_idx = m.end()
                    yield [m.group(1)]         # 产出已确认完整的项
                buffer = buffer[done_idx:]     # 剩余部分留到下个 chunk 再拼
            except NotImplementedError:
                parts = self.parse(buffer)     # 没实现 parse_iter 的子类走这条回退路径
                if len(parts) > 1:
                    for part in parts[:-1]:
                        yield [part]
                    buffer = parts[-1]
        for part in self.parse(buffer):        # 流结束时冲刷最后一项
            yield [part]
```

### 7.2 三个具体子类

```python
# langchain_core/output_parsers/list.py（节选）
class CommaSeparatedListOutputParser(ListOutputParser):
    """逗号分隔列表："foo, bar, baz" → ["foo", "bar", "baz"]"""
    def parse(self, text):
        try:
            # 用 csv.reader 而不是裸 split(",")：支持双引号包裹含逗号的项
            reader = csv.reader(StringIO(text), quotechar='"', delimiter=",", skipinitialspace=True)
            return [item for sublist in reader for item in sublist]
        except csv.Error:
            return [part.strip() for part in text.split(",")]   # 回退逻辑

class NumberedListOutputParser(ListOutputParser):
    """编号列表："1. foo\n2. bar" → ["foo", "bar"]"""
    pattern: str = r"\d+\.\s([^\n]+)"        # 数字 + 点 + 空白 + 内容

class MarkdownListOutputParser(ListOutputParser):
    """Markdown 列表："- foo\n- bar" → ["foo", "bar"]"""
    pattern: str = r"^\s*[-*]\s([^\n]+)$"    # 行首（可缩进）- 或 * + 内容
```

后两者实现了 `parse_iter`（`re.finditer`），因此流式时能**逐项实时产出**。

### 7.3 用法示例

## 8. String 输出解析器（StrOutputParser）

`langchain_core/output_parsers/string.py`。整个文件不到 70 行，是最简单的解析器，
但使用频率最高——`prompt | model | StrOutputParser()` 几乎是 LCEL 的Hello World。

```python
# langchain_core/output_parsers/string.py（全文要点）
class StrOutputParser(BaseTransformOutputParser[str]):
    """把模型输出（AIMessage / AIMessageChunk）转成纯字符串。支持流式。"""

    @classmethod
    def is_lc_serializable(cls) -> bool:
        return True                       # 可序列化（能安全存入 LangSmith/LangGraph 状态）

    @property
    def _type(self) -> str:
        return "default"

    def parse(self, text: str) -> str:
        """Returns the input text with no changes."""
        return text                       # ★ parse 就是恒等函数！
```

**为什么 `parse` 是恒等函数还有用？** 因为价值全在基类的 `invoke` / `_transform`：

- `invoke(AIMessage)` 时，基类把消息包成 `ChatGeneration`，
  `parse_result` 取 `result[0].text`——即 `message.content` 的**文本部分**
  （多模态 content list 会被规整成字符串）。所以它的作用是
  **`AIMessage → str` 的类型转换**，而不是文本加工。
- 流式时，`BaseTransformOutputParser._transform` 对每个 `AIMessageChunk`
  独立调用 `parse_result`，于是得到**逐 token 的字符串流**。

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_template("用一句话解释什么是{concept}")
chain = prompt | model | StrOutputParser()

# invoke：拿到 str（而不是 AIMessage）
print(chain.invoke({"concept": "递归"}))

# stream：拿到 str 迭代器，可直接 print，不必再 .content
for chunk in chain.stream({"concept": "递归"}):
    print(chunk, end="", flush=True)
```

### 9.1 历史名词澄清：StreamingOutputParser 已不存在

### 9.2 BaseTransformOutputParser：逐块流式

```python
# langchain_core/output_parsers/transform.py（节选）
class BaseTransformOutputParser(BaseOutputParser[T]):
    """Base class for an output parser that can handle streaming input."""

    def _transform(self, input: Iterator[str | BaseMessage]) -> Iterator[T]:
        for chunk in input:                      # 每个 chunk 独立处理
            if isinstance(chunk, BaseMessage):
                yield self.parse_result([ChatGeneration(message=chunk)])
            else:
                yield self.parse_result([Generation(text=chunk)])

    def transform(self, input, config=None, **kwargs) -> Iterator[T]:
        # _transform_stream_with_config：包上 Runnable 配置（回调、tags、LangSmith 追踪）
        yield from self._transform_stream_with_config(
            input, self._transform, config, run_type="parser"
        )
```

适用：解析结果**天然可分块**的场景——字符串（Str）、XML 叶子节点、列表项。
每个输入 chunk 产出一个输出 chunk，互不依赖。

### 9.3 BaseCumulativeTransformOutputParser：累积式流式

JSON/Pydantic/工具调用这类「整体才有意义」的结构，不能逐块解析
（半个 JSON 没有意义），必须**累积**。这就是该基类的设计：

```python
# langchain_core/output_parsers/transform.py（节选）
class BaseCumulativeTransformOutputParser(BaseTransformOutputParser[T]):
    diff: bool = False
    """流式时产出「上一帧与当前帧的 JSONPatch 差异」还是「当前完整快照」"""

    def _diff(self, prev: T | None, next: T) -> T:
        raise NotImplementedError        # 由子类实现（JsonOutputParser 用 jsonpatch）

    def _transform(self, input: Iterator[str | BaseMessage]) -> Iterator[Any]:
        prev_parsed = None
        acc_gen = None                                # 累积的 GenerationChunk
        for chunk in input:
            if isinstance(chunk, BaseMessageChunk):
                chunk_gen = ChatGenerationChunk(message=chunk)
            elif isinstance(chunk, BaseMessage):
                chunk_gen = ChatGenerationChunk(message=BaseMessageChunk(**chunk.model_dump()))
            else:
                chunk_gen = GenerationChunk(text=chunk)

            acc_gen = chunk_gen if acc_gen is None else acc_gen + chunk_gen  # ★ 累加
            #   GenerationChunk 的 __add__ 会拼接文本、合并 tool_call 参数分片

            parsed = self.parse_result([acc_gen], partial=True)   # ★ 每次全量部分解析
            if parsed is not None and parsed != prev_parsed:      # 有变化才产出
                if self.diff:
                    yield self._diff(prev_parsed, parsed)         # JSONPatch 增量
                else:
                    yield parsed                                  # 完整快照
                prev_parsed = parsed
```

**逐行解析：**

1. `acc_gen + chunk_gen`：LangChain 的 chunk 相加协议会把文本拼接、
   把工具调用参数的流式分片按 index 合并——所以累积后总是一个「更完整的响应」。
2. `parse_result(..., partial=True)`：子类在 partial 模式下必须**容忍不完整输入**
   （`parse_partial_json` 能解析缺右括号的 JSON；`PydanticToolsParser` 对不合规帧直接跳过）。
3. `parsed != prev_parsed` 去重：模型输出没让解析结果变化时不产出，避免刷屏。
4. `diff=True` 时产出 RFC 6902 JSONPatch 操作列表，适合前端做增量渲染：
   `[{"op": "replace", "path": "/summary", "value": "..."}]`。

### 9.4 各解析器流式能力对照

| 解析器 | 流式基类 | 流式产出 | partial 失败行为 |
|---|---|---|---|
| `StrOutputParser` | Transform | 原始文本 chunk | 不会失败 |
| `XMLOutputParser` | Transform | 闭合的叶子元素（AddableDict） | 尾部垃圾被忽略 |
| `ListOutputParser` 系 | Transform | 完整的单个列表项 | 不完整项留在缓冲区 |
| `JsonOutputParser` | Cumulative | 部分 JSON dict 快照 / JSONPatch | 返回 None（跳过该帧） |
| `PydanticOutputParser` | Cumulative | **校验通过的** Pydantic 实例 | 返回 None（跳过该帧） |
| `PydanticToolsParser` | Cumulative | Pydantic 实例（字段齐了才出现） | 跳过该帧 |
| `JsonOutputToolsParser` | Cumulative | tool call dict 快照 | parse_partial_json 容忍 |

### 9.5 流式示例

```python
from langchain_core.output_parsers import JsonOutputParser

parser = JsonOutputParser()

# 快照模式（默认 diff=False）：每帧是「到目前为止」的完整 dict
for partial_obj in parser.transform(model.stream("列出3种数据库，输出JSON数组")):
    print(partial_obj)
# [{'name': 'PostgreSQL'}]
# [{'name': 'PostgreSQL'}, {'name': 'My
# [{'name': 'PostgreSQL'}, {'name': 'MySQL'}]      ← 逐步逼近最终结果

# 增量模式：每帧是 JSONPatch 操作，适合前端增量更新 UI
diff_parser = JsonOutputParser(diff=True)
for patch in diff_parser.transform(model.stream("...")):
    print(patch)
# [{'op': 'replace', 'path': '/0/name', 'value': 'PostgreSQL'}]
```

## 10. BaseOutputParser 基类详解

`langchain_core/output_parsers/base.py` 定义了三层抽象，理解它们才能写出自定义解析器。

### 10.1 三层抽象

```python
# langchain_core/output_parsers/base.py（节选）
class BaseLLMOutputParser(ABC, Generic[T]):
    """最底层抽象：不是 Runnable，只有一个解析方法"""
    @abstractmethod
    def parse_result(self, result: list[Generation], *, partial: bool = False) -> T:
        """把一组候选 Generation（同一次调用的多个候选输出）解析为 T"""

class BaseGenerationOutputParser(BaseLLMOutputParser[T], RunnableSerializable[...]):
    """Runnable 化，但只要求实现 parse_result（旧 functions 解析器的基类）"""

class BaseOutputParser(BaseLLMOutputParser[T], RunnableSerializable[...]):
    """★ 日常基类：Runnable + parse(text) 抽象 + parse_with_prompt + get_format_instructions"""
```

### 10.2 BaseOutputParser 的关键成员

**(1) `invoke` / `ainvoke`——把任意输入规整成 Generation：**

```python
# base.py（节选）
def invoke(self, input: str | BaseMessage, config=None, **kwargs) -> T:
    if isinstance(input, BaseMessage):
        # 消息 → ChatGeneration，parse_result 里可以拿到 tool_calls 等结构化字段
        return self._call_with_config(
            lambda x: self.parse_result([ChatGeneration(message=x)]),
            input, config, run_type="parser",
        )
    # 字符串 → Generation
    return self._call_with_config(
        lambda x: self.parse_result([Generation(text=x)]),
        input, config, run_type="parser",
    )
```

这就是为什么同一个 parser 既能接 `model.invoke()`（消息）也能接裸字符串。

**(2) `parse_result` 默认实现——只取第一个候选：**

```python
# base.py（节选）
def parse_result(self, result: list[Generation], *, partial: bool = False) -> T:
    """返回值只从 result[0]（概率最高的候选）解析"""
    return self.parse(result[0].text)
```

**(3) `parse`——子类必须实现的唯一抽象方法：**

```python
@abstractmethod
def parse(self, text: str) -> T:
    """把单个字符串解析为结构。自定义解析器只需要实现这个 + _type。"""
```

**(4) `parse_with_prompt`——带 prompt 上下文的解析（为重试/修复预留）：**

```python
# base.py（节选）
def parse_with_prompt(self, completion: str, prompt: PromptValue) -> Any:
    """提供 prompt 是以便解析器在需要「重试或修复输出」时有上下文可用。
    默认实现忽略 prompt，直接调 parse。"""
    return self.parse(completion)
```

**(5) `get_format_instructions`——生成给模型看的格式说明：**

```python
def get_format_instructions(self) -> str:
    """Instructions on how the LLM output should be formatted."""
    raise NotImplementedError    # 默认不实现；Json/Pydantic/XML/List 系都覆写了
```

惯用法：`prompt = PromptTemplate(..., partial_variables={"format_instructions": parser.get_format_instructions()})`。

**(6) `OutputType` / `_type`：**

- `OutputType`：通过 pydantic 泛型元数据自动推断输出类型（`BaseOutputParser[T]` 的 T），
  供 LCEL / LangSmith 做类型展示；`PydanticOutputParser` 覆写为直接返回 `pydantic_object`。
- `_type`：序列化用的类型名字符串，自定义解析器必须实现。
- `aparse` / `aparse_result`：默认用 `run_in_executor` 把同步实现丢进线程池，
  子类通常不需要单独写异步版本。

### 10.3 自定义解析器实战

官方 docstring 中的布尔解析器就是最好的模板：

```python
# 摘自 base.py 类 docstring，稍加注释
from langchain_core.exceptions import OutputParserException
from langchain_core.output_parsers import BaseOutputParser

class BooleanOutputParser(BaseOutputParser[bool]):
    """把模型输出的 YES/NO 解析为 Python bool"""
    true_val: str = "YES"        # pydantic 字段：可配置的真值词
    false_val: str = "NO"

    def parse(self, text: str) -> bool:
        cleaned_text = text.strip().upper()          # 容错：去空白、统一大写
        if cleaned_text not in (self.true_val.upper(), self.false_val.upper()):
            # ★ 解析失败必须抛 OutputParserException（而不是 ValueError），
            #   这样 with_retry / Agent 修复回路才能识别并处理它
            raise OutputParserException(
                f"BooleanOutputParser expected output value to either be "
                f"{self.true_val} or {self.false_val} (case-insensitive). "
                f"Received {cleaned_text}."
            )
        return cleaned_text == self.true_val.upper()

    def get_format_instructions(self) -> str:        # 可选但推荐：让 prompt 自动带上格式要求
        return f"Your response should be either `{self.true_val}` or `{self.false_val}`."

    @property
    def _type(self) -> str:                          # ★ 必须实现：序列化标识
        return "boolean_output_parser"

# 使用
chain = prompt | model | BooleanOutputParser()
chain.invoke({"question": "水在标准大气压下 100°C 会沸腾吗？"})   # → True
```

## 11. 错误处理与重试

### 11.1 OutputParserException

`langchain_core/exceptions.py`——所有解析器的统一失败信号：

```python
# langchain_core/exceptions.py（节选）
class OutputParserException(ValueError, LangChainException):
    """输出解析器用这个异常表示「解析失败」。
    它与普通代码错误区分开：OutputParserException 可以被捕获并用于修复，
    而其他错误会直接向上抛。"""

    def __init__(self, error, observation=None, llm_output=None, send_to_llm=False):
        """
        Args:
            error: 错误消息或被重抛的异常
            observation: 给模型看的错误解释（用于让模型自我修正）
            llm_output: 出错的原始模型输出
            send_to_llm: 是否把 observation + llm_output 发回给 Agent，
                         让模型知道上次输出格式不对并自行改正
        """
```

设计意图：`observation` + `send_to_llm` 就是「**把错误喂回模型让它自己修**」的协议字段。

### 11.2 四种失败场景与对策

**场景 A：解析可能失败，但我想拿到原始响应自己判断 → `include_raw=True`**

```python
structured_model = model.with_structured_output(MySchema, include_raw=True)
result = structured_model.invoke(prompt)

result["raw"]             # AIMessage：看 tool_calls 是否为空 → 区分「没调工具」vs「参数错」
result["parsed"]          # 成功时为 MySchema 实例；失败时为 None
result["parsing_error"]   # 失败时的异常对象；成功时为 None
```

**场景 B：自动重试同一条链 → `with_retry()`（RunnableRetry）**

```python
from langchain_core.output_parsers import PydanticOutputParser

parser = PydanticOutputParser(pydantic_object=MySchema)
chain = prompt | model | parser

# with_retry 默认只对 OutputParserException 等指定异常重试（retry_if_exception_type）
robust_chain = chain.with_retry(
    stop_after_attempt=3,          # 最多 3 次
    wait_exponential_jitter=True,  # 指数退避 + 抖动
)
```

注意：单纯重跑同一条链，模型温度不为 0 时才可能「碰运气」成功；
更可靠的是**换更强的模型兜底**：

```python
# 场景 C：解析失败就降级到更强的模型
chain = (prompt | weak_model | parser).with_fallbacks(
    [prompt | strong_model | parser]
)
```

**场景 D：把错误信息喂回模型定向修复（repair loop）**

```python
from langchain_core.exceptions import OutputParserException
from langchain_core.messages import HumanMessage

def invoke_with_repair(model, parser, prompt_text, max_attempts=3):
    messages = [("user", prompt_text + "\n\n" + parser.get_format_instructions())]
    for _ in range(max_attempts):
        response = model.invoke(messages)
        try:
            return parser.invoke(response)          # 成功即返回
        except OutputParserException as e:
            # ★ 关键：把「你上次的输出 + 为什么错」作为新消息喂回去
            messages.append(response)                # 模型看到自己的错误输出
            messages.append(HumanMessage(
                content=f"你的输出无法解析：{e}。请严格按格式重新输出，不要任何多余文字。"
            ))
    raise RuntimeError("修复重试次数用尽")
```

**Agent 级重试**：`create_agent(response_format=ToolStrategy(schema, handle_errors=...))`
内置了同样的回路——解析失败时把错误模板作为 ToolMessage 发回给模型重新调用工具
（见 2.3 节 `handle_errors` 的五种取值）。

### 11.3 各解析器的异常行为差异（重要）

| 解析器 | 完整模式失败 | 流式（partial）失败 |
|---|---|---|
| `JsonOutputParser` | `OutputParserException`（带 llm_output） | 返回 `None`，该帧被跳过 |
| `PydanticOutputParser` | `OutputParserException`（包装 ValidationError） | 返回 `None` |
| `JsonOutputToolsParser` | `OutputParserException`（arguments 非法 JSON） | `parse_partial_json` 尽量容忍 |
| `PydanticToolsParser` | **裸 `pydantic.ValidationError` / ValueError**（注意不是 OutputParserException！截断时另有 max_tokens 日志告警） | 跳过不合规帧 |
| `XMLOutputParser` | `OutputParserException` | XML 闭合后的垃圾尾巴被静默忽略 |
| `JsonOutputKeyToolsParser`（first_tool_only） | 模型没调目标工具时返回 **`None`**（不是异常） | 同左 |

## 12. 完整代码示例（四个场景）

### 场景 1：Pydantic 模型 + with_structured_output（含诊断模式）

```python
"""场景1：用 with_structured_output 抽取工单信息，附 include_raw 诊断分支。"""
from langchain.chat_models import init_chat_model
from pydantic import BaseModel, Field
from typing import Literal

# 1. 定义输出 schema —— 字段 description 会进入工具的 JSON Schema，
#    是给模型看的「字段说明书」，写得越清楚输出越准
class Ticket(BaseModel):
    """IT 工单结构化信息。"""                    # docstring → 工具 description
    title: str = Field(description="不超过20字的工单标题")
    priority: Literal["low", "medium", "high"] = Field(description="紧急程度")
    affected_systems: list[str] = Field(description="受影响的系统列表")
    reporter_quote: str = Field(description="用户原话摘录")

model = init_chat_model("openai:gpt-4o", temperature=0)

# 2. 正常模式：直接得到 Ticket 实例；解析失败会抛异常
structured_model = model.with_structured_output(Ticket)
ticket = structured_model.invoke("我们的ERP系统从今早9点开始无法登录，财务月结卡住了，非常紧急！——老王")
print(ticket.priority)          # 'high'
print(ticket.affected_systems)  # ['ERP']

# 3. 诊断模式：不确定失败原因时，用 include_raw 区分
#    「模型没调工具」(raw.tool_calls 为空) vs 「调了但参数不合 schema」(parsing_error 非空)
diag_model = model.with_structured_output(Ticket, include_raw=True)
result = diag_model.invoke("同上工单描述")
if result["parsing_error"]:
    print("原始消息:", result["raw"])          # 看 tool_calls 内容
    print("解析错误:", result["parsing_error"])
else:
    print(result["parsed"])
```

### 场景 2：JSON Schema / TypedDict + LCEL 链（不依赖函数调用）

```python
"""场景2：对不支持工具调用的模型，用 prompt + JsonOutputParser 走纯文本 JSON。
同时演示 TypedDict schema 与 with_structured_output 的 dict 返回。"""
from typing import TypedDict
from langchain_core.output_parsers import JsonOutputParser
from langchain_core.prompts import ChatPromptTemplate

# 方式 A：TypedDict + with_structured_output（返回未校验的 dict）
class Summary(TypedDict):
    """文章摘要结构。"""
    headline: str
    key_points: list[str]

structured = model.with_structured_output(Summary)   # dict 输出，不做校验
print(structured.invoke("总结这篇文章：..."))         # {'headline': ..., 'key_points': [...]}

# 方式 B：裸 JSON Schema + JsonOutputParser 手工组链（最通用，任何模型可用）
json_schema = {
    "title": "TranslationResult",
    "type": "object",
    "properties": {
        "translation": {"type": "string", "description": "英文译文"},
        "confidence": {"type": "number", "description": "置信度 0~1"},
    },
    "required": ["translation", "confidence"],
}

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是专业翻译。{format_instructions}"),   # ★ 格式说明注入 system
    ("user", "{text}"),
])
parser = JsonOutputParser()      # 不传 pydantic_object → 纯 JSON 解析（它本来也不校验）

chain = (
    prompt.partial(format_instructions=
        "只输出符合以下 JSON Schema 的 JSON，不要 Markdown 围栏、不要解释：\n"
        + str(json_schema))      # 手写指令（也可用带 pydantic_object 的 parser 自动生成）
    | model
    | parser
)

```

### 场景 3：多输出解析链（fallback + 分支路由）

```python
"""场景3：组合多个解析器——先走工具调用解析，失败降级到纯文本 JSON 解析；
以及按模型输出内容路由到不同解析器的 RunnableBranch 用法。"""
from langchain_core.output_parsers import PydanticToolsParser, JsonOutputParser, StrOutputParser
from langchain_core.runnables import RunnableBranch, RunnableLambda
from langchain_core.exceptions import OutputParserException
from pydantic import BaseModel

class Sentiment(BaseModel):
    label: str
    score: float

# ---- 3a. with_fallbacks：工具解析链失败 → 文本 JSON 链兜底 ----
tool_chain = model.bind_tools([Sentiment], tool_choice="Sentiment") | PydanticToolsParser(
    tools=[Sentiment], first_tool_only=True
)
text_parser = JsonOutputParser()      # 兜底：直接抠 JSON
text_chain = model | text_parser | RunnableLambda(lambda d: Sentiment(**d))  # 手工校验

robust_chain = tool_chain.with_fallbacks([text_chain])   # 前者抛任何异常都切后者
print(robust_chain.invoke("这家餐厅太难吃了"))            # Sentiment(label='negative', ...)

# ---- 3b. RunnableBranch：按输出格式路由到不同解析器 ----
from langchain_core.output_parsers import XMLOutputParser, CommaSeparatedListOutputParser

xml_parser = XMLOutputParser()
csv_parser = CommaSeparatedListOutputParser()
str_parser = StrOutputParser()

def looks_like_xml(text: str) -> bool:
    return text.strip().startswith("<")

def looks_like_list(text: str) -> bool:
    return "," in text and "\n" not in text.strip()

router = RunnableBranch(
    (lambda msg: looks_like_xml(str(msg.content)), xml_parser),     # 条件1 → XML 解析
    (lambda msg: looks_like_list(str(msg.content)), csv_parser),    # 条件2 → 逗号列表解析
    str_parser,                                                      # 默认 → 原样字符串
)
chain = model | router      # 同一条链自适应三种输出形态
```

### 场景 4：流式结构化解析（快照 + JSONPatch 增量 + 流式 Pydantic）

```python
"""场景4：三种流式结构化解析姿势。"""
from langchain_core.output_parsers import JsonOutputParser, PydanticOutputParser
from pydantic import BaseModel, Field

class Report(BaseModel):
    title: str = Field(description="报告标题")
    sections: list[str] = Field(description="章节列表")

prompt_text = "为『数据库选型』写一份报告大纲，输出 JSON：title 和 sections 两个字段。"

# ---- 4a. 快照模式：每帧都是「到目前为止」的完整 dict，UI 直接整体重渲染 ----
snapshot_parser = JsonOutputParser()
for frame in snapshot_parser.transform(model.stream(prompt_text)):
    print("快照:", frame)
# 快照: {'title': '数据库选型'}
# 快照: {'title': '数据库选型', 'sections': ['需求分析']}
# 快照: {'title': '数据库选型', 'sections': ['需求分析', '候选对比']}  ...

# ---- 4b. JSONPatch 增量模式：只传变化，适合大对象/低频更新的前端 ----
patch_parser = JsonOutputParser(diff=True)
for patch in patch_parser.transform(model.stream(prompt_text)):
    print("增量:", patch)
# 增量: [{'op': 'add', 'path': '/title', 'value': '数据库选型'}]
# 增量: [{'op': 'add', 'path': '/sections/0', 'value': '需求分析'}] ...

# ---- 4c. 流式 Pydantic：字段凑齐并通过校验的那一帧起，才产出 Report 实例 ----
pyd_stream = model | PydanticOutputParser(pydantic_object=Report)
for frame in pyd_stream.stream(prompt_text):
    # 说明：未通过校验的中间帧返回 None，会被累积基类的
    # 「parsed is not None and parsed != prev_parsed」过滤掉，这里收到的都是 Report 实例
    print("Pydantic 帧:", frame)
# 字段凑齐并通过校验后开始产出 Report(title=..., sections=[...]) 实例，逐帧逼近最终值
```

## 13. 最佳实践与常见陷阱

### 13.1 选型速查

1. **优先用 `with_structured_output`**，不要手工 `bind_tools` + 解析器（除非你明确知道
   在做什么）——`bind_tools` 只返回带 `tool_calls` 的 `AIMessage`，**不含**解析环节。
2. `method` 按提供商**文档化能力**显式指定，别依赖默认值（默认值随集成和版本变化）：
   - 支持原生 Structured Outputs → `json_schema`（配合 `strict=True` 最强）；
   - 支持工具调用且支持强制 `tool_choice` → `function_calling`；
   - 只支持 JSON mode → `json_mode` + prompt 里写清 schema + 应用层校验重试。
3. **Agent 场景**用 `create_agent(response_format=...)`：模型画像准确时用自动策略
   （直接传 schema）；确知原生支持用 `ProviderStrategy`；需要校验失败自动重试回路用
   `ToolStrategy(handle_errors=...)`。不要把 agent 策略和模型级 `method` 混为一谈。
4. 模型不支持任何结构化能力（或本地小模型）→ 退回 `PydanticOutputParser` +
   `get_format_instructions()` 进 prompt + 重试兜底。

### 13.2 陷阱清单

**陷阱 1：`with_structured_output` 返回 `None` / 字段缺失。**
最常见根因链：`function_calling` 依赖强制 `tool_choice`；若适配层剥离或提供商忽略了
`tool_choice`（例如设置了 `disabled_params={"tool_choice": None}`），模型就可以**自由地
不调用 schema 工具**、改说自然语言——`JsonOutputKeyToolsParser(first_tool_only=True)`
此时按设计返回 `None`（见源码 5.1）。诊断：`include_raw=True` 看
`raw.tool_calls` 是否为空。小模型/量化模型 + 复杂 schema 是最易失败组合，**拆小 schema、拆多次调用**。

**陷阱 2：提供商 400 报错 `<model> does not support this tool_choice`。**
这不是 schema 错了，也不是不支持工具调用，而是后端**拒绝强制工具选择**
（典型：某些 OpenAI 兼容网关、思考模式下的推理模型）。模型级修法：

```python
model = ChatXxx(..., disabled_params={"tool_choice": None})   # 绑定前过滤掉 tool_choice
structured = model.with_structured_output(Schema, method="function_calling")
```

原理：OpenAI 系实现会先过 `_filter_disabled_params(...)` 再 bind（见 2.2 源码）。
注意两点：① 这只对**模型包装器路径**有效，`create_agent(response_format=ToolStrategy(...))`
仍会 `bind_tools(..., tool_choice="any")`，不受 `disabled_params` 影响；② 去掉强制后模型
可能不调工具 → 输出变 `None`，回到陷阱 1，需按能力换 `json_schema` / `json_mode` 或加重试。

**陷阱 3：`JsonOutputParser(pydantic_object=Foo)` 并不校验。**
1.x 源码里 `pydantic_object` 只参与 `get_format_instructions()`；解析路径就是
`parse_json_markdown`，返回的是**未校验 dict**。要校验用 `PydanticOutputParser`，
或工具路径的 `PydanticToolsParser`。

**陷阱 4：输出被 `max_tokens` 截断 → Pydantic 校验失败。**
`PydanticToolsParser` 对此有专门探测：发现 `response_metadata.stop_reason == "max_tokens"`
时记录 `_MAX_TOKENS_ERROR` 日志（「输出很可能不完整，请增大 max_tokens 或缩短 prompt」）
然后照抛 `ValidationError`。看到校验失败先查截断，别急着改 schema。

**陷阱 5：两个 Pydantic 解析器抛的异常类型不同。**
`PydanticOutputParser` 抛包装后的 `OutputParserException`；`PydanticToolsParser`
完整模式抛**裸 `ValidationError`/`ValueError`**。统一捕获时写
`except (OutputParserException, ValidationError, ValueError)`。

**陷阱 6：`strict` 字段名与直觉相反。**
`JsonOutputToolsParser.strict` / `parse_tool_call(strict=...)` 直接透传给
`json.loads(strict=...)`。解析器默认 `strict=False`，即**放宽** JSON 规范——允许字符串值内
出现裸换行、制表符等控制字符（模型输出长文本时常见）。如果你手动设了 `strict=True`，
含未转义换行的输出会开始报 `Invalid \n escape`。阅读源码时极易把这个字段理解反。

**陷阱 7：工具名匹配依赖类名或 title。**
`PydanticToolsParser` 用 `model_config.get("title") or tool.__name__` 建名字映射。
如果你给模型设置了自定义 `name`（如 `convert_to_openai_tool` 后被改名）或使用了
`model_config = {"title": ...}`，映射对不上会抛
`Unknown tool type: ... Available tools: ...`——错误消息里会列出可用名，照着改。

**陷阱 8：流式解析的 `None` 帧与「最后一帧」。**
累积式解析器对不完整的中间态返回 `None`（基类会过滤），但**手写循环调用
`parse_result(partial=True)` 时**你要自己跳过 `None`。另外 `PydanticToolsParser`
源码注释明说：目前只在**所有字段齐了以后**才开始流出对象（TODO: 更细粒度），
不要期待逐字段流式。

**陷阱 9：XML 解析记得装 defusedxml。**
`XMLOutputParser` 默认 `parser="defusedxml"`，未安装直接 `ImportError`。
不要为了省依赖改成 `parser="xml"`——解析的是**模型输出（不可信输入）**，
标准库解析器存在 XXE / XML 炸弹风险面。

**陷阱 10：列表解析器的流式「最后一项延迟」。**
`droplastn(..., 1)` 决定了：最后一个匹配永远要等**下一个 chunk 或流结束**才能确认完整。
即最后一项总是在流末尾才产出，不是 bug。

**陷阱 11：遗留 API 别再用。**
`openai_functions.py` 一族（`JsonOutputFunctionsParser` 等）对应已废弃的 functions API，
且已移出 `langchain_core.output_parsers.__all__`；`SimpleJsonOutputParser` 只是
`JsonOutputParser` 的兼容别名；`StreamingOutputParser` 在 1.x 已不存在（见 9.1）。
新代码用 tools 系 + transform 系。

**陷阱 12：中文格式说明的编码。**
`get_format_instructions()` 内部用 `json.dumps(..., ensure_ascii=False)`，
Field 的中文 description 会原样进入 prompt（不会被转成 `\uXXXX` 浪费 token、
也不会降低模型理解度）——自定义格式说明模板时保持同样习惯。
