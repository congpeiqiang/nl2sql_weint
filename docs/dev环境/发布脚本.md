# dev 发版命令手册（192.168.25.34）

> 本文**只列命令**。设计原理、逐条验收理由、残余风险见 [蓝绿发布_dev手册.md](蓝绿发布_dev手册.md)。
> 生产环境（25.64）的脚本在 `docs/prod环境/`，**两者不要混用**（端口号完全相同）。
> ⚠️ **提示符里没有环境名**：跑命令前先 `hostname` / `ip a` 确认落在哪台机器上。

| 脚本（都在本目录） | 作用 |
|---|---|
| [dev-release-backend-bluegreen.ps1](dev-release-backend-bluegreen.ps1) | **后端发版（蓝绿，首选）** —— 用户侧 0 个 5xx |
| [dev-release-backend.ps1](dev-release-backend.ps1) | 后端发版（老路）—— 破坏性迁移 / 停机窗口的退路，有一次冷启中断 |
| [dev-release-frontend.ps1](dev-release-frontend.ps1) | 前端发版 —— **不是蓝绿**，`location /` 有几秒 502 |
| [dev-apply-nginx-conf.sh](dev-apply-nginx-conf.sh) | 把仓库 `docker/nginx.conf` 整份同步到 34 |
| [dev-swap-src.sh](dev-swap-src.sh) | 服务器侧的 `src` 换装助手（发版脚本自己会送上去，一般不用手工跑） |

**与 prod 最大的区别**：dev 的后端代码走 **bind mount**（`/mydata/nl2sql/src` → `/app/src`），
不是打进镜像。所以 dev 发版**换的是目录，不是镜像**，全程 `docker save` / `docker build` 都不需要。
dev 是 **compose v2**（`docker compose`，容器名用**连字符** `nl2sql-app-*-1`）。

## 0. 首次准备

```powershell
cd D:\code_work_space\llm\nl2sql\docs\dev环境
.\dev-setup-ssh.ps1          # 只在这一步输一次 34 的口令；幂等，重复跑没事
```

一次发版有 30+ 次远程调用，没有 SSH key 就**每一次都单独弹一次口令**（轮询那 30 次够受的）。
本机 Git Bash 的 ssh 实测**不支持** ControlMaster 连接复用，所以只有「装 key」这条路。
同一个 `id_ed25519` 也是本机唯一能登 64 的 key —— 别删、别重新生成。

## 1. 后端发版（蓝绿 · 首选）

```powershell
cd D:\code_work_space\llm\nl2sql\docs\dev环境
.\dev-release-backend-bluegreen.ps1
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-DrainBudget` | `180` | 排空预算（秒），须 < compose `stop_grace_period=240s` |
| `-ChunkMB` / `-MaxRetry` | `0.5` / `8` | 分片大小 / 每片重试；链路差时把 `-ChunkMB` 调更小 |
| `-SkipPackage` | — | 复用服务器上已上传的包（重试时省一次上传） |
| `-Force` | — | 线上 nginx 与仓库模板不一致 / 流量不在 A / 有残留 B 时允许继续（**知道自己破坏哪条假设再用**） |
| `-Rollback` / `-PrevSrc` | — | 见 §4 |

推送的是**本机工作树**（含未提交改动）—— 这正是 dev 的用途；脚本开头会打印分支名与未提交改动数。

**发版前只读核对**（脚本第 0 步会自己打一遍，不满足会**在动手前停**）：

```bash
ssh weint@192.168.25.34 'docker ps -a | grep langgraph-api; \
  docker exec nl2sql-app-nginx-1 grep -n backend_up /etc/nginx/nginx.conf'
```

期望：只有 `nl2sql-app-langgraph-api-1` 一个容器（**无残留 B**），且
`set $backend_up  "langgraph-api:2026"`（两个空格，别被它骗了）。

**结束时看这几行**（脚本尾部的「本次发版结论」）：

```
POLL_TOTAL=131   POLL_NON200=0        ← 1s 轮询 /ok 全程非 200 计数
排空确认：A=yes  B=yes                 ← A=stale 见 §5
回退用：上一版代码目录 = src-prev-<stamp>
```

> ⚠️ dev 的代码目录是**轮换**出来的：发版结束时 `src` 是新代码、`src-prev-<stamp>` 是上一版。
> `src-prev-*` 是回退的唯一依据，**别手工删**（回退还会再留一个 `src-rolledback-*`）。
> `src-next` 常常会「复活」成一个**空的 root 属主目录**（切流后还 exec 过 B 所致，**无副作用**）：
> 脚本第 0 步会提示、第 3 步会清掉重放。详见 [蓝绿发布_dev手册.md](蓝绿发布_dev手册.md) §5.4。

## 2. 后端发版（老路 · 只在三种情况用）

```powershell
cd D:\code_work_space\llm\nl2sql\docs\dev环境
.\dev-release-backend.ps1
```

只在 ① **破坏性迁移**（删列 / 改类型，蓝绿的 expand-contract 不允许）、② 明确要一个**停机窗口**、
③ 蓝绿脚本本身出问题时用。代价：`src` 换装 + `docker compose restart`，**一次冷启中断**。

## 3. 前端发版

```powershell
cd D:\code_work_space\llm\nl2sql\docs\dev环境
.\dev-release-frontend.ps1              # 本地构建 → 打包 → 分片上传 → 只重启 frontend
.\dev-release-frontend.ps1 -SkipBuild   # 跳过本地构建（.next 须已是最新）
```

* 构建**必须在本地**：前端源码含 DLP 密文，只有本机的 DLP agent 解得了，服务器上 build 不出来。
* 只对 `frontend` 做 `stop/rm/up`，**不碰 nginx**（新前端 IP 由 nginx 请求期解析 ≤10s 自愈）。
* **不是蓝绿**：`location /` 有几秒 502。目前 dev 与 prod 都这样。

## 4. 回滚

### 后端（蓝绿，零中断）

```powershell
cd D:\code_work_space\llm\nl2sql\docs\dev环境
.\dev-release-backend-bluegreen.ps1 -Rollback                  # 读 /tmp/nl2sql_bluegreen_dev.state
.\dev-release-backend-bluegreen.ps1 -Rollback -PrevSrc src-prev-20261008-153012
```

* 上一版目录来自上次发版的 `SRC_PREV`（或服务器上 `ls -1d /mydata/nl2sql/src-prev-*`）。**不给就拒绝猜**。
* 回退**本身也是蓝绿**：先把 B 挂到 `src-prev-<stamp>` 起临时色 → 切流 → 停 A → 目录轮换回来 →
  起 A → 切回 A → 停 B。**不是「把 A 重启成旧版」**，所以同样零中断。
* 回退的终点 = 发版的终点（A 常驻、B 已删），所以回退完可以**立刻再次发版**；
  `-Rollback` 连跑两次 = 退回去再退回来（被换下去的那份留档成 `src-rolledback-<stamp>`）。
* 回退后 A 跑的是上一版代码，而平台库可能已被新版迁移改过（迁移是 add-only，一般仍能跑）。

### 切流之前就出问题（B 起不来 / 探测不过 / `nginx -t` 失败）

**线上零影响**（B 未接流、nginx 未切），清掉 B 重跑即可：

```bash
ssh weint@192.168.25.34 'bash /tmp/nl2sql_bg_steps_dev.sh rm_b'
```

> `nginx_apply` 若 `nginx -t` 失败会**就地回滚到备份且不 reload**，线上仍是旧配置。

### 前端

切回上一版前端代码，重跑 `.\dev-release-frontend.ps1`。每次覆盖 `:latest`，**没有 tag 回滚机制**；
要留旧版就在发布前手动 `docker tag nl2sql-app_frontend:latest nl2sql-app_frontend:rollback-<ts>`。

## 5. 验证

### ① 发版脚本自带的采样断言（看结尾那几行）

| 看什么 | 期望 |
|---|---|
| `POLL_NON200` | `0`（覆盖两次切流 + A 的重建 + 两次排空；原始采样 `/tmp/nl2sql_bg_dev_poll.log`） |
| `排空确认：A=` | `yes`。出现 **`stale`** = 切流之后旧色 A 又领到 run（残余竞态被观测到），查 A 的日志定位是哪一条 |
| 两色日志 | `database is locked` 各 0 条（日志另存在 `/tmp/nl2sql_dev_last_*.log`） |

> 只看**第 8 步**的 A。第 12 步停 B 时两色已是同一份代码，B 领到 run 也无害。

### ② 手工冒烟（服务器上跑）

```bash
# 后端直连 + 经 nginx（200 与 401 都算「通」：401=需登录，说明请求到得了应用；502=上游没解析到，404=路由没挂）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:2026/ok        # 200
for p in / /ok /api/db-configs /api/mcp/status; do \
  printf "%-18s -> " "$p"; curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:8080$p"; done

# 稳态：只剩 A 一个色、流量在 A
docker ps -a | grep langgraph-api
docker exec nl2sql-app-nginx-1 grep -n backend_up /etc/nginx/nginx.conf

# 平台库计数（发版前后应只增不减）
docker exec nl2sql-app-postgres-1 psql -U nl2sql -d nl2sql_platform -c \
  "select (select count(*) from thread) as thread, (select count(*) from schema_migrations) as migrations;"

# 预检结论与工具数（改了 MCP / 语义库时必看）
docker logs nl2sql-app-langgraph-api-1 2>&1 | grep -E "预检通过|预检失败" | tail -4
```

> dev 的 `.env.dev` 设了 `MCP_ALLOW_DEGRADED=0`，但语义库连不上等情况仍会让 A/B 都出现
> 「预检失败 + 降级启动」。**别拿它当回归判据** —— 判据是「B 不比 A 差」（脚本第 6 步已内置）。

### ③ 收尾清理（中途失败留下残留 B 时）

```bash
ssh weint@192.168.25.34 'bash /tmp/nl2sql_bg_steps_dev.sh rm_b'   # 删 B 容器（只碰这一个）
```

### ④ 发版前本地静态闸（改过脚本 / compose / nginx.conf / `dev-swap-src.sh` 后必跑）

```bash
PYTHONIOENCODING=utf-8 uv run --no-sync python scripts/verify_dev_blue_green.py        # 156/156
PYTHONIOENCODING=utf-8 uv run --no-sync python scripts/verify_blue_green.py            # 118/118
PYTHONIOENCODING=utf-8 uv run --no-sync python scripts/verify_release_zero_downtime.py # 43/43
```

### ⑤ 改过 `.ps1` 后必跑的两个闸

```bash
# 解析闸
powershell.exe -NoProfile -Command \
  '$e=$null; [void][System.Management.Automation.Language.Parser]::ParseFile((Resolve-Path ".\dev-release-backend-bluegreen.ps1").Path,[ref]$null,[ref]$e); if($e){$e|%{$_.Message}} else {"PARSE_OK"}'

# BOM 闸（无 BOM 时 PS 5.1 按 GBK 解码中文注释，会吃掉后面的字符）
head -c 3 dev-release-backend-bluegreen.ps1 | od -An -tx1     # 应为 ef bb bf
```

> 写这个 `.ps1` 时最容易踩的两个**语法**坑（都会让整段静默不执行）：
> ① `||` 不是 PS 的语句分隔符（别抄 bash 的 `cmd \` 换行 ||`）；
> ② 换行续接时 `+` **必须留在行尾** —— `"aaa"` 换行 `+ "bbb"` 报「缺少 )」。

## 6. 改了 `docker/nginx.conf` 怎么上

```bash
bash docs/dev环境/dev-apply-nginx-conf.sh          # 在仓库根跑
```

* `docker/nginx.conf` **不在发版包里**（tar 排除 `docker/`），改了必须手工跑这一条；发版不会带过去。
* 它做的是「md5 判差异 → 备份 → 就地写**同一 inode** → `nginx -t`（失败自动回滚）→ reload」，
  同步的是**整份文件**。
* 换个容器**不需要**这条（上游是请求期解析，≤10s 自愈）；只有**配置本身变了**才用。
* ⚠️ 变量形式的 `proxy_pass` 不做启动期解析 ⇒ **上游主机名写错 `nginx -t` 也照样通过**，必须真打一次请求。

| # | |
|---|---|

## 8. 附录：少见场景

### A. 一次性准备（首次或换机器）

见 §0。脚本做三件事：复用（没有才生成）`~/.ssh/id_ed25519`；把公钥去重后追加到 34 的
`authorized_keys`；用 `-o BatchMode=yes` 验证免密**真的生效**（不过就明确报错，不让你带隐患往下走）。

### B. 只改了 `src/` 下的 Python / prompt / 配置模板（日常 99%）

→ §1（蓝绿）。dev 的代码是 bind mount，换目录 + 重启容器即可，镜像里的 `.venv` 不动。

### C. 后端依赖变了（改了 `pyproject.toml` / `uv.lock`）

蓝绿与老路**都发不了** —— dev 没有「构建」这一步（34 无外网）。走「在 64 上构建、搬镜像回 34」：

```bash
# 1) 本机打包后端（用生产的排除清单，但**不要**排除 src —— dev 的镜像里也要它）
#    输出到 D:\code_work_space\llm\deepseek-workspace\nl2sql-dev\
# 2) 传到 64 的**独立**目录 /home/weint/apps/nl2sql/dev-build/backend/（不碰生产的 backend/）
# 3) 64 上构建（只用独立 tag，绝不覆盖生产 tag）：
#      docker build -t nl2sql-dev-backend:<ts> .
# 4) 搬到 34（在 34 上跑，只新增 tag，不删任何镜像）：
#      ssh weint@192.168.25.64 "docker save nl2sql-dev-backend:<ts>" | docker load
# 5) 34 上换 tag 重建：
cd /mydata/nl2sql/nl2sql-app
docker tag nl2sql-app_langgraph-api:latest nl2sql-app_langgraph-api:rollback-<ts>   # 存旧
docker tag nl2sql-dev-backend:<ts> nl2sql-app_langgraph-api:latest
docker compose stop langgraph-api nginx && docker compose rm -f langgraph-api nginx
docker compose up -d --no-deps langgraph-api nginx
# 6) 验证同 §5②
```

> ⚠️ **在 64 上构建只能用自己的 tag 和独立目录** —— 打上 `nl2sql-app_langgraph-api:latest`
> 就等于改动了生产镜像。

### D. 让 dev 追平生产版本（不构建，最稳）

用途：dev 想验证的正是生产那版行为；或 §C 构建失败时的兜底。日常通常只搬最后两个应用镜像。

```bash
# 在 34 上跑。64 上零落盘（docker save 走 stdout）；要用一个临时 askpass 带 64 的口令，用完即删。
# 用法：bash pull_from_64.sh [镜像名...]（不给参数则默认搬两个应用镜像）
```

完整脚本见 [蓝绿发布_dev手册.md](蓝绿发布_dev手册.md) §附录，或 git 历史里的
`docs/dev环境/发布脚本.md`（2026-10-08 版）。搬完**必须重建对应容器**：

```bash
cd /mydata/nl2sql/nl2sql-app
docker compose stop langgraph-api nginx && docker compose rm -f langgraph-api nginx
docker compose up -d --no-deps langgraph-api nginx
```

> dev 的 nginx 上游是**请求期解析**的 ⇒ 重建后端容器后**不需要** reload nginx；
> 但**配置本身**变了（§6）那一条仍然要跑。
