# 03 · 定时任务 API

> 源文件：`src/api/scheduled_tasks.py`（服务层 `agent/scheduler/service.py`，
> 固化 `pin_service.py` / `pin_exec.py` / `query_spec.py`，执行 `worker.py`）

## 契约

- 成功：`{"ok": true, "task" / "tasks" / "runs" / "pin": ...}`
- 失败：`{"ok": false, "error": "<用户可读>", "code"?: "<机读码>", "extra"?: {...}}`
- **owner 隔离在 service 层强制**：非管理员访问他人任务一律 **404**（不泄露存在性）；
  校验/状态错误（`ScheduleError`）→ 400。

## 1. `GET /api/scheduled-tasks`（登录）

**功能**：按 owner 过滤列出任务（管理员可 `?all=1`）；非本人任务由 service 层一律按 404 处理（不泄露存在性）。

**实现逻辑**：取 user → `show_all` 由 `?all=1` 且管理员决定 → `service.list_tasks(user, show_all)`（owner 过滤，非本人按 404 处理）

**入参**

| 参数 | 位置 | 说明 |
|---|---|---|
| `all` | query | `1` = 管理员看全部任务；否则只看自己的 |

**出参** `{"ok":true,"tasks":[<task>]}`；`500 {"ok":false,"error":"读取任务列表失败: ..."}`

`<task>` 主要字段：

```json
{"id":"...","owner":"uid","name":"任务名","prompt":"自然语言需求",
 "db_name":"imdb","sched_kind":"once|interval|cron","sched_expr":"...","tz":"Asia/Shanghai",
 "enabled":true,"state":"scheduled|paused|completed","next_run_at":"ISO",
 "last_run_at":"ISO","last_status":"success|error|...","retry_count":0,
 "running_thread_id":"","llm_route":"","llm_model":"",
 "pin_status":"active|invalid|none","pin_saved_at":"ISO","pin_semantic_version":"..."}
```

## 2. `POST /api/scheduled-tasks`（登录）

**功能**：校验调度表达式与目标库授权后落库任务，并预先算出首次 `next_run_at`（cron 用 croniter+tz，interval 为分钟数，once 为指定时刻）。

**实现逻辑**：`parse_body` → `service.create_task(user, body)`：校验调度表达式 + 复验库授权 + 算首次 `next_run_at` + 落库 → `ScheduleError`→400

**入参（主要字段）**

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 任务名（会话标题前缀 `[定时]`） |
| `prompt` | 是 | 自然语言需求 |
| `db_name` | 是 | 目标库（创建与每次触发都会复验授权） |
| `sched_kind` | 是 | `once` / `interval` / `cron` |
| `sched_expr` | 是 | interval = 分钟数；cron = 标准表达式；once = 触发时间 |
| `tz` | 否 | 时区名，默认服务器本地 |
| `llm_route` / `llm_model` | 否 | 指定模型（缺省跟随 active） |
| `enabled` | 否 | 默认 true |

**出参** `{"ok":true,"task":{...}}`
**错误**：`400 {"ok":false,"error":"<ScheduleError 文案>"}`、`500 {"ok":false,"error":"创建任务失败: ..."}`

## 3. `POST /api/scheduled-tasks/preview`（登录）

**功能**：用 croniter+tz 算出未来 N 次触发时间与人类可读描述，**不落库、不建任务**（供创建/编辑表单实时预览，前端不装第二套 cron 数学）。

**实现逻辑**：取 `sched_kind/sched_expr/tz/count`（clamp 1~10）→ `preview_runs()` + `describe_schedule()`（croniter+tz）→ **不落库**

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `sched_kind` / `sched_expr` | 是 | 同上 |
| `tz` | 否 | 时区 |
| `count` | 否 | 预览次数 1~10，默认 3 |

**出参** `{"ok":true,"runs":["ISO",...],"sched_display":"每天 09:00"}`

**错误**：`400 {"ok":false,"error":"<ScheduleError>"}`、`500 {"ok":false,"error":"预览失败: ..."}`

## 4. `PATCH /api/scheduled-tasks/{task_id}`（登录）

**功能**：按 `action` 执行暂停/恢复，或增量更新字段并重算下次触发；**换库会解绑固化**（旧口径已不成立）。

**实现逻辑**：取 `action` 并从 body `pop` → `pause_task` / `resume_task` / `update_task(user, id, body)`（换库即解绑固化）→ None→404

**入参**：path `task_id`；body 两种用法：

- `{"action":"pause"}` / `{"action":"resume"}`
- 直接传要改的字段（`name` / `prompt` / `db_name` / `sched_kind` / `sched_expr` / `tz` /
  `enabled` / `llm_route` / `llm_model`）

**出参** `{"ok":true,"task":{...}}`
**错误**：未知 action → `400 {"ok":false,"error":"未知 action: X（可选 pause/resume，或直接传要改的字段）"}`；
不存在 → `404 {"ok":false,"error":"任务不存在"}`；校验错 → `400`

## 5. `DELETE /api/scheduled-tasks/{task_id}`（登录）

**功能**：删除任务及其运行流水（owner 隔离）；不存在的任务按 404 返回。

**实现逻辑**：`service.delete_task(user, id)` → False→404

**入参**：path `task_id`

**出参** `{"ok":true}` / `404 {"ok":false,"error":"任务不存在"}`

## 6. `POST /api/scheduled-tasks/{task_id}/run`（登录）

**功能**：与 60s tick 走**同一个 CAS 认领**立即派发一次 run（双路触发天然互斥），fire-and-forget，不等执行完。

**实现逻辑**：`service.run_now(user, id)`（与 tick 共用 CAS 认领）→ "任务不存在"→404，其余 `ScheduleError`→400

**入参**：path `task_id`

**出参** `{"ok":true,"task":{...}}`；不存在 `404`，其余校验错 `400`，异常 `500`

## 7. `GET /api/scheduled-tasks/{task_id}/runs?limit=30`（登录）

**功能**：读 `task_runs` 运行流水，返回每轮的 run_id/状态/`pin_mode`/`pin_reason`，供前端历史列表与「本轮是回放还是回退」展示。

**实现逻辑**：`limit` clamp 1~200 → `service.list_runs(user, id, limit)` → None→404

**入参**：path `task_id`；query `limit`（默认 30，范围 1~200）

**出参**

```json
{"ok": true, "runs": [{"run_id":"...","thread_id":"...","fired_at":"ISO",
  "status":"success|error|timeout|interrupted|cancelled|running",
  "pin_mode":"normal|replay|fallback","pin_reason":"","error":""}]}
```

`pin_mode` 含义：

| 值 | 含义 |
|---|---|
| `normal` | 未配置固化，走正常 agent 执行 |
| `replay` | 本轮**固化回放**：数据由系统代取，主 agent 只解读 |
| `fallback` | 预检失败（库/版本/列/执行），本次回退正常执行，同时固化被标 `invalid` |

## 8. `GET /api/scheduled-tasks/{task_id}/pin`（登录）

**功能**：解析任务行上的 `pin_spec` 与 `pin_status`，回当前固化状态与模板；未固化返回 `pin: null`。

**实现逻辑**：`get_task_for_user` → 读 `pin_status/pin_spec`，无则 `pin:null`；有则 `json.loads(spec)` 后组装状态/版本/来源会话

**入参**：path `task_id`

**出参**（无固化时）

```json
{"ok": true, "pin": null}
```

有固化时：

```json
{"ok": true, "pin": {"status":"active|invalid","semantic_version":"<commit>",
  "saved_at":"ISO","invalid_reason":"","source_thread_id":"...","spec":{...}}}
```

`spec` 是固化模板（渠道、SQL / cube 定义、日期锚点、列签名等），前端只读展示。

## 9. `POST /api/scheduled-tasks/{task_id}/pin`（登录 + 库授权）

**功能**：从来源会话提取**那次成功查询**→日期锚点绑定（必要时 Wren 展开成物理 SQL）→**真跑一次只读查询**验证列与口径→写 `pin_spec`/`pin_status`；任一步失败返回机读 `code` 且**不落库**。

**实现逻辑**：分七步，任一步失败都**不落库**（半截 spec 会以 active 状态被回放，比没有更糟）。

1. **HTTP 层准入**（`pin_task_api`）：`require_user` → `get_task_for_user`（非本人按 404，不泄露存在性）→ `recheck_db_access(owner, db_name)`（固化会真跑查询，授权可能已被回收 → 403 fail-closed）→ 若 body 带 `thread_id` 再 `owned_thread()`（否则知道别人 thread_id 就能把别人的 SQL 固化进自己的任务，`preview_sql` 还会回显原文 —— 跨用户 IDOR）。
2. **定位来源会话**（`capture_spec`）：显式 `thread_id` 优先；否则 `_latest_success_thread()` 在 `task_runs` 找最近一条 `status=success` 且有 `thread_id` 的流水（无 → `no_source_run`）→ `client.threads.get_state()` 取 `values.messages` → `report_builder._find_last_check_result()` 找最近一条成功的 `check_async_task`（无 → `no_check_result`）。
3. **取回物理 SQL**（`_physical_sql_of`）：`sql_kind="cube"` 跳过（走定义）；否则 **内联 `dialect_sql` 优先，其次读 `dialect_sql_file` 指针**（>3000 字符只落盘）；两者都拿不到但确实存在 → `physical_sql_unreadable`。**绝不退回 `check["sql"]`** —— 语义层库里那是 wren 方言 SQL（`FROM v_workhour` 是 MDL 虚拟视图），回放必炸。同时 `_split_connector_limit()` 剥掉连接器末尾无条件追加的 `LIMIT n`（只剥末尾一条，模型自己的 top-N 保留），折算成 `spec["row_limit"] = min(5000, n)`，回放时补回，行数与来源 run 一致。
4. **日期锚点模板化**（`extract_spec` → `templatize`）：基准时间必须是**产生这条 SQL 那次 run 的时刻**（`task_runs.fired_at` → 该 thread 最近一次 run 的 `created_at` → 固化时刻），**不是**固化当天。

   > 事故：`2026-10-26` 在 10-27（周二）= `yesterday`，在 10-28（周三）= `week_start`；按固化当天解析会静默换成「本周一」，窗口逐日变宽、下周一直接起止倒挂恒空。

   锚点闭集（新增必须升 `SPEC_VERSION`）：`today` / `yesterday` / `tomorrow` / `month_start` / `last_month_start` / `last_month_end` / `year_start` / `week_start`。对每个**不同**的日期字面量（`\d{4}-\d{2}-\d{2}`）：

   | 情况 | 处理 |
   |---|---|
   | 在 `date_bindings` 里 | 用指定锚点，但校验锚点当天取值 == 字面量，否则 `bad_binding` |
   | 恰好命中 1 个锚点 | 直接用 |
   | 命中 0 个 | `accept_constants=false` → `unmatched_date`；`true` → 原样保留 + 告警 |
   | 命中 ≥2 个 | 先用用户原话收窄（`anchors_in_intent`，只收无歧义词，「上月」「周一」故意不在表内）；剩 1 个 → 用它 + 告警；否则 `ambiguous_date`（`extra.literal` / `extra.candidates`） |

   原则：**宁可报错不可猜错** —— 选错锚点，下个月口径整体偏。`caliber_block`（口径原文）逐字进 spec：回放时没有子 agent，报告口径节只能从这段抽。
5. **校验 spec 结构**（`extract_spec`）：cube 通道只保留 `CUBE_KEYS` 五键（`cube/measures/dimensions/filters/time_dimension`），出现 `limit/offset/granularity` 等 → `cube_key_unsupported`；缺 `cube`/`measures` → `no_query`。spec 头带 `v=1`、`db_name`、`tz`、`semantic_version`（Wren 项目 HEAD 的 **commit sha**，不比 tag/branch）、`source_thread_id`、`captured_at`。
6. **验证执行**（`run_pinned_spec`，**真跑一次**）：`render_spec`（版本闸 `spec_version_unknown`；模板占位符必须在 `params` 里，否则 `render_failed`）→ `row_limit = min(spec.row_limit, NL2SQL_SCHED_PIN_ROW_LIMIT=5000)` → sql 通道直接 `run_readonly_sql`；cube 通道 `resolve_wren_ctx_by_db` 无项目 → `not_semantic_db`、`plan_cube_sql_checked` 编译失败 → `cube_compile_failed`。
   `run_readonly_sql` 的铁律：`classify_sql` 判 write **硬拒**（`sql_failed`，不是审批）；按 `;` 拆多语句逐条 `_apply_default_limit(clamp_existing=True)`（无人值守通道必须把 SQL 自带的 `LIMIT 999999` 往下压）；引擎「async 外壳 + 同步实心」→ 一律 `asyncio.to_thread`；`truncated` 用**最后一条语句生效的 LIMIT** 判（语义层 plan 会追加 `LIMIT 1001`）。超时 120s → `exec_timeout`；**线程不可取消**，超时只放弃等待，SQL 在后台跑完。载荷裁剪 `rows[:200]`，超过也置 `truncated`。
7. **定基线并落库**：`spec["expect_columns"] = result.columns`（用**验证执行**的真实列；来源会话只有写给人看的文本，列名大小写/顺序/别名与驱动不一致，拿文本当基线第二次触发必误报漂移）→ `store.set_pin(spec_json, semantic_version, source_thread_id, now_iso)`。列比对发生在**触发时**（`validate_columns`，大小写不敏感、忽略顺序，只比增删列），不在固化时。

   固化后的 spec 形状：

   ```json
   {"v":1, "db_name":"witops", "tz":"Asia/Shanghai", "semantic_version":"a1b2c3d",
    "source_thread_id":"0192...", "captured_at":"ISO", "channel":"sql",
    "sql_template":"SELECT ... WHERE dt BETWEEN '{{p:month_start}}' AND '{{p:yesterday}}'",
    "params":["month_start","yesterday"], "expect_columns":["工号","姓名","工时"],
    "row_limit":5000, "caliber_block":"### 业务口径…", "warnings":[]}
   ```

   响应里的 `preview_sql` 是**实际下发**的那条（含引擎追加/收敛的 LIMIT）；`warnings` 三类：常量日期保留 / 按原话消歧 / **来源 run 非今日**（告诉运营「我点了固化，但用的是昨天的查询」）。

**入参**：path `task_id`；body 可选字段见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `thread_id` | 否 | 来源会话（缺省取任务最近一次成功 run）；**必须属于调用者** |
| `date_bindings` | 否 | 日期口径锚点选择（`ambiguous_date` 歧义确认时传） |
| `accept_constants` | 否 | true = 接受「对不上锚点」的字面量作业务常量 |

**出参**

```json
{"ok": true, "task": {"...": "<刷新后的任务>"},
 "pin": {"status":"active","channel":"sql|cube","preview_sql":"...","params":{},
         "warnings":[], "semantic_version":"...","saved_at":"ISO"}}
```

**错误**（`400`，带机读码）

```json
{"ok": false, "error": "<中文提示>",
 "code": "ambiguous_date|unmatched_date|no_source_run|no_check_result|columns_changed|not_semantic_db|cube_compile_failed|...",
 "extra": {}}
```

常见失效码：

| code | 含义 / 用户可做的动作 |
|---|---|
| `ambiguous_date` | 同一日期对应多个口径锚点 → 弹选择框（候选在 `extra.candidates`） |
| `unmatched_date` | 有对不上锚点的字面量 → 确认是业务常量（`accept_constants`）或改成相对日期 |
| `no_source_run` | 任务还没成功跑过一次 |
| `no_check_result` | 来源会话里没有成功的查询结果 |
| `columns_changed` | 返回列与固化时不一致（口径/表结构变了） |
| `not_semantic_db` | 该库已不是语义库，cube 通道无法回放 |
| `physical_sql_unreadable` | 只有语义层 SQL、读不回可执行物理版本 → 让任务再成功跑一次 |
| `sql_failed` / `exec_timeout` | 验证执行失败 / 超时 |
| `cube_key_unsupported` | cube 定义里有无法固化的键（limit/offset/granularity 等） |
| `spec_version_unknown` | 固化格式版本不认识（服务已升级，需重新固化） |
| `bad_binding` | `date_bindings` 指定的锚点与当天取值不符（锚点取值已变）→ 重新选择 |
| `no_query` | 来源结果里既无物理 SQL 也无 cube 定义（或 cube 缺 `cube`/`measures`） |
| `cube_compile_failed` | cube 定义编译失败（含引擎原话，通常 MDL 变了或名字拼错） |
| `render_failed` | 模板占位符与 `params` 不一致（spec 被改坏）或渲染期异常 → 重新固化 |

其他状态码：`403`（任务库授权已回收 / 无权访问来源会话）、`404`（任务不存在）、`500`

## 10. `DELETE /api/scheduled-tasks/{task_id}/pin`（登录）

**功能**：清空 `pin_*` 字段，任务回到正常 agent 执行（下次触发重新让模型写 SQL）。

**实现逻辑**：`pin_service.clear(id, "user_unpin: …")` → 回最新 task

**入参**：path `task_id`

**出参** `{"ok":true,"task":{...}}`；`404`；`500 {"error":"解绑固化失败: ..."}`

## 11. 固化回放机制（背景，非 HTTP 端点）

> 本节是第 7 节 `pin_mode` 字段的机制说明，**无入参/出参**。

触发时 `worker._fire` 在 `runs.create` **之前**做四道预检：

1. `spec.db_name == row.db_name`（写路径换库会解绑，这道闸盖住存量行）
2. 语义层 commit 与固化时一致（MDL 一变，物理 SQL 口径就变）
3. `run_pinned_spec` 只读执行成功
4. 返回列与固化签名一致（`validate_columns`）

通过则把结果合成一条成功的 `check_async_task` 结果塞进 `input`，并置
`configurable.pinned_replay=true`：

- 主 agent 侧 `PinnedReplayMiddleware` **摘掉 `start_async_task`**（模型看不见就不会再派子任务）
- `dynamic_prompt` 前置「固化回放模式」规则段（只解读数据、禁止重新取数、程序统计块照抄）

任一预检失败 → 标记 `pin_status=invalid` + `pin_mode=fallback`，走今天的正常执行路径
（纯增量能力，失效即回退）。
