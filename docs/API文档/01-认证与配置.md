# 01 · 认证与配置类 API

> 源文件：`src/api/auth_routes.py`、`auth_admin.py`、`db_config.py`、`model_config.py`、
> `deployment_info.py`、`eval_flags.py`
>
> 标注约定：每个端点都有 **入参**（位置 / 字段 / 必填）与 **出参**（成功响应体）两行；
> 「无」表示该端点不读任何参数（身份来自 Cookie/Authorization）。

## A. 登录与自助

### `POST /api/auth/login`（公开）

**功能**：校验 `auth_users.json` 中的用户名与口令（PBKDF2 26 万次迭代放线程池，不占事件循环），签发 24h 无状态 token 写入 HttpOnly Cookie，并把 `must_change_password` 透出给前端。

**实现逻辑**：`parse_body` → 字段非空 → `verify_password`（`asyncio.to_thread`，PBKDF2-260k）→ `sign_token` → `cookie_secure()` 判 Secure → `Set-Cookie`

**入参**（JSON body）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名（`auth_users.json`） |
| `password` | string | 是 | 明文口令，服务端 PBKDF2 校验 |

**出参** `200` + `Set-Cookie: nl2sql_token=...; HttpOnly; SameSite=Lax; Path=/`（HTTPS 时带 `Secure`）

```json
{"user_id": "string", "display_name": "string", "is_admin": true, "must_change_password": false}
```

**错误**：`400 {"error":"invalid JSON body"}`、`400 {"error":"username and password required"}`、
`401 {"error":"invalid credentials"}`

### `POST /api/auth/logout`（公开）

**功能**：只删除浏览器侧 Cookie；token 无状态、服务端无记录，因此这里**不**做吊销（要吊销须走管理员 `revoke` 或改密）。

**实现逻辑**：构造 `Response(204)` → `delete_cookie("nl2sql_token", path="/")`（不触服务端状态）

**入参**：无

**出参**：`204` 空响应 + `Set-Cookie: nl2sql_token=; Max-Age=0`

### `GET /api/auth/me`（登录）

**功能**：回显 `AuthMiddleware` 注入的 `request.state.user`，供前端 `AuthGuard` 判定登录态与首登改密提示；`NL2SQL_AUTH_DISABLED=1` 时直接返回 dev 身份。

**实现逻辑**：`NL2SQL_AUTH_DISABLED` 短路 dev → 读 `request.state.user` → `_user_payload` 四字段

**入参**：无（身份取自 Cookie 或 `Authorization`）

**出参**

```json
{"user_id": "string", "display_name": "string", "is_admin": true, "must_change_password": false}
```

`NL2SQL_AUTH_DISABLED=1` 时固定返回 `{"user_id":"dev","display_name":"Dev User","is_admin":true,...}`。
**错误**：`401 {"error":"unauthorized"}`

### `POST /api/auth/change-password`（登录）

**功能**：校验旧口令→写新哈希（线程池）→`token_version`+1 使该账号全部旧 token 立即失效→**为当前会话换发新 Cookie**（否则改完密会把自己踢下线）。

**实现逻辑**：取 `state.user`（排除 internal）→ `parse_body` → `change_password`（线程池：验旧密+哈希+`token_version`+1+原子写盘）→ `find_user` 取新 record → `sign_token` 换发 Cookie

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `old_password` | 是 | 旧口令 |
| `new_password` | 是 | 新口令（长度等规则见 `agent.auth.users.change_password`） |

**出参** `{"ok": true, "must_change_password": false}` + **换发新 Cookie**
（`token_version` +1，该账号所有旧 token 立即失效）

**错误**：`400 {"error":"old_password and new_password required"}`、
`400 {"error":"<旧密码错 / 新密码不合规>"}`、`401 {"error":"unauthorized"}`

## B. 用户与授权管理（全部 `require_admin`）

### `GET /api/auth/users/auth-list`

**功能**：读 `auth_users.json` 并剔除 `password_hash`，返回含 `is_admin` / `token_version` 的账号清单。

**实现逻辑**：`load_users()`（线程池读盘解析）→ 逐个剔除 `password_hash`

**入参**：无

**出参**

```json
{"users": [{"user_id":"u1","display_name":"张三","is_admin":false,
            "token_version":0,"must_change_password":false}]}
```

（`password_hash` 已剔除）

### `POST /api/auth/users`

**功能**：新增登录账号：PBKDF2 哈希口令后原子写回 `auth_users.json`（整段走线程池，避免百毫秒级 CPU 占住事件循环）。

**实现逻辑**：校验 user_id/password → `add_user`（线程池：PBKDF2+原子写盘）→ 201

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `user_id` | 是 | 登录名 |
| `password` | 是 | 初始口令 |
| `display_name` | 否 | 显示名 |
| `is_admin` | 否 | 默认 false |

**出参** `201 {"ok":true,"user":{"user_id":"...","display_name":"...","is_admin":false,...}}`

**错误**：`400 {"error":"user_id 必填" | "password 必填" | <ValueError>}`

### `PUT /api/auth/users/{uid}`

**功能**：按传入字段增量更新账号；改密会递增 `token_version`（旧 token 立即失效），并保留未传字段原值。

**实现逻辑**：四字段至少一个 → `update_user`（线程池；改密递增 `token_version`）→ 回 user

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `uid` | 是 | 目标用户 |
| body | `password` | 否 | 改密（会使旧 token 失效） |
| body | `display_name` | 否 | 显示名 |
| body | `is_admin` | 否 | 管理员标记 |
| body | `must_change_password` | 否 | 首登改密标记 |

四个 body 字段至少传一个，否则 `400 {"error":"至少传一个字段"}`。

**出参** `{"ok":true,"user":{...}}`

### `DELETE /api/auth/users/{uid}`

**功能**：从 `auth_users.json` 删除账号（先拦「删除自己」）；删除后该账号旧 token 因找不到用户而失效。

**实现逻辑**：`get_user` 防自删 → `remove_user`（线程池写盘）

**入参**：path `uid`

**出参** `{"ok":true,"user_id":"..."}`

**错误**：`400 {"error":"不能删除自己"}`、`400 {"error":"<ValueError>"}`

### `POST /api/auth/users/{uid}/revoke`

**功能**：`token_version`+1 并落盘，使该账号此前签发的所有 token 立即失效——怀疑口令外泄 / 设备丢失时不必改密即可踢下线。

**实现逻辑**：`revoke_tokens(uid)`（线程池：`token_version`+1 落盘）→ 回新版本号

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `uid` | 是 | 目标用户 |
| body | `reason` | 否 | 只记日志 |

**出参** `{"ok":true,"user_id":"...","token_version":1}`

副作用：目标用户被踢回登录页，用原密码重新登录。

### `POST /api/auth/users/reload`

**功能**：重新读盘并解析 `auth_users.json`，让管理员手工编辑的用户文件免重启生效。

**实现逻辑**：`reload_users()`（线程池读盘解析）→ `{ok, count}`

**入参**：无

**出参** `{"ok":true,"count":3}`（重载后的用户数）

### `GET /api/auth/users`

**功能**：读 grants 库的 `users` 表（登录时幂等登记出来的账号），返回来源 / 状态 / 最近活跃时间。

**实现逻辑**：线程池内 `_get_conn()` → `SELECT ... FROM users ORDER BY last_seen_at DESC`

**入参**：无

**出参**

```json
{"users": [{"user_id":"...","display_name":"...","source":"...","status":"...","last_seen_at":"ISO"}]}
```

### `GET /api/auth/users/{uid}/grants`

**功能**：读 grants 表，列出该用户的库级授权（`query` / `admin`）。

**实现逻辑**：`list_user_grants(uid)`（线程池 sqlite 读）

**入参**：path `uid`

**出参** `{"user_id":"u1","grants":[{"db_name":"imdb","level":"query",...}]}`

### `POST /api/auth/users/{uid}/grants`

**功能**：向 grants 表写入一条库授权；下游 `can_access_db` / `visible_dbs` 都读这张表。

**实现逻辑**：`parse_body` → `level ∈ {query,admin}` 校验 → `grant_db()`（线程池写入）

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `uid` | 是 | 目标用户 |
| body | `db_name` | 是 | 数据库名 |
| body | `level` | 否 | `query`（默认）/ `admin` |

**出参** `{"ok":true,"user_id":"u1","db_name":"imdb","level":"query"}`

**错误**：`400 {"error":"db_name 必填" | "level 必须是 query 或 admin"}`

### `DELETE /api/auth/users/{uid}/grants/{db}`

**功能**：删除 grants 表中该用户对该库的授权记录，下次请求即按新授权过滤。

**实现逻辑**：`revoke_db()`（线程池写入）→ 回 `user_id/db_name`

**入参**：path `uid`、`db`

**出参** `{"ok":true,"user_id":"u1","db_name":"imdb"}`

## C. 数据库连接与 MCP（`db_config.py`）

### `GET /api/db-configs`（登录）

**功能**：按 `visible_dbs(user)` 过滤后返回加密存储的库配置（密码脱敏），并用 `SemanticDbDetector` 标注该库是否已建模（决定前端是否暴露语义层能力）。

**实现逻辑**：`visible_dbs(user)` → `list_configs(masked=True)` 过滤 → `_masked_with_semantic`（`is_modeled`）

**入参**：无（按 `visible_dbs(user)` 过滤）

**出参**

```json
{"databases": [{"name":"imdb","db_type":"mysql","host":"...","port":3306,
                "user":"...","database":"imdb","password":"******",
                "wren_project":"/abs/path","is_default":false,"semantic":true}]}
```

`semantic` = 该库是否已建模（命中 `SemanticDbDetector`）。

### `POST /api/db-configs`（管理员）

**功能**：校验并加密落盘库配置（`is_default` 缺省保留原值，避免老客户端静默清掉默认库），失效一组发现类缓存，并**同步**把该库的 wrenai MCP 工具装进运行期注册表（免重启），把加载结果回给前端。

**实现逻辑**：`DBConfig.from_mapping` → 缺 `is_default` 回填库里原值 → `upsert`（加密落盘）→ `invalidate_db_discovery_caches` → `_ensure_mcp_tools`（`to_thread(ensure_sub_loaded)`）

**入参**（`DBConfig` 字段）

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 库标识（前端下拉、工具前缀都用它） |
| `db_type` | 是 | `mysql` / `clickhouse` / `postgres` / `sqlite` |
| `host` / `port` | 是（sqlite 可空） | 连接地址 |
| `user` / `password` | 是（sqlite 可空） | 凭据（存储时加密） |
| `database` | 否 | 库名（sqlite 为文件路径） |
| `wren_project` | 否 | 关联语义库目录 |
| `is_default` | 否 | **缺省 = 保留库里原值**，显式 `false` 才取消默认 |

**出参**

```json
{"ok": true, "name": "imdb",
 "mcp": {"db_name":"imdb","status":"ok","loaded":12,"error":""}}
```

**错误**：`400 {"error":"name 必填" | "<校验信息>"}`、`500 {"error":"保存失败: ..."}`

### `GET /api/db-configs/{name}`（登录 + 库权）

**功能**：先做库级授权校验，再返回单条脱敏配置（`password` 打码）并附 `semantic` 标记。

**实现逻辑**：`can_access_db` → `get_store().get`（KeyError→404）→ `to_mapping(masked=True)` + semantic

**入参**：path `name`

**出参**：单条 `DBConfig`（脱敏）+ `semantic` 标记
`{"name":"imdb","db_type":"mysql","password":"******","semantic":true,...}`

**错误**：`403 {"error":"无权访问数据库: imdb"}`、`404 {"error":"数据库 'imdb' 不存在"}`

### `DELETE /api/db-configs/{name}`（管理员）

**功能**：删除配置、失效发现类缓存，并把该库的 MCP 工具从运行期注册表摘除；历史消息里的存量调用由 `DynamicMCPToolsMiddleware` 返回错误而不会执行陈旧实例。

**实现逻辑**：`delete` → 失效发现缓存 → `invalidate_sub_entries(name)` 摘 MCP 工具

**入参**：path `name`

**出参** `{"ok":true,"name":"imdb","mcp":{"removed_servers":["wrenai_imdb"]}}`

**错误**：`404 {"error":"数据库 'imdb' 不存在"}`

### `POST /api/db-configs/{name}/test`（管理员）

**功能**：按 `db_type` 选驱动**直连**验证（MySQL/PG 跑 `SELECT 1`、ClickHouse `query("SELECT 1")`、SQLite 校文件存在、其余仅探 TCP），3s 超时；支持测请求体（保存前校验）与测已存配置，走长任务池。

**实现逻辑**：body 有则 `from_mapping`，否则 `get_store().get` → `offload_long(_test_connection)`（驱动直连 3s）

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `name` | 是 | 数据库名 |
| body | `DBConfig` 字段 | 否 | **带 body** → 用请求体测试（保存前校验，可带明文密码）；**不带** → 测试已保存配置 |

**出参** `200 {"ok":true,"message":"mysql 连接成功"}` /
`400 {"ok":false,"message":"mysql 连接失败: ..."}`

**错误**：`404 {"error":"数据库 'imdb' 不存在"}`；3 秒超时直连。

### `GET /api/mcp/status`（管理员）

**功能**：导出运行期 MCP 工具注册表快照（已加载的 server / 库名 / 工具数 / 失败原因），是排查「某库工具没起来」的直接抓手。

**实现逻辑**：`require_admin` → `get_mcp_status()` → 原样返回

**入参**：无

**出参**：运行期 MCP 注册表快照（`get_mcp_status()` 原样返回：已加载的 server、库名、工具数与失败原因）

### `POST /api/mcp/reload`（管理员）

**功能**：失效发现类缓存后**全量对账**运行期注册表：新增 / 变更 / **重试上次失败** / 摘除已删库，免重启生效（也是「某库工具一直没起来」的恢复手段）。

**实现逻辑**：失效发现缓存 → `asyncio.to_thread(refresh_sub_entries)` → `{ok, ...对账结果}`

**入参**：无

**出参** `{"ok":true,"added":[...],"changed":[...],"retried":[...],"removed":[...],"loaded":{...},"counts":{...}}`

**错误**：`500 {"ok":false,"error":"..."}`

### `GET /healthz`（登录 / 容器内网）

**功能**：进程存活探针，不做任何依赖检查，恒定返回 `ok`。

**实现逻辑**：常量返回 `{ok:true, service:"db-config-api"}`

**入参**：无

**出参** `{"ok":true,"service":"db-config-api"}`

> handler 不校验身份，但不在 `AuthMiddleware` 白名单 ⇒ 外部请求需登录，
> 容器内网自调用（无 Cookie、无 XFF）直通——docker healthcheck 走这条。

## D. 模型 provider（`model_config.py`，按用户隔离的 store）

### `GET /api/model-configs`

**功能**：读**当前用户独立**的 provider store（脱敏）并返回 active；对未配容量的模型按静态表自动推断 `context_window` / `max_tokens`（用户显式值不动）。

**实现逻辑**：`get_user_store(user_id)` → `list_configs(masked)` → `_enrich_models_with_context_window`（`resolve_*` 推断）→ 附 `active`

**入参**：无

**出参**

```json
{"providers": [{"name":"deepseek","base_url":"https://...","api_key":"******",
                "models":[{"id":"deepseek-v4","context_window":128000,"max_tokens":8192}],
                "default_model":"deepseek-v4","display_name":"DeepSeek",
                "api_protocol":"openai"}],
 "active": "deepseek"}
```

### `POST /api/model-configs`

**功能**：归一 `models`（支持对象列表或逗号串）、`api_key` 空串时**保留原值**，写入该用户 store；存储侧加密。

**实现逻辑**：`parse_body` → `models` 归一（str→list）→ `ModelConfig(...)`（`__post_init__` 再归一）→ `upsert`

**入参**

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | provider 名（激活键） |
| `base_url` | 是 | OpenAI 兼容网关根地址 |
| `api_key` | 否 | **空串 = 保留原值** |
| `models` | 否 | `[{id,...}]` 或逗号分隔字符串 |
| `default_model` / `display_name` | 否 | 默认模型 / 展示名 |
| `api_protocol` | 否 | `anthropic` 时用 `x-api-key` 认证 |

**出参** `{"ok":true,"name":"deepseek"}`

**错误**：`400 {"error":"name 必填" | "<ValueError>"}`、`500 {"error":"保存失败: ..."}`

### `GET /api/model-configs/{name}`

**功能**：返回单条 provider（脱敏）+ `active` 标记，并补齐模型容量后回给前端。

**实现逻辑**：`store.get`（KeyError→404）→ `to_mapping(masked)` → 附 `active` → 补容量

**入参**：path `name`

**出参**：provider 详情（脱敏）+ `"active": bool` + 补齐后的 `models`

**错误**：`404 {"error":"模型配置 'deepseek' 不存在"}`

### `DELETE /api/model-configs/{name}`

**功能**：从该用户 store 删除 provider；删除不存在的配置返回 404。

**实现逻辑**：`store.delete()` 返回 False → 404

**入参**：path `name`

**出参** `{"ok":true,"name":"deepseek"}`

**错误**：`404 {"error":"模型配置 'deepseek' 不存在"}`

### `POST /api/model-configs/{name}/activate`

**功能**：把该 provider 设为该用户的**激活项**，后续 `create_model` 与 run 级路由都以它为准；不存在则 404。

**实现逻辑**：`store.set_active(name)`（KeyError→404）

**入参**：path `name`

**出参** `{"ok":true,"active":"deepseek"}`

**错误**：`404 {"error":"..."}`

### `POST /api/model-configs/test`

**功能**：过 `net_guard` 出站守卫后 `GET {base_url}/v1/models`（非 JSON/网络错回退 `/models`）探活并回传模型 id 列表；`api_protocol=anthropic` 用 `x-api-key` 且不列模型（网关无该端点）。

**实现逻辑**：缺 base_url 且有 name → 读存储配置 → `_ssrf_reject` → `offload_long(_probe_models)`（`/v1/models`→`/models`；anthropic 用 `x-api-key`）

**入参**

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 二选一 | 有 `name` 且无 `base_url` → 用已存储配置 |
| `base_url` | 二选一 | 直接探活（保存前测试） |
| `api_key` | 否 | 配合 base_url 使用 |
| `api_protocol` | 否 | `anthropic` |

**出参** `200 {"ok":true,"message":"连接成功（2 个模型）","models":["deepseek-v4","deepseek-flash"]}`
失败 `400 {"ok":false,"message":"连接失败: ...","models":[]}`

**错误**：`400 {"error":"base_url 必填"}`、`400 {"ok":false,"message":"<被出站守卫拒绝>","models":[]}`

### `POST /api/model-configs/probe-capabilities`

**功能**：列表探测（兼容多种字段别名）+ 单模型 `GET /models/{id}` 兜底，提取 `context_window` / `max_tokens` 并标注来源（`probe` / `static` / `none`），供前端「刷新真实容量」回填。

**实现逻辑**：`models` 归一 → 补存储配置 → `_ssrf_reject` → `offload_long(_probe_all)`（列表探测 + 单查兜底 + `resolve_*` 回退）

**入参**

| 字段 | 必填 | 说明 |
|---|---|---|
| `models` | 是 | 要探测的模型 id 列表（或逗号串） |
| `name` / `base_url` / `api_key` / `api_protocol` | 否 | 同 `test` |

**出参**

```json
{"ok": true, "message": "已探测 2 个模型",
 "models": [{"id":"deepseek-v4","context_window":128000,"max_tokens":8192,
```

## E. 部署信息与评估开关

### `GET /api/deployment-info`（登录）

**功能**：读 `langgraph.json` 的 `graphs` 选主入口图名作为默认 `assistant_id`（读不到回退常量 `chat_agent`），让前端首屏零配置进聊天页。

**实现逻辑**：`_graph_ids()` 读 `langgraph.json`（异常 fail-open→[]）→ 命中 `chat_agent` 否则取首个 → 标 `source`

**入参**：无

**出参**

```json
{"ok": true, "assistant_id": "chat_agent", "graph_ids": ["chat_agent"], "source": "langgraph.json|fallback"}
```

### `GET | PUT | DELETE /api/eval-flags`（管理员）

**功能**：读 / 增量改 / 清空在线评估开关的**覆盖层**（落盘 JSON，评估器读时求值 ⇒ 即改即生效、无需重启）；每次变更记 WARNING 审计（来源 IP + 生效值前后差异）。

**实现逻辑**：GET：`snapshot()+overrides()+path()`；PUT：`parse_body`→取 `flags`（容忍扁平）→`patch_overrides`（线程池落盘）→`_audit`；DELETE：`clear_overrides`→`_audit`

**入参**

| 方法 | 入参 |
|---|---|
| GET | 无 |
| PUT | body `{"flags": {"<开关名>": <值>}}`（也容忍扁平 `{"<开关名>": <值>}`）；值传空串 = 删除该键覆盖 |
| DELETE | 无 |

**出参**（三种方法相同）

```json
{"ok": true,
 "flags": {"NL2SQL_EVAL_ENABLED": {"value": true, "source": "env|override|default"}},
 "overrides": {"NL2SQL_EVAL_ENABLED": true},
 "file": "<AGENT_DATA_ROOT>/shared/eval_flags.json"}
```

**错误**：`400 {"ok":false,"error":"body 需为 {\"flags\": {<开关名>: <值>}}" | <ValueError>}`、
`500 {"ok":false,"error":"写入失败: ..."}`
