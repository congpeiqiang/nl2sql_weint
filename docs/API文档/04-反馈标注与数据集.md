# 04 · 反馈、标注与数据集 API

> 源文件：`message_feedback.py`、`feedback_stats.py`、`feedback_annotation.py`
> 数据源：本地 `FeedbackStore`（SQLite，唯一真相）+ Langfuse 数据集（badcase / goodcase）

## A. 消息反馈

### `PUT /api/threads/{thread_id}/messages/{message_id}/feedback`（归属）

**功能**：`if_version` CAS 校验后写入反馈行（首次只落 rating/note）；后台异步补 `question`/`sql`/`cube_spec` 快照、入待标注队列、转发 Langfuse score，SQL 非空时快路径直标 `query`。

**实现逻辑**：`require_thread` → `parse_body` → `_validate(rating,note)` + `_if_version` → 线程池 `store.get + store.upsert`（CAS）→ 首次写入 `_schedule_snapshot_backfill` → SQL 非空 `set_feedback_type("query")` → `enqueue_annotation` → 评分/备注变更时 `_schedule_langfuse_score`

**入参**：path `thread_id`、`message_id`；body 见下表

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `rating` | string | 是 | `positive` / `negative` |
| `note` | string | 否 | 备注，≤ 2KB（UTF-8 字节） |
| `if_version` | int | 否 | CAS 版本；不匹配 → `409` |
| `context` | object | 否 | 仅首次写入时快照，如 `{"db_name":"imdb"}` |

**出参**

```json
{"ok": true, "feedback": {"thread_id":"...","message_id":"...","rating":"positive",
  "note":"","version":1,"question":"...","sql":"...","cube_spec":{},
  "feedback_type":"query|chat|","context":{"db_name":"imdb"},"updated_at":"ISO"}}
```

副作用（后台异步，不阻塞返回）：

1. 首次写入 → 后台补 `question` / `sql` / `cube_spec` 快照（Cube 通道按定义复算物理 SQL）
2. 入待标注队列（幂等）
3. 转发 Langfuse user-feedback score（首次写入 / 评分变化 / note 变化时）

**错误**：`400 {"error":"<rating/note 校验>"}`、`401/403`、
`409 {"error":"<版本冲突>"}`、`500 {"error":"保存失败: ..."}`

### `DELETE /api/threads/{tid}/messages/{mid}/feedback`（归属）

**功能**：删除反馈行并按固定顺序级联：收回因该 👍 自动入集的 Good Set → 非终态标注回滚 `rejected` → 排队 Langfuse 撤销哨兵（v4 无 score 删除 API）。

**实现逻辑**：`require_thread` → `_if_version` → 线程池 `purge_feedback`（删行 → `withdraw_auto_good` → `revoke_annotations_for_message` → `_schedule_langfuse_revoke`）→ 未删到→404

**入参**：path `thread_id`、`message_id`；body 可选 `{"if_version": N}`。

**出参** `{"ok":true}`

级联（**顺序固定不可调换**）：

1. 收回因该 👍 而自动入集的 Good Set 条目（人工确认过的不动）
2. 该消息非终态标注回滚为 `rejected`（不打扰已确认工作）
3. 排队 Langfuse 撤销哨兵（v4 无 score 删除 API，用哨兵分表达软删除）

**错误**：`404 {"error":"反馈不存在"}`、`409`、`400`（if_version 非法）

### `GET /api/threads/{thread_id}/feedback`（归属）

**功能**：读该会话全部反馈记录，供前端回显已点过的赞/踩与备注。

**实现逻辑**：`require_thread` → `offload(store.list_thread)` → `to_mapping`

**入参**：path `thread_id`（无 body / query）

**出参** `{"feedback":[<同 feedback 对象>]}`

### `GET /api/feedback/export`（管理员）

**功能**：全表导出反馈（含 👍 正例与 question/SQL 快照），供 badcase 评测集回流。

**实现逻辑**：`require_admin` → `offload(store.export_all)` → 组装 `count + feedback`

**入参**：无

**出参** `{"count":N,"feedback":[<feedback 对象>]}`（含 👍 正例，供评测集回流）

## B. 反馈看板

### `GET /api/feedback/stats?days=7`（管理员）

**功能**：按窗口聚合总数/正负/好评率，再按 `query`/`chat`/`unknown` 分组算信噪比与每日趋势；`feedback_type` 空值惰性判定（LRU 缓存），失败归 `unknown`。

**实现逻辑**：`require_admin` → days clamp → `records_in_window` → 逐条 `feedback_type or _classify_empty` → `_bucket()` 分组 + `trend` 按本地日切 → `signal_noise_ratio`

**入参**：query `days`（默认 7，范围 1~365）

**出参**

```json
{"days": 7, "total": 120,
 "count": 120, "positive": 90, "negative": 30, "positive_rate": 0.75,
 "query":   {"count":100,"positive":80,"negative":20,"positive_rate":0.8},
 "chat":    {"count":15,"positive":10,"negative":5,"positive_rate":0.6667},
 "unknown": {"count":5,"positive":0,"negative":5,"positive_rate":0.0},
 "signal_noise_ratio": 6.67,
 "trend": [{"date":"2026-10-27","total":20,"positive":15,"negative":5,"query":18,"chat":2}]}
```

- `signal_noise_ratio` = query 数 / chat 数（chat=0 → `null`，前端显示 ∞/N/A）
- `feedback_type` 为空（存量/未判定）的记录**惰性判定**（LRU 缓存），失败保持 `unknown` 单独归组
- 数据来自本地 SQLite，Langfuse 不可达不影响看板

## C. 待标注队列（全部 `require_admin`）

状态机：

```
queued ──is_valid=1──→ annotating ──execute 校验──→ validated ──confirm-good──→ good（终态）
   └────is_valid=0────→ rejected                    └──confirm──→ badcase（终态）
```

### `GET /api/feedback/annotations?status=&limit=`

**功能**：按状态读本地标注队列（limit≤200），并用反馈快照**同步补齐** `question`/`bad_sql`/`cube_spec`（无网络读取）。

**实现逻辑**：`require_admin` → status 白名单 + limit clamp 50/200 → `offload(_load)`（`list_annotations` + `_fill_annotation_from_snapshot`）→ `to_mapping`

**入参**（query）

| 参数 | 说明 |
|---|---|
| `status` | 可选：`queued` / `annotating` / `validated` / `badcase` / `good` / `rejected` |
| `limit` | 可选，默认 50，上限 200 |

**出参**

```json
{"count": 1, "annotations": [{"thread_id":"...","message_id":"...","status":"queued",
  "question":"...","bad_sql":"...","gold_sql":"","bad_type":"","note":"",
  "cube_spec":{},"db_name":"imdb","rating":"negative","feedback_type":"query",
  "is_valid":0,"exec_error":"","annotator":"","annotated_at":"","badcase_at":"",
  "auto_good":0,"updated_at":"ISO"}]}
```

列表会从本地反馈快照**同步补齐** `question` / `bad_sql` / `cube_spec`（无网络读取）。

**错误**：`400 {"error":"status 必须是 [...] 之一"}`

### `GET /api/feedback/annotations/bad-types`

**功能**：把 `BAD_TYPES` 三元组（key/label/desc）直接回给前端，作为错误类型下拉与 `confirm` 的校验依据。

**实现逻辑**：`require_admin` → 直接映射 `BAD_TYPES` 三元组

**入参**：无

**出参** `{"bad_types":[{"key":"...","label":"...","desc":"..."}]}`
（枚举来源 `agent.eval.bad_types.BAD_TYPES`，供前端下拉）

### `GET /api/feedback/datasets?name=badcase|goodcase&limit=`

**功能**：直读 Langfuse 数据集一页条目（≤100），把 `input`/`expected_output`/`metadata` 统一成展示行，并算出 `has_gold`（是否有权威金标）。

**实现逻辑**：`require_admin` → `name` 白名单 → limit clamp 100 → `offload_long(_fetch)`（`dataset_items.list`）→ `_dataset_item_to_row` 归一 + 算 `has_gold`

**入参**（query）

| 参数 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 只接受 `badcase` / `goodcase` |
| `limit` | 否 | 默认 100，上限 100（v4 `dataset_items.list` 硬上限） |

**出参**

```json
{"dataset": "badcase", "count": 1,
 "items": [{"item_id":"...","question":"...","session_id":"<thread_id>",
   "message_id":"...","sql":"<expected_output.sql>","has_gold":true,
   "cube_spec":"<JSON 串>","physical_sql_original":"<模型实际下发>","note":"",
   "source":"user-annotation|auto-collect","db_name":"imdb","trace_id":"...",
   "bad_type":"...","rating":"...","reasons":["..."],
   "created_at":"ISO","collected_at":"YYYY-MM-DD"}]}
```

取值遵循字段契约的权威顺序：`sql` 只认 `expected_output.sql`；
`cube` 认 `expected_output.cube`，缺席才退 `metadata.cube_spec`；
不读 `metadata.gold_sql` / `good_sql`（与 `expected_output.sql` 同值，是给人看的镜像）。

**错误**：`400 {"error":"name 必须是 badcase 或 goodcase"}`
Langfuse 关闭 → `{"dataset":"badcase","count":0,"items":[]}`；读取失败 → 同形 + `error` 字段（不 500）。

### `GET /api/feedback/dataset-stats`

**功能**：分页拉全量数据集算规模/有无金标/来源分布（60s 进程内缓存），队列深度直读本地 SQLite——把「`without_gold` 金标缺口」显式暴露出来。

**实现逻辑**：`require_admin` → 本地 `count_annotations` → `_dataset_stats_cached`（分页拉全量 ≤2000 条，60s 缓存）→ `_summarize_dataset`；Langfuse 关闭→`disabled`

**入参**：无

**出参**

```json
{"queue": {"queued":12,"annotating":3,"validated":4,"badcase":8,"good":20,"rejected":5},
 "badcase":  {"total":120,"with_gold":90,"without_gold":30,"by_source":{"auto-collect":70,"user-annotation":50}},
 "goodcase": {"total":60,"with_gold":60,"without_gold":0,"by_source":{"auto-good":20,"user-annotation":40}},
 "disabled": false, "error": ""}
```

- `without_gold` = 该数据集里**没有权威金标**（`expected_output.sql` 为空）的条目数
- 数据集统计分页拉全量（上限 20 页 × 100 = 2000 条），有 60s 进程内缓存；队列深度直读本地 SQLite
- Langfuse 关闭 → `disabled=true`；读取失败带 `error`（不 500）

### `POST /api/feedback/annotations/clear`

**功能**：按可删状态白名单逐行 CAS 删除条目与用户反馈，并为真删反馈的行批量排队撤销哨兵（单批上限 500，超出部分如实报 `capped`/`remaining`）。

**实现逻辑**：`require_admin` → `_deletable_error(status)` → `list_annotations(cap 500)` → 逐行 `purge_feedback(revoke=False)` + `delete_annotation(status)`（CAS）→ `_schedule_langfuse_revoke_many` → 汇总 `capped/remaining`

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `status` | 是 | 只接受**可删状态**白名单：`queued` / `annotating` / `validated` / `rejected` |

`good` / `badcase` 一律拒绝（它们有 Langfuse 数据集条目或 BadCase 标记）。

**出参**

```json
{"ok": true, "status": "queued", "deleted": 120, "feedback_deleted": 118,
 "skipped": 2, "remaining": 0, "scores_queued": 118, "capped": false}
```

- `skipped` = CAS 未命中（循环期间该行变成终态）
- `capped=true` 表示超过单批上限 500 条未全清，`remaining` 是真实剩余
- 逐行按 `status` 条件删，避免把刚变成 `badcase` 的行误删成孤儿

**错误**：`400 {"error":"status 必填，且必须是 [...] 之一" | "状态 X 不可删除：..."}`

### `GET /api/feedback/annotations/{thread_id}/{message_id}`

**功能**：惰性补齐 `question`/`bad_sql`/`cube_spec`（先本地快照、再读线程 state 提取），并**只读回显**模型原口径 `cube_original`（不落库、不入数据集）。

**实现逻辑**：`require_admin` → `_backfill_annotation`（本地快照 → 线程 state）→ 附 `cube_original`（`_model_cube`）

**入参**：path `thread_id`、`message_id`

**出参**

```json
{"annotation": {"thread_id":"...","message_id":"...","status":"annotating",
  "question":"...","bad_sql":"...","gold_sql":"...","bad_type":"","note":"",
  "cube_spec":{},"cube_spec_readable":"...","db_name":"imdb",
  "rating":"negative","feedback_type":"query","is_valid":1,"exec_error":"",
  "annotator":"","annotated_at":"","badcase_at":"","auto_good":0,
  "cube_original":{},"updated_at":"ISO"}}
```

- 惰性补齐 `question` / `bad_sql` / `cube_spec`：先本地反馈快照，再读线程 state
- `cube_original` 是**只读回显**的「模型原口径」（不落库、不入数据集）；
  `cube_spec` 可能已被「按新口径试算」改写，两者不同 = 人工改过口径

**错误**：`404 {"error":"标注不存在"}`

### `DELETE /api/feedback/annotations/{thread_id}/{message_id}`

**功能**：先删用户反馈（含自动入集收回与撤销哨兵）再 CAS 删标注行，避免留下一颗「看得见却修不了的赞」；CAS 未命中时如实回报已删/未删。

**实现逻辑**：`require_admin` → 读 ann → `_deletable_error` → `expected_status` CAS 校验 → `purge_feedback(revoke=False)` → `delete_annotation(expected)` → 未命中则回报「反馈已删、条目未删」

**入参**：path `thread_id`、`message_id`；body（可选）`{"expected_status": "queued"}` —— 客户端看到的状态，用于 CAS（缺省用本次读到的状态）。

删除一条**本地队列条目 + 它的用户反馈**（硬删，无墓碑）。

**出参**

```json
{"ok": true, "deleted": {"annotation": true, "feedback": true}}
```

**错误**：

- `404 {"error":"标注不存在"}`
- `409 {"error":"状态 X 不可删除：它有 Langfuse 数据集条目或 BadCase 标记，请用对应的撤回 / 移出操作"}`
- `400`（`expected_status` 不在可删白名单）
- `409 {"ok":false,"deleted":{"annotation":false,"feedback":true},"error":"条目状态已变化（可能刚被确认入集），未删除；用户反馈已移除"}`

> 顺序：**先删反馈、后删标注行** —— 反过来的话一旦失败会留下「聊天里一个活的 👍/👎 + 一条不存在的队列行」，那个赞从此既看不见也修不了。

### `POST …/{tid}/{mid}/judge`

**功能**：写 `is_valid`/`annotator` 推进到 `annotating` 或 `rejected`；`direct_good` 时校验「点赞 + SQL 非空」后跳过修正/执行**直入 Good Set**。

**实现逻辑**：`require_admin` → `is_valid` 布尔校验 → 读 ann（终态 409）→ `direct_good` 分支校验点赞+SQL → `_confirm_good_commit`；否则 `update_annotation(status=annotating|rejected)`

**入参**：path `tid`、`mid`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `is_valid` | 是 | 必须是 bool；true → `annotating`，false → `rejected` |
| `annotator` | 否 | 标注人（≤64 字） |
| `direct_good` | 否 | 点赞正例直达：true 时要求 `is_valid=true` 且 `rating=positive`，跳过修正/执行直接入 Good Set |

**出参** `{"ok":true,"annotation":{...}}`；`direct_good` 直达时额外 `"good": true`

**错误**：
`400 {"error":"is_valid 必须是布尔值"}`、
`400 {"error":"direct_good 需要 is_valid=true" | "直接入 Good Set 仅限点赞反馈"}`、
`400 {"error":"本条回答没有 SQL（如纯文本回答/澄清/闲聊），无法直接入 Good Set。...","reason":"no_sql"}`、
`404 {"error":"标注不存在"}`、`409 {"error":"状态 X 不可再判断" | "状态更新失败"}`

### `POST …/{tid}/{mid}/execute`

**功能**：只读硬校验（`classify_sql`）→ 已建模库经 Wren `dry_plan` 展开成物理 SQL → dbmcp 引擎执行预览（≤100 行）；成功把标注员 SQL 写成 `bad_sql` 并推进 `validated`，失败记 `exec_error`。

**实现逻辑**：`require_admin` → 读 ann → `db_name` 库权 → `_to_physical_sql`（Wren dry_plan）→ `_run_preview`（`classify_sql` + dbmcp 引擎，≤100 行）→ 写 `bad_sql` + 推进 `validated`；失败写 `exec_error`

**入参**：path `tid`、`mid`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `sql` | 是 | 待校验 SQL（已建模库会先经 Wren `dry_plan` 展开为物理 SQL） |
| `db_name` | 否 | 缺省用标注记录上的库 |

**出参**

```json
{"ok": true,
 "result": {"columns":["..."],"rows":[[...]],"row_count":12,"truncated":false,
            "...": "其余字段由 combine_multi_results 产出"},
 "expanded": true, "executed_sql": "<展开后的物理 SQL；未改写时为空串>"}
```

行为：成功 → `bad_sql` 更新为标注员写的这条，且状态从 `queued`/`annotating` 推进到 `validated`；
失败记 `exec_error`（不推进状态）。

**错误**：`400 {"error":"sql 不能为空"}`、
`403 {"error":"无权访问数据库: X"}`、
`400 {"error":"仅允许只读查询（检测到 写/DDL 操作，已拒绝执行）"}`、
`400 {"error":"执行失败: ...（已建模库展开失败时附原因）"}`、`404`

### `POST …/{tid}/{mid}/preview-cube`

**功能**：校验并规范化 `cube_spec` → 用 `plan_cube_sql_checked` 编译出**真正会下发的 SQL**（含连接器 LIMIT）→ 执行预览；只把口径落库，**不推进状态机**。

**实现逻辑**：`require_admin` → 读 ann → `_parse_cube_spec`（结构/键名/边界三层）→ 库权 → `resolve_wren_ctx_by_db` → `plan_cube_sql_checked` → `_run_preview` → 只落 `cube_spec`

**入参**：path `tid`、`mid`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `cube_spec` | 是 | 规范化查询定义，**对象或 JSON 字符串**均可 |
| `db_name` | 否 | 缺省用标注记录上的库 |

**出参**

```json
{"ok": true, "spec": {"cube":"...","measures":["..."],"dimensions":["..."],"filters":[],"time_dimension":""},
 "cube_spec_readable": "按「度量/维度」拼的人读文本", "physical_sql": "<编译后的方言 SQL>",
 "cube_sql": "<wren 语义 SQL>", "dialect": "mysql",
 "result": {"columns":[...],"rows":[...],"row_count":100,"truncated":true}}
```

副作用**只有**：把试算过的口径落库（`cube_spec`），**不推进状态机、不写 `gold_sql`**。

**错误**：
`400 {"error":"查询定义不能为空" | "查询定义不是合法 JSON（...）" | "查询定义必须是对象（...）"}`、
`400 {"error":"查询定义含未知字段 [...]; 可用字段: [...]"}`、
`400 {"error":"查询定义不要写 limit/offset：线上由平台在工具边界剥离、改结果集截窗，试算与线上必须同一条路"}`、
`400 {"error":"库 X 不是已建模库（无 wren 语义层项目），无法试算口径"}`、
`400 {"error":"口径编译失败：..." | "口径试算执行失败: ..."}`、`403`、`404`

> `granularity` / `segments` / `order_by` 也一律拒绝：`query_cube` 根本不收，
> 真收这几个键会**静默不生效**，比报错更坏。

### `POST …/{tid}/{mid}/confirm`

**功能**：先**真跑一遍金标 SQL** 校验（已建模库先展开），通过后写三处：Langfuse `badcase` 数据集、`badcase_status.json`（进回归集）、本地终态 `badcase`。

**实现逻辑**：`require_admin` → 校验 gold_sql/bad_type → 读 ann（终态/点赞 409）→ `_to_physical_sql` + `_run_preview` 验金标 → `_find_trace_with_retry` → `_write_dataset_item`（badcase）→ `badcase_status.annotate()` → `update_annotation(status=badcase)`

**入参**：path `tid`、`mid`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `gold_sql` | 是 | 人工确认的金标 SQL（会**真实执行一遍**校验） |
| `bad_type` | 是 | 错误类型（见 bad-types，非法值会被拒绝） |
| `db_name` | 否 | 缺省用标注记录上的库 |
| `note` | 否 | 备注（缺省沿用反馈里的评论） |
| `annotator` | 否 | 标注人 |

写三处：① Langfuse `Dataset:badcase`（`expected_output.{sql,cube}` + metadata 镜像）
② `badcase_status.json`（`reviewed` + `bad_type` + `gold_sql`，进回归集）③ 本地状态 → `badcase`。

**出参** `{"ok":true,"annotation":{...}}`

**错误**：
`400 {"error":"gold_sql 不能为空" | "bad_type 不能为空" | "bad_type 非法（可选: [...]）"}`、
`400 {"error":"金标 SQL 执行失败（请先修正）: ..."}`、
`403`、`404 {"error":"标注不存在"}`、
`409 {"error":"状态 X 不可再确认，勿重复操作" | "点赞反馈不能确认成 BadCase（仅差评可入 BadCase，可改为驳回）"}`、
`409 {"error":"该条目已被删除，无法确认入 BadCase（Langfuse 里的 badcase 条目已写出，如需清理请到数据集 UI）"}`

### `POST …/{tid}/{mid}/confirm-good`

**功能**：用给定 SQL（缺省回退 `gold_sql` → `bad_sql`）写 `goodcase` 数据集并把本地置 `good`；**不重执行**（页面 execute 预览已人工核对）。

**实现逻辑**：`require_admin` → 读 ann → `sql` 缺省回退 `gold_sql→bad_sql` → `_confirm_good_commit`（trace 定位 → `_write_goodcase_item` → 本地 `good`）

**入参**：path `tid`、`mid`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `sql` | 否 | 正确 SQL；缺省回退 `gold_sql` → `bad_sql`（模型 SQL 即正确 SQL） |
| `db_name` / `annotator` | 否 | |

写两处：① Langfuse `Dataset:goodcase`（`source=user-annotation`）② 本地状态 → `good`（终态）。
**不需要重执行**（页面 execute 预览已人工核对）。

**出参** `{"ok":true,"annotation":{...}}`
**错误**：`400 {"error":"缺少正确 SQL（先用执行验证生成，或手动填写）"}`、`404`、`409`

### `POST …/{tid}/{mid}/revoke-good`

**功能**：先真删 `goodcase` 数据集条目，成功后把本地回 `queued`，维持「本地 `good` ⇔ 数据集有条目」不变量；删不掉则本地不动并报错。

**实现逻辑**：`require_admin` → 读 ann（非 good 409）→ `_find_trace_with_retry` → `_delete_goodcase_items`（真删）→ `reopen_annotation` 回 `queued`

**入参**：path `tid`、`mid`；无 body。

Langfuse 侧**真删条目**（不打标记），本地状态回 `queued`。

**出参**

```json
{"ok": true, "annotation": {...}, "deleted_items": 1,
 "warning": "数据集里没找到对应条目（可能已被手工删除），本地已回退"}
```

不变量：**本地 `status=good` ⇔ 数据集里有这条**。删不掉时不退本地状态，而是报错让人工处理。

**错误**：
`404 {"error":"标注不存在"}`、
`409 {"error":"状态 X 不在 Good Set，无需撤回"}`、
`409 {"error":"...；请到 Langfuse 数据集 UI 手动删除后重试","reason":"ambiguous"}`、
`502 {"error":"删除数据集条目失败（...）；本地未回退，可重试或去 Langfuse UI 手动删","reason":"delete_failed"}`、
`409 {"error":"本地状态回退失败（可能已被他处改动）"}`

### `POST /api/feedback/annotations/revoke-badcase`

**功能**：按 `item_id` 真删 `badcase` 条目；仅当该 trace 已无剩余 BadCase 时把 `badcase_status` 置 `invalid`，并按 `thread_id/message_id` 选择性回退本地状态。

**实现逻辑**：`require_admin` → 校验 item_id/trace_id → `_remove_badcase_item`（按 item 删）→ `remaining==0` 时 `badcase_status.mark(invalid)` → 按 thread/message 选择性 `reopen_annotation(from_status=badcase)`

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `item_id` | 是 | Langfuse dataset item id（自动采集条没有 `message_id`，故按 item 定位） |
| `trace_id` | 是 | 该条目所属 trace（用于列出同一 trace 的其他 BadCase） |
| `thread_id` / `message_id` | 否 | 有本地标注行时据此回退状态 |

**出参**

```json
{"ok": true, "deleted_items": 1, "remaining_items": 0,
 "local_reopened": true, "status_closed": true,
 "annotation": {"...": "..."},
 "warning": "该 trace 下还有 2 条 BadCase，状态未关闭"}
```

- `status_closed` 只在「该 trace 已无 BadCase 条目」时才置 `invalid`（`badcase_status` 按 trace 键，
  提前关会把兄弟条目一起踢出回归集）
- `annotation` 在自动采集条场景下为 `null`（本来就没有本地行，**正常情况**）

**错误**：
`400 {"error":"缺少 item_id / trace_id，无法定位 BadCase 条目","reason":"bad_request"}`、
`409 {"error":"...；请到 Langfuse 数据集 UI 手动删除后重试","reason":"ambiguous"}`、
`502 {"error":"删除数据集条目失败（...）；本地未回退，可重试或去 Langfuse UI 手动删","reason":"delete_failed"}`

> ⚠️ Langfuse 不在线时，数据集相关端点返回的 `warning` / `disabled` 会如实说明
> 「条目未删除，仅本地回退」；本地队列操作（列表 / judge / execute / 删除）不受影响。
