# 06 · 语义库（Wren 项目）管理 API

> 源文件：`src/api/wren_semantic.py`（21 个端点）
> 「语义库」= 磁盘上的 Wren 项目目录，通过 `db_config.wren_project` 与数据库关联。
> 权限：写操作多数要**管理员**（`admin_guard`，**返回** 403 JSON 而非抛异常）；
> 读操作要**登录 + 项目归属**（`_require_project_access`）。
>
> 标注约定：每个端点都有 **入参** 与 **出参** 两行；「无」= 不读任何参数。
> 通用错误形状 `{"error":"<中文>"}`；保存/构建类另有 `{"ok":true|false, ...}`。

## 1. 列表与创建

### `GET /api/wren-projects`（登录）

**功能**：扫描活跃工作区一级目录（含 `wren_project.yml`，跳过 `备份`/`backup`）并按库可见性过滤，逐库读 git 信息与 `target/mdl.json` 概览计数。

**实现逻辑**：`require_user` → `visible_dbs` + `is_admin` → `offload_long(_list_details)`（`_scan_wren_projects` → `_project_detail`：`repo_info` + `_mdl_summary` + `_associated_dbs`）

**入参**：无（按 `visible_dbs(user)` 过滤；管理员看全部；跳过名字含 `备份`/`backup` 的目录）

**出参**

```json
{"projects": [{"path":"/abs/path","name":"目录名","project_name":"wren_project.yml 的 name",
  "source":"git|local","git":{"branch":"main","commit":"a1b2c3d","dirty":false},
  "built": true, "models": 48, "views": 3, "relationships": 12, "cubes": 4,
  "data_source":"mysql", "associated_dbs":["imdb"]}]}
```

`built=false` 时 MDL 计数全为 0（尚未构建）。

### `POST /api/wren-projects/create`（管理员）

**功能**：建项目骨架（`wren_project.yml` + 空 `models/views/cubes/target` + `knowledge/` 5 类目录 + 模板文件 + `config/connection_*.json`），并写 `db_config.wren_project` 完成关联（此处不加载 MCP 工具）。

**实现逻辑**：`admin_guard` → `project_name/db_name` 校验 → `get_store().get(db_name)` → 目录冲突 409 → `offload(_materialize)`（建目录树 + 写 yml/connection/模板 + `set_wren_project`）→ `_invalidate_detector`

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `project_name` | 是 | 项目名（目录名会 sanitize，仅保留字母数字与 `-_`） |
| `db_name` | 是 | 关联的数据库配置（必存在） |
| `description` | 否 | 写入 `wren_project.yml` 的 `properties.description` |

**出参** `{"ok":true,"project":{...},"path":"/abs/path","requires_restart":false}`

**错误**：`400 {"error":"project_name 必填" | "db_name 必填"}`、
`404 {"error":"数据库 'X' 不存在"}`、`409 {"error":"目标目录已存在: <path>"}`

> 此处**不**同步加载 MCP 工具：目录刚建、`models/` 还是空的，工具在 introspect → build 之后才装。

### `POST /api/wren-projects/local`（管理员）

**功能**：校验后端路径存在、在 workspace 内且有 `wren_project.yml` → 写 `db_config.wren_project` 关联 → 失效发现类缓存并**同步加载该库的 wrenai 工具**，把加载结果回给前端。

**实现逻辑**：`admin_guard` → 校验目录/`wren_project.yml`/workspace 边界 → `get_store().set_wren_project` → `_invalidate_detector` → `_ensure_mcp_tools(target_db)`

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | **后端服务器**上的绝对路径（不是客户端电脑路径） |
| `target_db` | 是 | 关联的数据库配置名 |

**出参** `{"ok":true,"project":{...},"requires_restart":false,"mcp":{...}}`（`mcp` 为同步热加载结果）

**错误**：`400 {"error":"path 与 target_db 必填"}`、
`400 {"error":"后端机器上没有这个目录：X（这里要填**后端服务器**上的绝对路径，不是你这台电脑的路径）"}`、
`400 {"error":"目录存在，但根目录缺少 wren_project.yml：X"}`、
`400 {"error":"目录必须在后端 workspace 内：X（当前填的是 Y）"}`、
`404 {"error":"数据库 'X' 不存在"}`

### `POST /api/wren-projects/from-git`（管理员）

**功能**：浅克隆 → 校根目录有 `wren_project.yml` → 用 `target_db` 生成 connection/注册 profile → `context build` → 写关联 → 重建检索索引；同名目录走「可接管」确认流（不直接覆盖）。

**实现逻辑**：`admin_guard` → `validate_repo_url` → 目标目录已存在：未确认回 `code=exists`；已确认且是 git → 400；否则 `_adopt_git_into` → 不存在则 `clone_shallow` → 校验 yml → `_build_with_profile` → `set_wren_project` + `_ensure_mcp_tools` → `_refresh_retrieval_index`

**入参**（JSON body）

| 字段 | 必填 | 说明 |
|---|---|---|
| `repo_url` | 是 | 仓库地址（http/ssh，`validate_repo_url` 校验） |
| `ref` | 否 | 分支 / tag |
| `project_name` | 否 | 目标目录名；缺省取仓库名（去 `.git`），再 sanitize |
| `target_db` | 否 | 用该库连接信息生成 `config/connection_*.json` 并注册 profile |
| `overwrite_connection` | 否 | 默认 true；false = 保留仓库自带连接，只按 `wren_project.yml` 的 profile 构建 |
| `replace_existing` | 否 | 同名目录已存在时，必须显式 true 才走「接管替换」 |

**出参（正常）**

```json
{"ok":true,"project":{...},
 "build_note":"...；检索索引已重建（1213 条，向量 1213）",
 "requires_restart":false,"mcp":{...}}
```

**出参（同名目录已存在且未确认，`200` 需前端弹确认）**

```json
{"ok": false, "code": "exists", "adoptable": true, "pristine": false,
 "local_files":["knowledge/glossary/自定义.md"],
 "error": "已存在同名语义库「x」（其中 1 个自建文件会先备份再替换）；确认后带 replace_existing=true 重试",
 "project": {...}}
```

**错误**：`400 {"error":"repo_url 必填" | "<URL 校验>" | "仓库根目录缺少 wren_project.yml（语义库需按规范放在仓库根）"}`、
`400 {"error":"「x」已是 Git 仓库，请用卡片上的「更新」按钮","code":"is_git"}`、
`500 {"error":"<克隆失败原因>"}`

> 构建失败**不**返回错误：`ok:true` + `build_note` 里说明构建未完成（可后续点「构建」重试）。

### `DELETE /api/wren-projects/{name}`（管理员）

**功能**：解绑所有关联库（`wren_project` 置空）→ 摘除这些库的 MCP 工具 → 尽力删除项目目录（Windows 只读文件走 `onexc` 改权限）。

**实现逻辑**：`admin_guard` → `_find_project` → workspace 边界 + 名称一致校验 → `_associated_dbs` 逐个 `set_wren_project("")` → `invalidate_sub_entries` → `offload_long(_rmtree_force)`

**入参**：path `name`

**出参** `{"ok":true,"name":"..."}`；目录未能完全删除时额外
`"warning":"目录未能完全删除，可能被进程占用，请手动删除"`

**错误**：`404 {"error":"语义库 'X' 不存在"}`、`403 {"error":"仅支持删除 workspace 内的语义库"}`、
`400 {"error":"项目名与请求 name 不一致，拒绝删除"}`

## 2. 建模（内省 → 生成）

### `POST /api/wren-projects/{name}/introspect`（管理员）

**功能**：按 `db_type` 直连内省表结构/主键/外键（同步驱动走长任务池），并读已有 `models/*/metadata.yml` 的列与隐藏状态，供「调整已有库」对话框预置复选框。

**实现逻辑**：`admin_guard` → 定位 `db_name`（body/关联库/项目名）→ `offload_long(introspect_database)` → 组装 tables/FKs + `_read_existing_models`

**入参**：path `name`；body 可选

| 字段 | 必填 | 说明 |
|---|---|---|
| `db_name` | 否 | 目标库；缺省按关联库 / 项目名反查 |

**出参**

```json
{"ok": true, "db_name": "imdb", "db_type": "mysql",
 "existing_models": {"表名": {"columns":["..."], "hidden":["..."]}},
 "tables": [{"name":"t","comment":"","primary_key":"id","column_count":12,
             "columns":[{"name":"id","type":"int","wren_type":"integer",
                         "nullable":false,"comment":"","is_primary_key":true}]}],
 "foreign_keys": [{"source_table":"a","source_column":"x",
                   "target_table":"b","target_column":"y"}]}
```

**错误**：`404 {"error":"语义库 'X' 不存在" | "数据库 'Y' 不存在"}`、
`400 {"error":"无法确定目标数据库，请显式传入 db_name"}`、`500 {"error":"数据库内省失败: ..."}`

### `POST /api/wren-projects/{name}/generate-models`（管理员）

**功能**：先校验字段选择（不得隐藏主键/被外键引用的列）→ 按选择写/改 `models/*/metadata.yml` 与 `relationships.yml`；`patch_existing` 走**文本手术**只改 `is_hidden`，保住手写描述与字段顺序。

**实现逻辑**：`admin_guard` → 参数校验（`prune`/`delete_tables` 必须配 `patch_existing`）→ 定位 db → 内省 → `_project_lock` 内 `offload_long(_apply_model_selection)`（校验→删目录→写/改 yml→relationships）

**入参**：path `name`；body 见下表

| 字段 | 必填 | 说明 |
|---|---|---|
| `selected_tables` | 是 | 至少一张表 |
| `selected_columns` | 否 | `{"表": ["可见列"]}`；未列出的表 = 全列可见 |
| `include_relationships` | 否 | 默认 true，按外键生成 `relationships.yml` |
| `db_name` | 否 | 目标库 |
| `patch_existing` | 否 | true = 已有模型文件只改 `is_hidden`（保住手改的描述/字段顺序） |
| `prune` | 否 | 仅配 `patch_existing`：不在选择里的模型目录全删（含「数据库里已不存在的表」） |
| `delete_tables` | 否 | 仅配 `patch_existing`：逐表点名删除（界面「取消勾选」） |

**出参**

```json
{"ok":true,"models_generated":48,"models_removed":0,"relationships_generated":12,
 "skipped_columns":{"表":["列"]},"message":"..."}
```

**错误**：`400`（`selected_tables` 空、`selected_columns` 不是对象、`delete_tables` 不是数组、
隐藏主键、隐藏被外键引用的列、`prune`/`delete_tables` 未与 `patch_existing` 同用）、
`409`（`metadata.yml` 被手工改过结构、无法定位列块）

> 校验在写盘**之前**完成：被拒的请求保证一个字节都不落盘。
> 「数据库有、模型文件里没有」的列会跳过并在 `skipped_columns` 里点名（不是错误）。

## 3. 业务知识（`knowledge/`）

只认 wren 的 5 个目录，且只有 `.md` 会被消费：

| 前端分类 | 目录 | 形态 |
|---|---|---|
| `glossary` | `knowledge/glossary/` | 自由 Markdown |
| `metrics` | `knowledge/metrics/` | 自由 Markdown |
| `rules` | `knowledge/rules/` | 自由 Markdown |
| `sql_patterns` | `knowledge/sql/` | front-matter 的 `nl` + `sql` |
| `caveats` | `knowledge/caveats/` | 自由 Markdown |

### `GET /api/wren-projects/{name}/knowledge/read`（登录 + 归属）

**功能**：遍历 `knowledge/` 下 5 个分类目录逐个读 `.md`（`sql/` 目录额外解析 front-matter 的 `nl`+`sql`），按分类汇总返回。

**实现逻辑**：`_require_project_access` → `offload_long(_collect)`（遍历 5 分类目录读 `.md`，sql 目录用 `parse_query_markdown`）

**入参**：path `name`（无 body / query）

**出参**

```json
{"ok": true, "knowledge": {
  "glossary":[{"name":"表/术语名","file":"knowledge/glossary/x.md","content":"<原文>"}],
  "metrics":[...], "rules":[...], "caveats":[...],
  "sql_patterns":[{"name":"...","file":"knowledge/sql/x.md","nl":"...","sql":"...",
                   "source":"user","body":"","datasource":"...","tags":["..."],"created_at":"..."}]}}
```

### `GET /api/wren-projects/{name}/knowledge/template`（登录 + 归属）

**功能**：返回 `wren_templates.all_templates()` 的全部知识模板文本，供前端新建条目时预填。

**实现逻辑**：`_require_project_access` → `all_templates()`

**入参**：path `name`（无 query）

**出参**

```json
{"templates": {"knowledge_yml":"...", "rules_general":"...", "glossary":"...",
               "metrics":"...", "sql":"...", "caveats":"..."}}
```

### `POST /api/wren-projects/{name}/knowledge/save`（管理员）

**功能**：在项目写锁内批量写/删知识文件（路径白名单防穿越）；`sql_pairs` 由 wren 自己的 `render_query_markdown` 渲染 front-matter，保证与 `load_query_pairs` 往返一致。

**实现逻辑**：`admin_guard` → 类型/非空校验 → `_project_lock` 内 `offload_long(_apply)`（`files` 直写 / `sql_pairs` 走 `render_query_markdown` / `deletes` 幂等删；逐条 `_resolve_knowledge_file`）

**入参**：path `name`；body 见下表（三者至少给一项）

| 字段 | 必填 | 说明 |
|---|---|---|
| `files` | 否 | `{"knowledge/<分类>/<名>.md": "<正文>"}`（自由 Markdown 分类） |
| `sql_pairs` | 否 | `{"knowledge/sql/<名>.md": {nl, sql, datasource?, tags?, body?, source?, created_at?}}` |
| `deletes` | 否 | `["knowledge/<分类>/<名>.md", ...]`（幂等，已不存在视为完成） |

路径规则：只接受 `knowledge/<5 分类之一>/<名字>.md`；允许中文/空格，拒绝 `..`、绝对路径、
反斜杠、二级子目录、非 `.md`、隐藏文件与非法字符。
`sql_pairs` 由 wren 自己的 `render_query_markdown` 渲染 front-matter（与读取侧往返一致）。

**出参**

```json
{"ok":true,"saved":["knowledge/glossary/术语表.md"],
 "deleted":[],"rejected":["knowledge/bad/path.md"]}
```

**错误**：`400 {"error":"files / sql_pairs 需为对象，deletes 需为数组" | "files / sql_pairs / deletes 至少给一项"}`、
`400 {"error":"没有可写入的文件，路径或内容不合法","rejected":[...]}`（全部被拒时）

### `POST /api/wren-projects/{name}/knowledge/ai-generate`（管理员）

**功能**：内省表结构 + 外键 → 拼 prompt 让 LLM 产出 glossary/metrics/rules/sql_patterns 草稿；LLM 不可用时降级为基于表结构的 `fallback` 生成。

**实现逻辑**：`admin_guard` → 定位库 → 内省 → 拼 prompt → `get_llm().ainvoke` → 剥 markdown 围栏 → 按 `scope` 过滤；异常走 `_fallback_generate`

**入参**：path `name`；body 可选

| 字段 | 必填 | 说明 |
|---|---|---|
| `scope` | 否 | 生成范围，默认 `["glossary","metrics","rules","sql_patterns"]` |
| `industry` | 否 | 行业描述（提升术语质量） |
| `notes` | 否 | 补充说明 |

**出参** `{"ok":true,"generated":{"glossary":[...],"metrics":[...],"rules":[...],"sql_patterns":[...]},"mode":"ai|fallback","error":""}`

LLM 不可用 / 调用失败 → 降级为基于表结构的 `fallback` 生成（仍 `ok:true`，失败时带 `error`）。

## 4. 构建 / 校验 / 概览

### `POST /api/wren-projects/{name}/build`（管理员）

**功能**：在**暂存副本**里 `context build` → 用 `os.replace` 原子替换 `target/mdl.json`（零窗口）→ 对线上目录跑 `memory index` → 重装关联库工具 → 重建检索索引。

**实现逻辑**：`admin_guard` → `_find_project` → `_rebuild_swapped`（项目锁 + `_stage_build_replace`：副本 build → `_replace_target_mdl` 原子替换 → 检索索引）→ `memory index` → `_sync_mcp_tools_many`

**入参**：path `name`（无 body）

**出参**

```json
{"ok": true,
 "message": "context build 完成；检索索引已重建（1213 条，向量 1213）；memory index 完成",
 "mcp": {"imdb": {"db_name":"imdb","status":"ok","loaded":12}}}
```

**错误**：`400 {"ok":false,"message":"context build 失败: ...（未换入：线上目录保持原样）" | "暂存副本失败：..." | "换入失败：..."}`、
`404 {"error":"语义库 'X' 不存在"}`

> `memory index` 与检索索引都是 best-effort：失败只体现在 `message` 里，不影响 `ok`。

### `POST /api/wren-projects/{name}/validate`（登录 + 归属）

**功能**：跑 `wren context validate` 并把原始输出与 `mdl.json` 概览一并返回（`ok` 仅表达校验是否通过，HTTP 恒 200）。

**实现逻辑**：`_require_project_access` → `offload_long(_run_wren context validate)` → `_mdl_summary` 补 `name`/`path`

**入参**：path `name`（无 body）

**出参**

```json
{"ok": true, "message": "<wren 原始输出>",
 "summary": {"built":true,"models":48,"views":3,"relationships":12,"cubes":4,
             "data_source":"mysql","name":"项目名","path":"/abs/path"}}
```

`ok` = wren 校验是否通过；**HTTP 状态恒为 200**（除 404 / 403），校验失败看 `ok:false` + `message`。

**错误**：`404 {"error":"语义库 'X' 不存在"}`、`403`（非 owner）

### `GET /api/wren-projects/{name}/summary`（登录 + 归属）

**功能**：读 `target/mdl.json` 概览（models/views/relationships/cubes）+ 项目名 + 关联库列表，供卡片与详情页展示。

**实现逻辑**：`_require_project_access` → `offload_long(_load_summary)`（`_mdl_summary` + name/path + `_associated_dbs`）

**入参**：path `name`

**出参**

```json
{"summary": {"built":true,"models":48,"views":3,"relationships":12,"cubes":4,
             "data_source":"mysql","name":"项目名","path":"/abs/path",
             "associated_dbs":["imdb"]}}
```

**错误**：`404 {"error":"语义库 'X' 不存在"}`、`403`

### `POST /api/wren-projects/{name}/open-directory`（登录 + 归属）

**功能**：在**宿主机**用 `os.startfile` / `open` / `xdg-open` 打开项目目录（子进程走线程池，避免无桌面环境下卡住事件循环）。

**实现逻辑**：`_require_project_access` → 按平台选 `os.startfile` / `open` / `xdg-open` → `offload_long(_open)`

**入参**：path `name`（无 body）

**出参** `{"ok":true,"path":"/abs/path"}`

**错误**：`404`、`500 {"error":"打开目录失败: ..."}`

## 5. Git 版本管理

### `GET /api/wren-projects/{name}/git-status`（登录 + 归属）

**功能**：非 Git 项目返回「接管会覆盖哪些本地文件」（供前端提前弹确认）；Git 项目用 `ls-remote` 实时对比远程 sha，并区分阻断性本地改动 / 未跟踪新知识 / 构建产物。

**实现逻辑**：`_require_project_access` → 非 git 走 `_local_content_state`；git 走 `offload_long(_collect)`（`repo_info` + `_rev_parse` + `list_remote_refs` + `status --porcelain` + `local_changes`）→ 比对 sha 得 `has_updates`

**入参**：path `name`

**出参（非 Git 项目）**

```json
{"ok":true,"is_git":false,"has_updates":false,
 "adopt_local_files":["knowledge/glossary/自定义.md"],
 "adopt_pristine":false,"adopt_built":true}
```

**出参（Git 项目）**

```json
{"ok":true,"is_git":true,"has_updates":true,"has_local_changes":true,
 "local_changes":["阻断性改动文件"],"untracked_changes":["新知识文件"],
 "generated_changes":["构建产物"],
 "branch":"main","commit":"a1b2c3d","remote_branch":"main","remote_commit":"d4e5f6a",
 "default_branch":"main"}
```

`has_updates` 用 `ls-remote` 实时取远程分支 sha 比对（不用 `origin/HEAD`，浅克隆仓库没有该引用）。

**错误**：`404`、`403`

### `GET /api/wren-projects/{name}/git-refs`（登录 + 归属）

**功能**：`ls-remote` 列远程分支/tag（含默认分支）+ 当前分支与 commit，供「更新」对话框选版本。

**实现逻辑**：`_require_project_access` → 非 git 回空 → `offload_long(_collect)`（`list_remote_refs` + `repo_info`）

**入参**：path `name`

**出参**

```json
{"ok":true,"is_git":true,"current_branch":"main","current_commit":"a1b2c3d",
 "default_branch":"main","branches":["main"],"tags":["v1.0"]}
```

非 Git 项目 → `{"ok":true,"is_git":false,"default_branch":"","branches":[],"tags":[]}`

**错误**：`404`、`403`

### `POST /api/wren-projects/{name}/git-pull`（管理员）

**功能**：在暂存副本里 `pull_ref`（可选先 `git stash` 备份本地改动）→ 成功后整目录原子换入 → 缺 `mdl.json` 时就地补构建 → 重建检索索引；失败时线上目录一字节未动。

**实现逻辑**：`admin_guard` → 非 git 400 → `ref`/`discard_local` 取值（query 优先 body）→ `_pull_swapped`（项目锁 + `_stage_and_swap`：副本 `pull_ref` → 缺 mdl 补 build → 整目录换入）→ `_invalidate_detector` + 检索索引

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `name` | 是 | 语义库名 |
| query / body | `ref` | 否 | 分支或 tag；缺省 = 远程默认分支最新 |
| query / body | `discard_local` | 否 | true = 先 `git stash` 备份本地改动再更新（返回 `stash_ref`） |

**出参** `{"ok":true,"changed":true,"message":"...","stash_ref":"stash@{0}","build_note":"..."}`

**错误**：`400 {"error":"该语义库不是 Git 仓库"}`、
`400 {"error":"<pull_ref 的拒绝原因>（未换入：线上目录保持更新前状态）"}`

安全保证：拉取在暂存副本里做，失败时线上目录一个字节都没动；成功才整目录原子换入；
换入前若副本无 `target/mdl.json` 会就地补一次 build；换入后 best-effort 重建检索索引。

### `POST /api/wren-projects/{name}/push`（管理员）

**功能**：`init` → 配 `origin` → 重命名分支 → 补 git 身份 → `add -A` → `commit` → `push` → （可选）打并推 tag；非快进给 409 引导勾选强制覆盖，GitHub 缺仓库时尝试 `gh repo create` 后重试。

**实现逻辑**：`admin_guard` → `validate_repo_url` → 补 commit_message → `git init` / `branch -m` / `remote add`（或 `set-url` + `branch -M`）→ `_ensure_git_identity` → `add -A` → `commit --allow-empty` → `push -u`（非快进 409 / GitHub 自动建仓重试 / `set-url` 重试）→ 可选 `tag -f` + push tag

**入参**

| 字段 | 必填 | 说明 |
|---|---|---|
| `remote_url` | 是 | 远程地址（`validate_repo_url` 校验） |
| `branch` | 否 | 默认 `main` |
| `tag` | 否 | 推送后打并推 tag |
| `commit_message` | 否 | 留空自动生成「语义库更新 <名> <时间>」；会自动补 git user.name/email |
| `force` | 否 | true = `--force`（强制覆盖远端） |

**出参** `{"ok":true,"message":"git init；remote add origin；git add -A；git commit；push to origin/main；tag v1.0"}`

**错误**：`400 {"error":"remote_url 必填" | "<URL 校验>"}`、
`409 {"error":"远端分支 'main' 已有不同历史，普通推送被拒绝。...git 输出: ..."}`、
`500 {"error":"git init/add/commit/push 失败: <git 原始输出>"}`

> GitHub 仓库不存在时会尝试 `gh repo create` / GitHub API 自动建私有仓库后重试一次。

### `POST /api/wren-projects/{name}/git-adopt`（管理员）

**功能**：备份本地 → 干净浅克隆（可先在暂存目录构建）→ 两次同盘 `rename` 整目录原子换入，让「已存在的本地库」接上远程；已是 Git 仓库则拒绝。

**实现逻辑**：`admin_guard` → `_find_project` → workspace 边界 → 已是 git 400 → `_adopt_git_into`（`_local_content_state` 确认 → 浅克隆 → 校验 yml → 可选构建 → 两次 `rename` 换入）→ 检索索引

**入参**

| 字段 | 必填 | 说明 |
|---|---|---|
| `repo_url` | 是 | 远程地址 |
| `ref` | 否 | 分支 / tag |
| `discard_local` | 否 | 本地有自建内容时必须显式 true 才覆盖 |
| `build` | 否 | 默认 true（接管路径**强制真构建**：否则会沿用仓库原作者的 profile） |
| `target_db` | 否 | 用于生成 connection / profile |

**出参** `{"ok":true,"name":"...","build_note":"..."}`

**错误**：`400 {"error":"该语义库已是 Git 仓库，请用卡片上的「更新」按钮" | "仓库根目录缺少 wren_project.yml..."}`、
`403 {"error":"仅支持接管 workspace 内的语义库"}`、
`200 {"ok":false,"code":"local_content","local_files":[...],"pristine":false}`（等前端确认）
