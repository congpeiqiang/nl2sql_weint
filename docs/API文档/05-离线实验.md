# 05 · 离线实验 API（全部管理员）

> 源文件：`src/api/experiment.py`；后台执行 `agent/eval/run_experiment.py`
> 产物目录：`{active_workspace}/eval/experiment_runs/`
> 四维 A/B：**数据集 × prompt label × skill git ref × 语义库 git ref**

后台执行方式：`POST` 建 `stamp` + 初始 status 文件后 `asyncio.create_task` 跑
`_execute_run`（阻塞逻辑用 `asyncio.to_thread` 包），进度经 `on_progress` 回写
`{stamp}.status.json`，前端轮询读取。

> 标注约定：每个端点都有 **入参** 与 **出参** 两行；「无」= 不读任何参数。

## 1. `GET /api/experiment/datasets`

**功能**：调 Langfuse 列全部数据集并逐个取条目数（`datasets.list` 不带计数），读取失败记 -1；`note` 用来区分「数据集为空」与「读取失败」。

**实现逻辑**：`require_admin` → Langfuse `datasets.list` → 逐数据集 `dataset_items.list` 取条数（异常记 -1）→ 组装 + `note`

**入参**：无

**出参**

```json
{"datasets": [{"name":"badcase","count":120},{"name":"goodcase","count":60}],
 "note": ""}
```

`count = -1` 表示该数据集条目数读取失败；`note` 用于区分「数据集为空」与「读取失败」。

## 2. `GET /api/experiment/prompt-labels?name=<prompt 名>`

**功能**：读参与实验的 prompt（`PROMPT_NAMES`）在 Langfuse 上的可用 labels，供前端选 A/B 版本；Langfuse 关闭时返回空 + note。

**实现逻辑**：`require_admin` → 取 `name` 或全部 `PROMPT_NAMES` → 读 Langfuse prompt labels；未启用给 `note`

**入参**：query `name`（可选，prompt 名；不传 = 列出全部）

**出参**

```json
{"prompts":[{"name":"main_agent","labels":["production","latest","exp-a"]}]}
```

无 `name` 时列出全部 `PROMPT_NAMES` 的 labels；Langfuse 关闭时返回空列表 + `note`。

## 3. `GET /api/experiment/skill-refs`

**功能**：用 git 读 skills 仓库的 tags / branches / HEAD（短 sha），供选实验用的 skill 版本；读失败或未绑 git 返回空 + 修复 note。

**实现逻辑**：`require_admin` → `_git_refs(skills 仓库)`（`git tag` / `for-each-ref` / `rev-parse`）→ 空则按 origin 给 note

**入参**：无

**出参**

```json
{"tags":["skills/2026-10-01"],"branches":["main"],"head":"a1b2c3d"}
```

读失败或未绑 git：`{"tags":[],"branches":[],"head":"","note":"..."}`

## 4. `GET /api/experiment/semantic-refs?db=<库名>`

**功能**：按库定位语义库 repo 并读远程 refs，供选实验用的语义层版本；未绑 git / 远程不可达时返回空 + note（说明如何修）。

**实现逻辑**：`require_admin` → 按 `db` 定位语义库目录 → `_git_refs`（本地+远程）→ 空则给修复 note

**入参**：query `db`（语义库关联的数据库名）

**出参**

```json
{"tags":["v1.2"],"branches":["main"],"head":"a1b2c3d"}
```

本地目录未绑 git / 远程不可达 → 空数组 + `note`（说明如何修复：推 tag 或先绑远程）。

## 5. `POST /api/experiment/runs`

**功能**：校验 `datasets` 非空、`arms` 非空且名字唯一 → 建 `stamp` + 初始 status 文件 → `asyncio.create_task` 后台执行（物化预检 → 装数据集 → spawn worker）→ 立即返回 `status_url` 给前端轮询。

**实现逻辑**：`require_admin` → `parse_body` → datasets/arms 校验（名字唯一）→ `_stamp()` + `_write_status(queued)` → `asyncio.create_task(_execute_run)` 记入 `_RUN_TASKS` → 回 `status_url`

**入参**（JSON body）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `datasets` | string[] | 是 | 至少一个数据集名（不再隐式默认 badcase） |
| `arms` | object[] | 是 | 每臂 `{name, prompt_label?, skill_ref?, semantic_ref?}`，`name` 唯一 |
| `dataset_limit` | int | 否 | 每数据集取样上限，0 = 全部 |
| `judge` | bool | 否 | 是否启用 LLM 判分 |
| `threshold` | float | 否 | 判分通过阈值，默认 0.05 |
| `timeout` | int | 否 | 单题超时秒，默认 1800 |
| `description` | string | 否 | 实验描述（≤ 2000 字） |
| `llm_route` / `llm_model` / `enable_thinking` | string | 否 | run 级模型（空串 = 跟随 active） |
| `badcase_status` | string | 否 | 仅老的 `from_badcase` 路径使用 |

`semantic_ref` 形态：`db=ref`（单库）或 `db=ref,db2=ref2`（多库）。

**出参**

```json
{"ok": true, "stamp": "20261028T153000", "status_url": "/api/experiment/runs/20261028T153000"}
```

**错误**：`400 {"error":"datasets 不能为空：请至少勾选一个数据集"}` /
`400 {"error":"arms 必填（每臂 {name, prompt_label?, skill_ref?, semantic_ref?}）"}` /
`400 {"error":"arm 名重复（name 需唯一）"}`

> **预检策略**：skill_ref / semantic_ref / prompt label 在提交后先做**物化预检**
> （浅克隆、prompt 版本快照）。失败不阻塞提交，但 run 会以
> `status=error, stage=failed` 收尾并给出明确原因 —— 不允许静默退化跑「当前版本」
> 得出看似成功实则错误的 A/B 结果。

## 6. `GET /api/experiment/runs`

**功能**：同时扫 `run_*.json`（manifest）与 `*.status.json`，合并出历史 run（**运行中的也在列表里**，其 `gate` 为 null），按 `stamp` 倒序。

**实现逻辑**：`require_admin` → 扫 `run_*.json`（manifest）+ `*.status.json` → 合并（运行中只有 status）→ 按 `stamp` 倒序

**入参**：无

**出参**

```json
{"runs": [{"stamp":"20261028T153000","status":"running|done|error|cancelled|interrupted",
  "stage":"queued|preflight|loading_dataset|running_arms|complete|failed|cancelled",
  "dataset":"badcase","arms":[...],"gate":{...}|null,
  "started_at":"ISO","finished_at":"ISO","description":"...",
  "model_label":"deepseek/deepseek-v4"}]}
```

按 `stamp` 倒序。运行中的 run 只有 `*.status.json`（manifest 未落盘），也会出现在列表里，
`gate` 为 `null`。

## 7. `GET /api/experiment/runs/{stamp}`

**功能**：读 status / manifest / 逐条明细拼出完整结果；`status=running` 且超过 7200s 未刷新时**惰性标记** `interrupted`（看门狗失灵时的兜底）。

**实现逻辑**：`require_admin` → `_read_status` → `running` 超 7200s 惰性置 `interrupted` → 读 manifest/逐条明细组装

**入参**：path `stamp`

**出参**

```json
{"stamp":"...","status":"done","stage":"complete",
 "progress":{"total":4,"done":4,"current":""},
 "request":{"datasets":["badcase"],"dataset_limit":0,"judge":true,"threshold":0.05,
            "description":"...","llm_route":"","llm_model":"","enable_thinking":"false",
            "model_label":"..."},
 "arms":[...], "manifest":{...}, "gate":{...}, "cases":[...], "error":"",
 "started_at":"ISO","finished_at":"ISO"}
```

超时兜底：`status=running` 且距 `started_at` 超过 7200s → 惰性标记 `interrupted`（`stage=failed`）。

## 8. `POST /api/experiment/runs/{stamp}/cancel`

**功能**：写 `<run_dir>/<stamp>/cancel` 停止标记并把状态置 `cancelling`（暂态），由 orchestrator/worker 在每题/每臂的自然断点退出后收口 `cancelled`；僵尸 run（进程重启无存活 task）直接收尾。

**实现逻辑**：`require_admin` → 读 status（终态 409 / 不存在 404）→ 僵尸 run 直接收尾 → 存活则写 `cancel` 标记 + `status=cancelling` → 竞态兜底

**协作式取消**（不 kill subprocess，避免强杀 agent 留半截 trace）：

**入参**：path `stamp`（无 body）

1. 写停止标记 `<run_dir>/<stamp>/cancel`
2. 状态置 `cancelling`（暂态，前端继续轮询）
3. orchestrator / worker 在每题 / 每臂的自然断点检查标记 → 干净退出、部分结果照常落盘
4. orchestrator 返回 `RC_CANCELLED` → 终态 `cancelled`

**出参** `{"ok":true,"status":"cancelling" | "cancelled"}`

**错误**：`404 （run 不存在）`、`409 （已结束（xxx），无法停止）`、`500 （写停止标记失败）`

幂等与兜底：僵尸 run（`status=running` 但进程重启后无存活 task）直接收尾为 `cancelled`；
写完标记后若 task 恰好结束，也会补一次终态，防前端卡在 `cancelling`。

## 9. `DELETE /api/experiment/runs/{stamp}`

**功能**：`running` 中拒绝（409）；否则删 manifest / status / 明细目录（`shutil.rmtree` 走长任务池，避免阻塞事件循环）。

**实现逻辑**：`require_admin` → 运行中 409 → 删 manifest/status 文件 + `offload_long(shutil.rmtree, run_dir)`

**入参**：path `stamp`

**出参** `{"ok":true,"deleted":"<stamp>"}`
**错误**：`409 （仍在运行 / 状态为 running，不能删除）`、`404 （不存在）`
