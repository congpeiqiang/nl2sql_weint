# 07 · 运维与可观测 API

> 源文件：`metrics.py`、`drain.py`、`trace_routes.py` + 三个纯 ASGI 中间件
> （`request_log.py`、`auth_middleware.py`、`langfuse_metadata.py`）
>
> 标注约定：路由端点都有 **入参** 与 **出参** 两行；中间件不是 HTTP 端点，单列一节说明。

## A. 指标

### `GET | HEAD /metrics`（**仅容器内网**）

**功能**：直接复用 langgraph 的 `meta_metrics`：`format=prometheus` 走全局 REGISTRY（本模块注册的 `nl2sql_*` 自动合并进同一份 exposition），`format=json` 给队列/worker 快照；上游不可用时降级为自采指标而不是 500。

**实现逻辑**：惰性 `_resolve_meta_metrics()`（import `langgraph_api.api.meta`）→ `handler(request)` 按 `format` 出 prometheus/json → 加 `cache-control: no-store`；不可用走 `_degraded_response`

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| query | `format` | 否 | `prometheus`（默认）→ exposition 文本；`json` → 队列/worker 快照 + 告警状态 |

**出参**

| format | 响应 |
|---|---|
| prometheus | `200` + `text/plain; version=0.0.4`（`nl2sql_*` 指标族） |
| json | `200` + `{"queue": {...}, "workers": {...}, "alerts": {...}}` |

**暴露面**：不在 auth 白名单 → 带 Cookie 或 `X-Forwarded-For` 的外部请求 401/403；
只有「内网 IP + 无 Cookie + 无 XFF」放行。生产 nginx 只把 `/api/` 转后端，`/metrics` 对外不可达。

**指标族（统一 `nl2sql_` 前缀）**

| 指标 | 类型 | 采样来源 |
|---|---|---|
| `process_rss_bytes` | Gauge | `/proc/self/statm`（非 Linux 走 psapi / resource） |
| `event_loop_lag_seconds` / `_max_seconds` | Gauge | 采样循环 `asyncio.sleep` 的超时值 |
| `run_queue_running` / `_pending` | Gauge | `langgraph_runtime.ops.Runs.stats` |
| `run_queue_wait_seconds{quantile}` | Gauge | 同上（pending run 等待时长） |
| `worker_slots{state=max\|active\|available}` | Gauge | `langgraph_runtime.metrics.get_metrics()` |
| `llm_calls_total{outcome}` / `llm_latency_seconds{outcome}` | Counter / Histogram | `ModelTimeoutMiddleware` |
| `llm_gate_total{result}` / `llm_gate_wait_seconds` / `llm_retries_total{outcome}` | Counter / Histogram | `agent/utils/llm_gate` |
| `sqlite_lock_wait_seconds{store}` 等 4 条 | Histogram / Counter / Gauge | `prom_metrics.metered_rlock` |
| `mcp_servers{status}` | Gauge | `tools/mcp_tool._sub_entries` |
| `process_children` | Gauge | `/proc` 中 PPid == 本进程（MCP stdio 子进程口径） |
| `disk_free_bytes{path}` / `disk_used_ratio{path}` / `data_bytes{area}` | Gauge | 保留策略那轮量完缓存 |
| `alerts_total{alert}` / `alert_active{alert}` | Counter / Gauge | 本模块看门狗 |
| `sched_worker_alive` / `sched_tasks_enabled` / `sched_fires_ok_total` / `sched_fires_error_total` / `sched_last_tick_age_seconds` | Gauge | `scheduler/worker.metrics_snapshot` |
| `metrics_samples_total{result}` | Counter | 采样轮次 |

**降级**：上游 `langgraph_api.api.meta.meta_metrics` 不可用时不 500 —— 返回本模块自采指标，
prometheus 输出首行加注释说明队列指标缺失，JSON 输出带 `degraded` 字段。

## B. 优雅停机（排空）

### `POST /api/admin/drain`（管理员）

**功能**：置 `draining` 标志（此后新建 run 被 `DrainGateMiddleware` 以 503 + `Retry-After` 拒绝），并按预算轮询本实例在跑任务数直到清零；返回带 `counter_source`/`counter_trusted` 的快照。

**实现逻辑**：`require_admin` → 解析 `wait` → `begin_drain("admin")` → 可选 `await wait_for_idle()`（轮询 `active_workers()`）→ `drain_state()`

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| query | `wait` | 否 | 默认 `1`（等待清零）；`0` = 只置位不等待 |

**出参**（快照）

```json
{"draining": true, "started_at": 0.0, "deadline_at": 0.0,
 "waited_secs": 3.5, "remaining": 0, "drained": true, "reason": "admin",
 "counter_source": "inmem|postgres|unknown",
 "counter_trusted": true, "counter_detail": "WORKERS=0"}
```

> ⚠️ 发版脚本必须断言 **`counter_trusted && remaining == 0`**：只判 `remaining == 0`
> 会在版型切换（读不到计数）时把「读不到」当成「已排空」，接着 `docker stop` 腰斩在跑的 run。

### `GET /api/admin/drain`（管理员）

**功能**：只读当前排空快照（不触发任何动作），供发版脚本轮询判断何时可 `docker stop`。

**实现逻辑**：`require_admin` → `drain_state()`（纯读，含 `_counter_meta`）

**入参**：无

**出参**：同上快照（发版脚本轮询用）

### `DELETE /api/admin/drain`（管理员）

**功能**：撤销 `draining` 标志、恢复接单（运维改主意 / 排空失败回退），返回最终快照。

**实现逻辑**：`require_admin` → `end_drain()` 清标志并返回快照

**入参**：无

**出参**：撤销后的快照（`draining=false`，恢复接单）

### 排空期 503 形状（非独立端点）

> 该小节描述 `POST /runs*`、`POST /threads/{tid}/runs*` 在排空期间的响应，**无入参**。

```json
{"error":"服务正在停机排空（发版中），暂不接受新的查询请求，请稍后重试",
 "draining": true, "remaining_tasks": 2}
```

响应头 `Retry-After: 30`。只拦 7 条**创建 run** 的路径；取消 / 查询 / 会话操作照常放行。

## C. 轨迹（Trace）

> 数据源：全局共享 `traces.sqlite`（`EventStore`，进程级单实例），切换工作区不丢历史。

### `GET /api/traces/threads/{thread_id}/events`（归属）

**功能**：按 thread + 可选 task/event_type/seq 区间分页查 `traces.sqlite` 事件表并回总数；同步 sqlite 读包成一次 `offload`，不占事件循环。

**实现逻辑**：`_owned()` 归属守卫 → `_parse_pagination`（limit≤500）→ `offload(_load)`（`query_events` + `count_events`）

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `thread_id` | 是 | 会话 ID |
| query | `task_id` | 否 | 按子任务过滤 |
| query | `event_type` | 否 | 按事件类型过滤 |
| query | `seq_from` / `seq_to` | 否 | seq 区间 |
| query | `limit` / `offset` | 否 | 默认 200 / 0；limit ≤ 500 |

**出参**

```json
{"thread_id":"...","total":1234,"limit":200,"offset":0,"count":200,
 "events":[{"seq":1,"thread_id":"...","task_id":"...","event_type":"...",
            "payload":{...},"ts":"ISO"}]}
```

**错误**：`400 {"error":"thread_id required"}`、`403`

### `GET /api/traces/threads/{thread_id}/lineage`（归属）

**功能**：用 `SessionLineageEngine` 递归读事件表，构建该会话的祖先链、当前节点与后代树（主/子 agent 谱系）。

**实现逻辑**：`_owned()` → `SessionLineageEngine(store).trace_session(tid)`（`offload`）

**入参**：path `thread_id`

**出参**

```json
{"thread_id":"...", "ancestors":[...], "node":{...},
 "descendants":[{"...":"...","children":[...]}]}
```

**错误**：`400`、`403`

### `GET /api/traces/threads/{thread_id}/stats`（归属）

**功能**：全量扫该会话事件做投影：LLM 总耗时、四类 token（input/output/cache_read/reasoning）、步数、工具调用数、子 agent 数。

**实现逻辑**：`_owned()` → `offload(store.compute_session_stats)` 投影

**入参**：path `thread_id`

**出参**

```json
{"thread_id":"...","total_llm_ms":12345,"total_input_tokens":1000,
 "total_output_tokens":500,"total_cache_read_tokens":0,"total_reasoning_tokens":0,
 "step_count":12,"tool_call_count":7,"subagent_count":1}
```

**错误**：`400`、`403`

### `GET /api/traces/threads/{thread_id}/llm-calls`（归属）

**功能**：读该 thread 的每次 LLM 调用明细（模型/路由/token/耗时），供前端逐次展开。

**实现逻辑**：`_owned()` → `offload(store.get_llm_calls)`

**入参**：path `thread_id`

**出参**

```json
{"thread_id":"...","count":2,
 "calls":[{"model":"...","route":"...","input_tokens":1000,"output_tokens":500,
           "latency_ms":1234,"ts":"ISO"}]}
```

**错误**：`400`、`403`

### `GET /api/traces/tasks/{task_id}/events`（**管理员**，跨 thread 排障）

**功能**：按 `task_id` 跨 thread 取子任务全部事件（无归属维度可查 ⇒ 仅管理员），用于排障子 agent 的执行链。

**实现逻辑**：`_admin_only()` → `offload(store.get_task_events)`（跨 thread）

**入参**：path `task_id`

**出参** `{"task_id":"...","count":N,"events":[...]}`

**错误**：`400 {"error":"task_id required"}`、`403`

> 权限：四个 `/threads/{tid}/*` 路由统一包 `_owned()`（归属守卫）；
> `tasks/{task_id}/events` 没有归属维度可查，`_admin_only()` → 仅管理员。

## D. 三个纯 ASGI 中间件（非 HTTP 端点）

> 本节三个对象**没有 URL、没有入参/出参**，只描述它们对请求/响应的改写。

### `RequestContextMiddleware`

- 读入站 `X-Request-ID` / `X-Correlation-ID`（仅接受 `[A-Za-z0-9._:-]{1,64}`，不合规丢弃重建）
- 生成 12 位 hex 写入 contextvar，注入**每条**日志（`%(request_id)s` 由 `RequestIdFilter` 完成）
- 响应加 `X-Request-ID` 头；请求结束记一行
  `[access] rid=... method path -> status latency=..ms total=..ms ip= user= [tid=]`
- 不缓冲 body、只读响应消息 → 不破坏 SSE；`/ok` 不记日志

### `AuthMiddleware`

- 白名单前缀放行（见 README 2.1）
- 内部请求判据：`is_internal(来源网段) and not has_cookie and not has_xff`
  → 注入 `user_id="internal"`（**缺一不可**：只看网段会从 nginx 入口被打穿）
- 校验通过注入完整用户对象；未通过 `401 {"error":"unauthorized"}`
- 每个带 Cookie 的请求会幂等 `register_user`（首次入库）
- 强制改密开关见 README 2.1

### `LangfuseMetadataMiddleware`

只作用于 run 创建路径（`POST /runs`、`/runs/stream|wait|batch`、
`POST /threads/{tid}/runs[/stream|batch]`）：

1. **授权钳制（安全属性，不受监控开关影响）**
   - 外部真实用户：`config.configurable.user_id` 强制覆盖为登录身份
   - `configurable.db_name` 不在授权内 → `403 {"error":"forbidden","detail":"..."}`
   - 删除客户端伪造的 `thread_id` / `checkpoint_id` / `checkpoint_ns`
   - 内部调用（子 agent / sync 循环）不钳制
2. **Langfuse metadata 注入（监控旁路）**：写入 `config.metadata`
   （`langfuse_session_id` / `langfuse_trace_name` / `langfuse_tags` / `langfuse_user_id` 等），
   失败只 debug；同时登记会话归属（`grants` 表 + thread `metadata.owner`）

逃生开关：`NL2SQL_SKIP_RUN_DB_AUTHZ=1` 跳过 db_name 授权校验（仍钳制 `user_id`）——仅应急。

## E. 生命周期（`custom_app._lifespan`）

> 非 HTTP 端点，无入参/出参；列出启动/停机顺序以便排障。

**启动（yield 之前，任一失败只 warning 不拦启动）**

1. 运行时库归位（`sqlite_paths.adopt_all_stores`）
2. 指标采样任务（`api.metrics.start()`）
3. 子任务终态补写器（`pending_terminal.start_reaper`）
4. 保留策略维护线程（`retention.start_maintenance`）
5. 嵌入通道保活（`embedder.start_warmer`）
6. 定时任务调度 worker（`scheduler.worker.start_worker`）

**停机（顺序是设计的一部分）**

1. `stop_worker()` —— 排空窗口内不再产生新的定时 run
2. `begin_drain("lifespan-shutdown")` + `wait_for_idle()` —— 等本实例在跑任务清零
3. `flush_langfuse()` —— 让最后一批 trace/分数进入本次上送
4. `stop_reaper()` → `stop_maintenance()` → `stop_warmer()` → `metrics.stop()`
