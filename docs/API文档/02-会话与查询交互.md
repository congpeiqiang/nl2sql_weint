# 02 · 会话与查询交互 API

> 源文件：`auto_title.py`、`thread_search.py`、`thread_run_status.py`、`thread_delete.py`、
> `thread_export.py`、`thread_fork.py`、`thread_compact.py`、`task_cancel.py`、
> `sql_approval.py`、`report_file.py`
>
> 标注约定：每个端点都有 **入参**（位置 / 字段 / 必填）与 **出参**（成功响应）；
> 「无」= 不读任何参数（身份来自 Cookie/Authorization）。

## A. 标题与搜索

### `POST /api/auto-title`（登录）

**功能**：用该账号自己的轻量模型（`enable_thinking=False`，按 `user_id` LRU 缓存）把首条问题压成 ≤20 字标题；无模型或调用失败则回退「原文截断」，不报错。

**实现逻辑**：取 `require_user().user_id` → `_get_title_model`（LRU 64，`create_model(enable_thinking=False, user_id)`）→ `ainvoke` → `_clean_title` 截 20 字；失败/无模型回退原文截断

**入参**（JSON body）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | 是 | 用户首条问题（超 500 字截断） |

**出参** `{"title":"≤20 字标题"}`

说明：无状态，不读 thread；模型生成失败时回退「问题原文截断」（仍 200）。

**错误**：`400 {"error":"text 必填"}`、`500 {"error":"模型不可用"}`

### `GET /api/threads/fts`（登录）

**功能**：按 TTL（默认 5s）节流刷新 FTS5(trigram) 索引（枚举会话、只重建 `updated_at` 变过的），再**在 SQL 内**按归属过滤检索标题/正文/tool_call SQL；中文 ≤2 字退 `LIKE` 扫描。

**实现逻辑**：`require_user` → `_refresh_if_stale`（TTL 5s + `_refresh_lock`；`threads/search` 枚举 + 只重建变更会话）→ `offload(_search)`（FTS5 trigram，短词退 LIKE，**SQL 内按 owner 过滤**）

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| query | `q` | 是 | 关键词（中文 ≤2 字自动退化 LIKE 扫描） |
| query | `limit` | 否 | 默认 20，范围 1~50 |

**出参**

```json
{"ok": true, "query": "关键词",
 "results": [{"thread_id":"...","title":"...","snippet":"...","matched_count":3,"updated_at":"ISO"}]}
```

**错误**：`400 {"ok":false,"error":"q 必填"}`

说明：FTS5(trigram) 索引 + 5s 节流增量刷新；归属过滤在 SQL 内完成。

## B. 会话状态与生命周期

### `GET /api/threads/{thread_id}/run-status`（归属）

**功能**：自调用读 `state` 与最近 runs，用四判据（`next` 非空 / 无活跃 run / 无 HITL 等待 / 末条不是终稿）+ 失败戳区分「半轮未完成」与「执行失败」，并把 `task.error` 剥壳成可读原因给前端。

**实现逻辑**：`_UUID_RE` → `require_thread` → 自调用 `GET /threads/{id}/state` + `/runs?limit=10`（转发 Cookie/Authorization）→ `classify()`：活跃 run / interrupts / 末条是否终稿 / 失败戳 → 组合两个布尔

**入参**：path `thread_id`（UUID）

**出参**

```json
{"ok": true, "thread_id": "uuid", "checkpoint_id": "...",
 "has_active_run": false, "active_run_ids": [],
 "next": ["model"], "awaiting_interrupt": false, "last_message_is_final": true,
 "last_run": {"run_id":"...","status":"interrupted","updated_at":"ISO"},
 "turn_incomplete": false, "turn_failed": false, "last_error": ""}
```

判定口径：

- `turn_incomplete` = `next` 非空 ∧ 无活跃 run ∧ 无 HITL 等待 ∧ 末条不是终稿 assistant 文本 ∧ 非失败
- `turn_failed` = 末轮 run 为 `error`/`timeout` **或** 末条 AI 带失败戳（且无活跃 run / 无审批）
- `last_error` 取 `state.tasks[].error` 剥壳后的可读文本（≤300 字），取不到回落到失败戳 `detail`

**错误**：`400 {"ok":false,"error":"invalid thread_id"}`、`403`（非 owner）、`404`、
`502 {"ok":false,"error":"state HTTP <code>" | "runs HTTP <code>" | "upstream unavailable"}`

### `DELETE /api/threads/{thread_id}`（归属）

**功能**：先取消该线程在飞 run（主 run + `async_tasks` 里仍在跑的子 run），**再**删会话注册表（顺序不可反，否则 cancel 会 404）；定时任务下轮照常 fire。

**实现逻辑**：`require_thread` → 查主 run 列表（非终态）→ `POST …/runs/{rid}/cancel?action=interrupt` → 读 `state.async_tasks` 取消子 run → `DELETE /threads/{id}` → 回 cancelled 清单

**入参**：path `thread_id`（UUID）

**出参**

```json
{"ok": true, "thread_id": "...",
 "cancelled": [{"thread_id":"<主或子线程>","run_id":"..."}]}
```

语义：先取消本次在飞 run（含 `async_tasks` 子 run），再删会话；不影响下次定时触发。

**错误**：`400 {"ok":false,"error":"非法的会话 ID"}`、
`401 {"error":"登录已失效，无法删除会话；请重新登录后再试"}`、
`403 {"error":"权限不足：该会话不属于当前账号，无法删除"}`、
`502 {"ok":false,"error":"删除会话失败（HTTP N）" | "删除会话失败：<异常类型>"}`

### `POST /api/threads/{thread_id}/compact`（归属）

**功能**：按 wire 字符量（含 tool_call args）切分消息 → 保留最近 ≥8 条且 ≤12k tokens → 用该账号模型生成摘要 → `RemoveMessage(ALL)` + 摘要 + 保留消息重写 state；收益不足（<5 条或 <2000 tokens）直接 skipped。

**实现逻辑**：取 `messages` → `_msg_wire_chars` 估 token（含 tool_call args）→ `_split_messages`（保留 ≥8 条且 ≤12k）→ 收益护栏（<5 条或 <2000 tokens 则 skipped）→ `_generate_summary`（该账号模型，失败截断降级）→ `RemoveMessage(ALL)+摘要+保留` 写 state

**入参**：path `thread_id`（无 body）

**出参（压缩成功）**

```json
{"ok": true, "summarized_count": 42, "preserved_count": 18, "summary_length": 1280}
```

**出参（收益不足，跳过）**

```json
{"ok": true, "skipped": true, "reason": "压缩收益不足：...", "message_count": 60, "est_gain_tokens": 900}
```

规则：消息 <20 条不压缩；至少保留最近 8 条且 ≤ ~12k tokens；待总结 ≥5 条且预计省 ≥2000 tokens。

**错误**：`400`（非法 thread_id）、`502 {"error":"写入压缩结果失败: ..."}`

### `GET /api/threads/{thread_id}/export`（归属）

**功能**：自调用取 `state.values.messages`，渲染成 Markdown（用户/助手/工具 + 思考折叠块 + SQL 代码块）或原始 JSON，以 `attachment` 流式下载，前端不缓冲内容。

**实现逻辑**：`require_thread` → 自调用取 state → 按 `format` 分支：`_to_markdown` 渲染 / `json.dumps` → `Response` + `Content-Disposition`

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `thread_id` | 是 | 会话 ID |
| query | `format` | 否 | `md`（默认）/ `json` |

**出参**：文件流（`Content-Disposition: attachment`）

- `md` → `session-<tid>.md`：含「深度思考」折叠块、工具调用与 SQL 代码块
- `json` → `session-<tid>.json`：`{thread_id, title, messages}`

**错误**：`400 （format 仅支持 md / json）`、`404 （会话不存在）`、`502 （读取会话失败）`

### `POST /api/threads/{thread_id}/fork`（归属）

**功能**：先 `threads/copy` 整线程复制，若给 `message_id` 则从新到旧翻页定位「该消息为最后一条」的 checkpoint，用 `update_state(as_node="__copy__")` 把 head 回退到该点；失败时清理副本线程。

**实现逻辑**：`require_thread` → `POST /threads/{id}/copy` → `claim_thread` 登记归属 → 有 `message_id` 时翻页 `history` 定位锚点 → `state(as_node="__copy__")` 回退 → `PATCH` 标题；失败时 `DELETE` 副本

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `thread_id` | 是 | 源会话 |
| body | `message_id` | 否 | 分叉锚点；不传 = 整线程复制 |

**出参**

```json
{"ok": true, "thread_id": "<新会话>", "source_thread_id": "...",
 "checkpoint_id": "<锚点 checkpoint 或 null>", "title": "原标题（分叉）"}
```

**错误**：`400 （无效的会话 ID）`、`404 （未找到该消息对应的检查点，无法从此处分叉）`、
`502 （复制/回退失败）`

### `POST /api/threads/{task_id}/cancel`（归属，校验 body 里的主会话）

**功能**：读主线程 `async_tasks[task]` 拿 run_id → 取消子 run（`action=interrupt`）→ 回写终态（重试 3 次 + 保活 sync watcher）；并区分「用户取消」与「发版把 run 带走」（后者写 `terminal_cause=service_restart`）。

**实现逻辑**：`require_thread(main_thread_id)` → 读 `async_tasks[task]` + 子 run 最新状态 → `_terminal_override`（区分重启/取消）→ 中止非终态子 run → `_mark_main_cancelled`（重试 3 次，`as_node="__start__"`）+ 保活 watcher

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `task_id` | 是 | 子任务 id（= 子线程 id） |
| body | `main_thread_id` | 是 | 主会话 thread_id，用于回写 `async_tasks`，并据此校验归属 |

**出参** `{"ok":true,"task_id":"...","main_thread_id":"...","status":"cancelled"}`

行为：读主线程条目 → 取消子 run（`action=interrupt`）→ 回写 `async_tasks[task].status`（重试 + 保活 watcher）。

子 run 已终态时的回写规则：

| 子 run 状态 | 回写结果 |
|---|---|
| `interrupted` 且判定为「发版带走」 | `error` + `terminal_cause=service_restart` + 可读原因 |
| 其他 `interrupted` | `cancelled` |
| 其他终态 | 原样回写 |

## C. SQL 审批（HITL 恢复）

### `POST /api/threads/{thread_id}/sql-approval`（归属 + 库权）

**功能**：先确认子线程确实停在审批 interrupt 上，再把用户决策以 `Command(resume={"decisions":[...]})` 注回子线程恢复执行（approve 执行 / reject 返回拒绝 / edit 用改后 SQL）；随后清除主线程条目的 `awaiting_approval` 并换新 `run_id`。

**实现逻辑**：校验 `main_thread_id`/`decisions`（db_name 做库权校验）→ `_find_pending_interrupt` → `POST /threads/{sub}/runs` 带 `Command(resume=…)` → `_refresh_main_task_entry`（清 `awaiting_approval`、换 `run_id`）

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `thread_id` | 是 | **子会话** id（UUID） |
| body | `main_thread_id` | 是 | 主会话 id（UUID），用于校验归属与刷新进度条目 |
| body | `decisions` | 是 | 非空数组，元素见下表 |
| body | `db_name` | 否 | 恢复 run 的 `configurable.db_name`；传了则做库授权校验 |

`decisions[]` 三种形态：

| type | 必填字段 |
|---|---|
| `approve` | — |
| `reject` | `message`（可选，string） |
| `edit` | `edited_action: {name, args}` |

**出参** `{"ok":true,"thread_id":"<子会话>","main_thread_id":"...","run_id":"<新 run>"}`

**错误**：
`400 {"ok":false,"error":"非法的子会话 ID" | "main_thread_id 缺失或非法" | <decision 校验信息>}`、
`403 {"ok":false,"error":"无权访问数据库: X"}`、
`502 {"ok":false,"error":"恢复执行失败 (HTTP N)"}`

前置条件：子线程必须确实停在审批 interrupt 上；副作用：清 `awaiting_approval`、换新 `run_id`。

## D. 报告文件

### `GET /api/reports`（登录）

**功能**：遍历当前工作区 `report/` 目录，按归属过滤（自己的 + 无记录存量）列出 `.md/.html/.csv/.json` 文件及大小 / 修改时间，倒序。

**实现逻辑**：`require_user` → `report_dir.iterdir()` 过滤后缀 → `_may_read`（`can_read_report`，异常 fail-open）→ 按 mtime 倒序

**入参**：无

**出参**

```json
{"reports": [{"filename":"..._20260914_165606.html","size":12345,"mtime":"2026-09-14T16:56:06+00:00"}],
 "count": 1}
```

只列 `.md` / `.html` / `.csv` / `.json`；按归属过滤（自己的 + 无记录存量），mtime 倒序。

### `GET | HEAD /api/reports/{filename}`（登录 + 归属）

**功能**：文件名白名单 + 解析后仍在 `report/` 内的双保险防穿越；归属不符与不存在返回**同一个 404**（不泄露存在性）。GET 回内容或附件下载，HEAD 只回 `Content-Length` 供前端探测附件按钮。

**实现逻辑**：`require_user` → `_SAFE_FNAME` 校验 → `(report_dir/name).resolve()` 归目录 → 归属不符/不存在同 404 → HEAD 回 `Content-Length`；GET 读字节，`download` 时加 RFC5987 头

**入参**

| 位置 | 字段 | 必填 | 说明 |
|---|---|---|---|
| path | `filename` | 是 | 报告文件名（不含路径分隔符） |
| query | `download` | 否 | `1` / `true` / `yes` → 以附件下载 |

**出参**

| 方法 | 响应 |
|---|---|
| GET | `200` + `text/markdown; charset=utf-8`（下载时 `application/octet-stream` + `Content-Disposition`） |
| HEAD | `200` + `Content-Length`（不返回正文，供前端探测） |
| 不存在/越权 | `404 （报告不存在或非法文件名）`——越权也回 404，不泄露存在性 |

**错误**：`500 （报告读取失败）`
