## Global Constraints

- Python ≥ 3.13，使用 `uv` 管理依赖
- 所有新模块必须有 `__init__.py`，导出明确接口
- 中文注释和日志消息保持不变
- `noqa: BLE001` 仅在兜底 `except Exception as e:` 处使用，且必须配合 `_logger.exception()`
- 不改变现有 API 接口的请求/响应格式
- 不改变 LangGraph 原生路由的行为
- `.env.dev` 不提交 Git

## Review Focus

1. **中间件顺序破坏** — 23 层中间件有部分序约束，重构过程中任何顺序变更都可能导致静默行为错误
2. **守护线程停机丢失** — sync 线程和 eval worker 在进程重启时丢失进度，治理时不能使情况更差
3. **SQLite 并发互踩** — auth SQLite 共享连接 + 全局锁，修改时不能引入死锁
4. **SSE 流断裂** — 中间件改 ASGI 纯管道不能缓冲响应体，否则 `/runs/stream` SSE 中断
5. **内部 HTTP 自调用身份判定** — Docker IP + 无 Cookie 判 internal 的逻辑脆弱，改直连时不能丢失鉴权

## Task 1-2：异常处理治理 — **已完成（处方改写）**

> ⚠️ **修订 v4（2026-10-14 实施后回写）：** v1/v2/v3 的处方是「把 178 处 `except Exception:` 拆成分层 `except (httpx.HTTPError, ...)`」。**实测后判定该处方基本不成立**，本任务改为治理真正存在的两类缺口。以下为改写后的定稿。

### 为什么原处方不成立

逐点打开 TOP 5 的 178 处，几乎全部是这个形状：

```python
try:
    ...
except Exception:  # noqa: BLE001
    _logger.warning("[sync] 取 state 失败: %s", e)
```

它们**已经**是「兜底 + 留痕」的 best-effort 路径——网络抖动、旁路监控、可选字段缺失，语义就是「失败就算了」。把 `except Exception` 换成 `except (httpx.HTTPError, ConnectionError) as e`：

1. **不改变任何运行时行为**——两条支路的处理体都是 log 一行然后继续；
2. **不增加任何信息**——日志文案一个字都没变；
3. **引入误分类风险**——`ValueError` 由被调方内部抛出时（比如 JSON 解码），新分支会把它标成「参数异常」，反而把真因写歪。

更直接的反证：**v1 模板自己就是坏的**——那个 `except Exception:` 后面写着 `_logger.error("[sync] 同步异常: %s", e)`，而 `e` 根本没绑定（没写 `as e`）。这处一并暴露了原处方是从模式想象出来的，不是从代码读出来的。

**结论：Task 1-2 的处方在这里基本不成立。** 真正的缺口是两类：

| 类别 | 症状 | 为什么危险 |
|------|------|-----------|
| ① **完全静默** | `except Exception:` 后直接 `return {}` / `= None` / `= 1`，无任何日志 | 出故障时**零痕迹**，只能靠下游涌现的怪值反推 |
| ② **日志缺异常类型** | `_logger.warning("...失败: %s", e)` | `str(e)` 对 `KeyError`/`ConnectionError` 都是不透明文本，**分不出是环境抖动还是代码 bug** |

```python
"""声明式中间件管道——用 Layer 枚举 + 拓扑排序替代手动排列。"""
from enum import Enum, auto
from dataclasses import dataclass, field
from typing import Any
import logging

_logger = logging.getLogger(__name__)


class Layer(Enum):
    """中间件执行阶段——从外到内。"""
    GUARD = auto()           # 门禁：ModelRequired, QuotaError, ModelTimeout
    TOOL_REGISTRY = auto()   # 工具注入：DynamicMCPTools, ToolFilter
    OBSERVABILITY = auto()   # 观测：TraceRecorder, LangfuseSpan, TokenMeter
    PROGRESS = auto()        # 进度：ProgressTracker, ProgressBoundary, WriteTodos
    CONTEXT = auto()         # 上下文：ThinkingToggle, DbContext, QueryKeywords
    SAFETY = auto()          # 安全：FilesystemThreadGuard, ExecuteGuard, SQLApproval
    OPTIMIZATION = auto()    # 优化：MessageSlimmer, KnowledgeTrim, QueryResultOffload
    GATE = auto()            # 业务门控：CaliberGate, QueryGate, CubeRouteGate, FailureCircuit
    PROMPT = auto()          # 提示词：dynamic_prompt, SkillsMiddleware


@dataclass
class MiddlewareSpec:
    layer: Layer
    name: str
    middleware: Any
    after: list[str] = field(default_factory=list)  # 同层内：必须在这些之后
    before: list[str] = field(default_factory=list) # 同层内：必须在这些之前


def build_chain(specs: list[MiddlewareSpec]) -> list:
    """拓扑排序 → 平坦中间件列表。"""
    # 按 layer 分组，层内按 after/before 约束拓扑排序
    from collections import defaultdict
    by_layer: dict[Layer, list[MiddlewareSpec]] = defaultdict(list)
    for spec in specs:
        by_layer[spec.layer].append(spec)

    result = []
    for layer in Layer:  # 按枚举顺序（外→内）
        layer_specs = by_layer.get(layer, [])
        sorted_specs = _topo_sort(layer_specs)
        result.extend(s.middleware for s in sorted_specs)

    _logger.info("[pipeline] 构建 %d 层中间件链", len(result))
    return result


def _topo_sort(specs: list[MiddlewareSpec]) -> list[MiddlewareSpec]:
    """同层内拓扑排序。检测循环依赖。"""
    name_to_spec = {s.name: s for s in specs}
    in_degree = {s.name: 0 for s in specs}
    adj = {s.name: [] for s in specs}

    for s in specs:
        for dep in s.after:
            if dep in adj:
                adj[dep].append(s.name)
                in_degree[s.name] += 1
        for dep in s.before:
            if dep in adj:
                adj[s.name].append(dep)
                in_degree[dep] += 1

    queue = [name for name, deg in in_degree.items() if deg == 0]
    order = []
    while queue:
        name = queue.pop(0)
        order.append(name)
        for neighbor in adj[name]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)

    if len(order) != len(specs):
        raise ValueError(f"中间件循环依赖检测：{set(s.name for s in specs) - set(order)}")

    return [name_to_spec[name] for name in order]
```

## ~~Task 3-2：MCP 子进程生命周期管理 + 工具缓存池~~ — 无需修复

> **v4 结论（2026-10-14 实施期实测）：不存在子进程泄漏，本节整体作废。**
>
> v3 的根因判断「当前代码库存在子进程泄漏（`MultiServerMCPClient` 创建后未关闭）」是
> **对的观察、错的结论**——「创建后未关闭」为真，但那个对象**不需要关闭，也不持有任何
> 可释放的资源**。五条证据（前三条读码，后两条实测）：

**① `MultiServerMCPClient` 是一个无状态工厂，不是连接持有者。**
实测其 `__dict__` 只有配置项，**没有任何 session / transport / 子进程**：

```
client.__dict__ == ['callbacks', 'connections', 'handle_tool_errors',
                    'tool_interceptors', 'tool_name_prefix']
hasattr(client, 'close') == False
```

**② `get_tools()` 自己开自己的 session 并当场关掉。**
`client.py:166` 的 `get_tools()` 内部走 `load_mcp_tools(None, connection=…)`；
`tools.py:585-594` 在 `session is None` 时执行：

```python
async with create_session(connection, mcp_callbacks=mcp_callbacks) as tool_session:
    await tool_session.initialize()
    tools = await _list_all_tools(tool_session)     # ← 退出 with 即回收子进程
```

即 **`get_tools()` 期间起一个子进程只为枚举工具名，函数返回前就已回收**。

**③ 工具**调用**路径同样是 `async with` 作用域内闭环。**
`tools.py:460-482`：每次 `ainvoke` 都 `async with create_session(...)`，
且异常被捕获到 `captured_exception`、**在 with 之外重抛**（该库为规避 MCP SDK 在断连时
吞异常而特意这么写）——两条路径都由上下文管理器退出时回收。

**④ 把 `create_session` 追到底 = 官方 SDK 的 `stdio_client` 上下文管理器。**
`sessions.py:264-269`：

```python
async with (
    stdio_client(server_params) as (read, write),      # ← MCP SDK：__aexit__ 杀子进程
    ClientSession(read, write, **session_kwargs) as session,
):
    yield session
```

**⑤ 实测：起多少收多少。**
用一个最小 stdio MCP server（启动即落盘 `START <pid>`、`atexit` 落盘 `EXIT <pid>`），
跑「1 次 `get_tools()` + 5 次工具调用 + 3 次 `get_tools()`」：

```
START 行数 = 9      EXIT 行数 = 9      未回收 pid = 0
5 次调用的 pid 各不相同（41392 / 20616 / 3064 / 25452 / 27012）
```

9 = 1 + 5 + 3，与调用次数精确相符，**零泄漏**。

### 因此 v3 的三步都不能做

| v3 步骤 | 为什么不能做 |
|---------|--------------|
| Step 1 `_SubEntry` 加 `_client` 字段 | 没有资源需要持有；存下来反而**误导**后来者以为它在管连接 |
| Step 2 保存 client 引用 | 同上。且 `mcp_tool.py:98` 的 `client` 是 per-server **局部变量**，其生命周期本就只覆盖一次枚举 |
| Step 3 改用 `async with MultiServerMCPClient(...) as client:` | **会当场炸**：`client.py:355-368` 的 `__aenter__`/`__aexit__` 都 `raise NotImplementedError`（该库 0.1.0 起**移除了**上下文管理器支持）。原文「A new session will be created for each tool call」写在 `get_tools()` 的 docstring 里 |

### Step 4-5 的 LRU 也不需要

`_sub_entries` 缓存的是**工具对象**（`_SubEntry.tools: list[BaseTool]`），**不是连接**。
条目数由「配置了几个库」决定，无外部资源需要限额；LRU 淘汰只会把一次慢枚举白白作废
（下次访问得重连、重列工具）。

### 顺带澄清：每次工具调用起一个新子进程，是**设计**不是缺陷

`mcp_tool.py:203-206` 的原文：

> `fingerprint` 只覆盖「变了必须重连 server 才生效」的东西（server 名 + 语义库路径 +
> wren 可执行文件路径）；**连接信息不在其中**——它进的是 Wren profile 文件，**每次工具
> 调用新起的 MCP 子进程会重新读**，所以改密码/换 host 天然即时生效，不需要重载工具。

也就是说「每次调用新起子进程」正是**改密/换 host 免重载**这一特性的实现方式。真要优化
它（比如 Wren 子进程冷启开销），是**换设计**（引入连接池后必须另行解决 profile 变更的
失效问题），属于 Task 4 级别的独立提案，不在本手册范围内。

### 若将来要做，正确的第一个问题不是「怎么关」

而是「**长连接池能承受 profile/凭据变更的失效成本吗**」。先答这个再动代码。

```python
async def _adaptive_poll(self, sub_thread_id: str):
    """自适应轮询：变化时快、稳定时慢。"""
    interval = 0.2       # 初始 200ms
    stable_count = 0
    last_todos_hash = None

    while not self._done:
        state = await self._fetch_subagent_state(sub_thread_id)
        current_hash = _hash_todos(state)

        if current_hash != last_todos_hash:
            # 状态变化 → 快速轮询
            interval = 0.2
            stable_count = 0
            last_todos_hash = current_hash
            await self._sync_to_main(state)
        else:
            # 稳定 → 逐步降频
            stable_count += 1
            interval = min(0.2 + stable_count * 0.1, 2.0)

        # 终态检测（无论是否变化都检查）
        if self._is_terminal(state):
            await self._handle_terminal(state)
            break

        await asyncio.sleep(interval)
```

```python
"""轻量级依赖注入容器。"""
class Container:
    def __init__(self):
        self._singletons: dict[str, Any] = {}
        self._factories: dict[str, callable] = {}

    def register_singleton(self, name: str, instance: Any):
        self._singletons[name] = instance

    def register_factory(self, name: str, factory: callable):
        self._factories[name] = factory

    def resolve(self, name: str) -> Any:
        if name in self._singletons:
            return self._singletons[name]
        if name in self._factories:
            instance = self._factories[name]()
            self._singletons[name] = instance  # 缓存
            return instance
        raise KeyError(f"未注册: {name}")

# 全局容器
_container = Container()

def get_container() -> Container:
    return _container
```
