# 语义库管理模块 UX 优化方案

> 创建时间：2026-08-24
> 状态：方案设计中，待实施

---

## 一、当前实现问题分析

### 1.1 入口设计问题

当前布局：4 个入口平铺，用户认知负担重

```
┌─────────────────────────────────────────────────────────────┐
│ 语义库管理                                                   │
├─────────────────────────────────────────────────────────────┤
│ [+ 新增语义库]        ← 5步向导，门槛高                      │
│ [↓ 从 Git 拉取]       ← 需要 Git 知识                       │
│ [🔗 关联本地目录]     ← 需要知道目录在哪                     │
│                                                              │
│ 语义库列表...                                                │
└─────────────────────────────────────────────────────────────┘
```

**问题**：
- 用户不知道该选哪个入口（决策成本高）
- 每个入口的操作流程割裂
- 缺乏统一的"语义库"概念引导

### 1.2 业务知识填写问题

当前实现：提供模板，但用户需要直接编辑 YAML/MD 文件

**痛点**：
- **语法容易出错**：YAML 缩进、特殊字符处理
- **没有字段提示**：不知道填什么内容，只能看空模板
- **没有结构化表单**：完全自由文本，缺乏引导
- **已有语义库无编辑入口**：创建后无法追加/修改业务知识

### 1.3 列表展示问题

当前实现：简单表格/列表

**问题**：
- 状态信息不直观（来源、构建状态、关联库等需要多处查看）
- 操作入口分散在顶部按钮，不就近

### 4.3 关键设计点

| 设计点 | 方案 |
|--------|------|
| **已有内容处理** | 打开时读取并填充表单，不是覆盖而是编辑 |
| **AI 补充 vs 重新生成** | AI 只生成"新增"内容，不覆盖用户已编辑的部分 |
| **冲突检测** | AI 生成时检测与已有内容是否冲突，提示用户 |
| **保存后操作** | 保存后提示"是否重新构建 MDL"，确保变更生效 |
| **版本历史** | 可选：保存前备份旧文件，支持回滚 |

```python
# GET /api/wren-projects/{name}/knowledge/read
async def read_knowledge(request: Request):
    """读取语义库的业务知识文件，返回结构化数据。"""
    name = request.path_params["name"]
    project = _find_project(name)
    if project is None:
        return json_response({"error": f"语义库 '{name}' 不存在"}, status=404)
    
    result = {
        "glossary": [],       # 从 knowledge/glossary.yml 解析
        "metrics": [],        # 从 knowledge/metrics.yml 解析
        "rules": [],          # 从 knowledge/rules/*.md 解析
        "sql_patterns": [],   # 从 knowledge/sql/*.yml 解析
        "caveats": [],        # 从 knowledge/caveats.yml 解析
    }
    
    # 解析各文件...
    glossary_file = project / "knowledge" / "glossary.yml"
    if glossary_file.exists():
        import yaml
        data = yaml.safe_load(glossary_file.read_text(encoding="utf-8")) or {}
        result["glossary"] = data.get("terms", [])
    
    # ... 其他文件类似
    
    return json_response(result)
```

### 6.3 AI 生成 API

```python
# POST /api/wren-projects/{name}/knowledge/ai-generate
async def ai_generate_knowledge(request: Request):
    """AI 分析数据库结构，生成业务知识草稿（不覆盖已有）。"""
    name = request.path_params["name"]
    data = await parse_body(request)
    scope = data.get("scope", ["glossary", "metrics", "rules", "sql_patterns"])
    industry = data.get("industry", "")  # 可选：行业信息
    notes = data.get("notes", "")        # 可选：额外说明
    
    project = _find_project(name)
    if project is None:
        return json_response({"error": f"语义库 '{name}' 不存在"}, status=404)
    
    # 读取已有知识，避免重复生成
    existing = _read_existing_knowledge(project)
    
    # 获取数据库内省结果
    db_name = _get_associated_db(project)
    cfg = store.get(db_name)
    from agent.utils.db_introspect import introspect_database
    introspect_result = introspect_database(cfg)
    
    # 调用 LLM 生成新内容
    generated = await _ai_generate_knowledge(
        db_type=cfg.db_type,
        db_name=db_name,
        tables=introspect_result.tables,
        foreign_keys=introspect_result.foreign_keys,
        scope=scope,
        existing=existing,
        industry=industry,
        notes=notes,
    )
    
    return json_response({
        "ok": True,
        "generated": generated,  # 新增的内容
        "conflicts": [],         # 与已有内容冲突的项（让用户决定）
    })
```

## 七、数据结构定义

### 7.1 TypeScript 类型

```typescript
// 词汇表
interface GlossaryTerm {
  name: string;           // 术语名称
  definition: string;     // 定义
  synonyms: string[];     // 同义词
  relatedTables: string[]; // 相关表
}

// 指标
interface Metric {
  name: string;           // 指标名称
  displayName: string;    // 展示名
  type: 'sum' | 'count' | 'count_distinct' | 'avg' | 'max' | 'min';
  expression: string;     // SQL 表达式
  dimensions: string[];   // 维度
  description: string;    // 描述
}

// 业务规则
interface Rule {
  name: string;           // 规则名
  category: 'general' | 'filter' | 'calculation' | 'permission';
  description: string;    // 规则描述
  scope: 'global' | 'tables';
  tables?: string[];      // 适用表（scope=tables 时）
}

// SQL 模式
interface SqlPattern {
  name: string;           // 名称
  questions: string[];    // 适用问题
  template: string;       // SQL 模板
  parameters: {
    name: string;
    type: string;
    default: string;
  }[];
}

// 注意事项
interface Caveat {
  title: string;          // 标题
  severity: 'important' | 'normal' | 'tip';
  description: string;    // 描述
  correctExample: string; // 正确写法
  wrongExample: string;   // 错误写法
}

// 编辑器状态
interface KnowledgeEditorState {
  glossary: GlossaryTerm[];
  metrics: Metric[];
  rules: Rule[];
  sqlPatterns: SqlPattern[];
  caveats: Caveat[];
  
  isDirty: boolean;
  changedSections: Set<string>;
  
  aiGenerating: boolean;
  aiSuggestions: Partial<KnowledgeData>;
}
```
