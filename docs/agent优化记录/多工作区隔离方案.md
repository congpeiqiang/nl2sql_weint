# NL2SQL 多工作区隔离方案

> 实施日期：2026-08-20 | 状态：已完成并验证

## 目标

生产环境用户可在 UI 新建空目录作为工作区，适配其他项目的目录结构。不同工作区隔离中间数据/报告；共享 memory、skills；db_config、语义库、feedback、checkpoint 按工作区隔离。

## 隔离矩阵

| 按工作区隔离 | 全局共享 |
|---|---|
| `db_config.json` | `memory/` |
| `model_config.json`（可选覆盖） | `skills/` |
| `checkpoint/` | |
| `feedback/` | |
| `semantic/`（Wren 项目） | |
| `report/` | |
| `tmp/` | |
| `nl2sql_process_data/` | |
| `large_tool_results/` | |

## 关键实现细节

- **WorkspaceManager** 单例统一路径解析，替换所有 `Path(__file__).resolve().parents[N]` 硬编码
- `workspace_manager/__init__.py` 重导出 `get_workspace_manager`、`WorkspaceManager`，17 个文件无需修改 import
- 所有 `get_store()` 函数追踪工作区路径，切换时自动重建 store
- 默认工作区 = `src/agent/workspace/`，零配置回退，兼容现有部署
- 活跃工作区切换即时生效（DynamicFilesystemBackend 每次操作前重新解析 root_dir）
- `langgraph.json` / `graph.json` 中 graph 路径指向 `graphs/` 和 `checkpoint/` 子目录

## API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/workspaces` | 列表（含活跃标记） |
| POST | `/api/workspaces` | 注册新工作区 |
| PUT | `/api/workspaces/{name}/activate` | 切换活跃工作区 |
| DELETE | `/api/workspaces/{name}` | 取消注册 |
| GET | `/api/workspaces/active` | 获取当前活跃信息 |

## VFS 复合后端

`main_agent` 和 `nl2sql_agent` 同构，使用 `CompositeBackend` 最长前缀匹配：

```
CompositeBackend
├── /workspace/memory/  → shared_memory_backend (共享)
├── /workspace/skills/  → shared_skills_backend (共享)
├── /workspace/         → workspace_data_backend (当前工作区)
└── /                   → shared_code_backend (代码只读)
```
