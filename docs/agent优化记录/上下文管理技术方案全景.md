# NL2SQL 上下文管理技术方案全景

**日期**：2026-08-19
**摘要**：本文档系统梳理当前 NL2SQL 系统中所有与上下文窗口管理相关的技术方案，涵盖消息瘦身、检查点管理、中间件、Token 计量、记忆文件、对话历史管理等维度。

---

## 一、消息瘦身（Message Slimming）

### 1.1 超大 Tool 结果截断

- **文件**：[message_slimmer.py](../src/agent/middlewares/message_slimmer.py)
- **触发**：每次工具调用返回的 ToolMessage
- **机制**：工具结果文本超过 16000 字符时，将完整内容落盘到 `workspace/large_tool_results/<tool_call_id>`，消息内只保留 head+tail 预览 + 路径指针。防止单个大结果（如 73KB 的 `read_file`）占据 checkpoint 大部分空间。
- **安全设计**：fail-open，落盘失败保留原消息不阻断

### 1.2 Tool 结果去重

- **文件**：[message_slimmer.py](../src/agent/middlewares/message_slimmer.py)
- **触发**：每次工具调用返回的 ToolMessage
- **机制**：对 ToolMessage 文本内容做 MD5 哈希，与线程内历史 ToolMessage 比较。完全重复时替换为小占位文本（引用首次出现的 `tool_call_id`），保留 `tool_call_id`/`name`/`id`，LangGraph 工具配对与前端步骤推导不受影响。
- **典型场景**：2×14KB `write_todos` 结果、2×8.8KB SKILL.md 读取

## 二、检查点管理（Checkpoint Management）

### 2.1 AsyncSqliteSaver 持久化

- **文件**：[checkpointer_factory.py](../src/agent/checkpointer_factory.py)
- **触发**：每次状态变更
- **机制**：基于 `langgraph.checkpoint.sqlite.aio.AsyncSqliteSaver`，将 checkpoint 持久化到 `checkpoints.sqlite`。通过 `langgraph.json` 配置 `checkpointer` 字段加载。

### 2.2 自定义 State Schema 与 Reducer

- **文件**：[main_agent.py](../src/agent/main_agent.py)（MainAgentState）
- **触发**：每次状态更新
- **机制**：自定义 `MainAgentState` 扩展 `DeepAgentState`，关键字段使用 `_merge_dict_by_key` reducer 按 task_id 合并，并发多查询场景下防止多线程写入互相覆盖。字段包括：
  - `query_headers`：`Annotated[dict[str, dict], _merge_dict_by_key]`
  - `subagent_steps_map`：`Annotated[dict[str, list], _merge_dict_by_key]`
  - `active_queries`：`Annotated[dict[str, bool], _merge_dict_by_key]`
  - `token_stats`：`Annotated[dict, _accumulate_token_stats]`（累积型，保留最近 50 步）

### 2.3 ECharts SVG/HTML 落盘（避免上下文携带大体积内容）

- **文件**：[path_resolver.py](../src/agent/utils/path_resolver.py)
- **触发**：每次图表生成
- **机制**：
  - **SVG**：自动保存到 `/workspace/report/`，消息内返回小型 iframe 内联渲染
  - **HTML**：使用 CDN 加载 echarts.js（jsdelivr + unpkg fallback），option JSON 注入模板，避免内联 1.1MB echarts 库

## 三、中间件层上下文管理

### 3.1 QueryKeywordsMiddleware — 动态关键词注入

- **文件**：[query_keywords.py](../src/agent/middlewares/query_keywords.py)
- **触发**：每次模型调用
- **机制**：从 `configurable.query_keywords` 读取前端传入的关键词，注入到主智能体系统提示词中，替换 `【数据查询】触发关键词` 行，确保 LLM 与前端使用同一份意图识别关键词。

### 3.2 ThinkingToggleMiddleware — 动态模型切换

- **文件**：[thinking_toggle.py](../src/agent/middlewares/thinking_toggle.py)
- **触发**：每次模型调用
- **机制**：根据 `configurable.enable_thinking` / `llm_route` / `llm_model` 动态重建模型实例，支持前端 Composer 切换模型而不重启后端。

### 3.3 CurrentDbContextMiddleware — 数据库名注入

- **文件**：[current_db_context.py](../src/agent/middlewares/current_db_context.py)
- **触发**：每次模型调用（最新消息为 HumanMessage 时）
- **机制**：在最新 HumanMessage 前追加 `【当前数据库：{db_name}】`，作为最高优先级信号，防止 LLM 被对话历史中过时的库名误导（切库后仍按旧库委派）。

### 3.4 dynamic_prompt — 系统提示词动态注入

- **文件**：[main_agent.py](../src/agent/main_agent.py)
- **触发**：每次模型调用
- **机制**：使用 `@dynamic_prompt` 装饰器，在系统提示词开头追加"最高优先级"数据库名段：`"无论对话历史或总结中如何描述数据库，一律以本段为准"`。与 CurrentDbContextMiddleware 形成双重防御。

### 3.5 WriteTodosProtocolMiddleware — 进度追踪协议

- **文件**：[write_todos.py](../src/agent/middlewares/write_todos.py)
- **触发**：每次子智能体模型调用
- **机制**：追加 `write_todos` 分级使用指引到子智能体系统提示词末尾。策略 A/C（复杂查询）强制，策略 B（快速通道）可跳过。禁止为"了解流程"而读取 SKILL.md。

### 3.6 TokenMeterMiddleware — Token 用量采集

- **文件**：[token_meter.py](../src/agent/middlewares/token_meter.py)
- **触发**：每次 LLM 调用
- **机制**：采集 `input_tokens`、`output_tokens`、`cache_read_tokens`、`reasoning_tokens` 和 wall-clock 耗时，写入 state 的 `token_stats` 字段。State 使用 `_accumulate_token_stats` reducer 做累积求和，保留最近 50 步防止 bloat。

### 3.7 SQL Approval Middleware — 人机协作审批

- **文件**：[sql_approval.py](../src/agent/middlewares/sql_approval.py)
- **触发**：写/DDL 类 SQL 执行（run_sql 工具）
- **机制**：基于 `HumanInTheLoopMiddleware`，`classify_sql()` 判断 SQL 类型，INSERT/UPDATE/DELETE/DROP/ALTER 等触发 interrupt。前端渲染审批卡，用户确认后继续。前端策略开关 `sql_approval_policy` 可控制行为。

### 3.8 SkillDataMiddleware — 技能数据持久化

- **文件**：[skill_data.py](../src/agent/middlewares/skill_data.py)
- **触发**：技能调用 save/load 操作
- **机制**：按 `thread_id` 在 `/workspace/nl2sql_process_data/{thread_id}/` 下持久化技能输出数据，避免通过 LLM 上下文传递大量中间数据。

### 3.9 DeepAgents Async Config Patch — 配置透传

- **文件**：[deepagents_async_config_patch.py](../src/agent/middlewares/deepagents_async_config_patch.py)
- **触发**：子智能体创建时（模块导入时 monkey-patch）
- **机制**：修补 `_ClientCache.get_sync/get_async`，向异步子 agent 的 run 转发父 run 的 `configurable`（db_name/query_keywords 等），过滤掉 `__pregel_*`/`langgraph_*` 内部键。

## 六、对话历史管理

### 6.1 增量读取（since/cursor）

- **文件**：[check_progress.py](../src/agent/subagents/check_progress.py)
- **触发**：`check_async_task` 传 `since` 参数时
- **机制**：可选的 `since` cursor 参数实现增量读取子线程消息。`_add_incremental` 计算 `cursor = len(messages)`，返回 `messages[since:]`，每条截断到 800 字符，最多 20 条。避免全量返回消息历史。

### 6.2 进度摘要提取

- **文件**：[check_progress.py](../src/agent/subagents/check_progress.py)（`_extract_progress`）
- **触发**：每次 `check_async_task` 调用
- **机制**：从子线程消息中提取紧凑进度摘要：todo 列表、完成百分比、步骤耗时、当前步骤、最新工具调用、最新 AI 思考。避免将完整消息历史灌入主智能体上下文。

### 6.3 read_file 全量补丁

- **文件**：[check_progress.py](../src/agent/subagents/check_progress.py)（`apply_read_file_patch`）
- **触发**：模块导入时
- **机制**：将 `read_file` 默认 limit 从 100 行改为 99999 行，防止 LLM 多次调用 `read_file` 读取同一文件，减少历史消息膨胀。

### 6.4 子智能体状态镜像（Sync Thread）

- **文件**：[sync_subagent_todos.py](../src/agent/subagents/sync_subagent_todos.py)
- **触发**：`start_async_task` 后自动启动，持续运行至子任务结束
- **机制**：守护线程每 0.5s 轮询子线程状态，将子智能体进度（含耗时）镜像写入主智能体 state 的 `subagent_steps_map[task_id]`。主智能体无需反复调用 `check_async_task` 即可获知进度。关键设计：
  - 进程级 `threading.Lock` 串行化并发 `update_state` 调用
  - 终态回退检测：每 4 周期检查终态是否被 auto-continue run 覆盖
  - 10 秒 grace period 后清理子智能体进度

### 6.5 Sync 自动启动

- **文件**：[sync_launcher.py](../src/agent/subagents/sync_launcher.py)
- **触发**：每次 `start_async_task` 调用
- **机制**：monkey-patch deepagents 的 `_build_start_tool`，在 `start_async_task` 返回后自动提取 `main_thread_id`/`sub_thread_id` 并调用 `launch_sync()`。

### 6.6 本地进度追踪

- **文件**：[track_progress.py](../src/agent/subagents/track_progress.py)
- **触发**：每次子智能体模型调用
- **机制**：扫描消息历史中最新 `write_todos` ToolMessage，提取 todo 列表，对比上次状态记录状态转换（pending→in_progress→completed）及时间戳，写入 `%TEMP%/nl2sql_progress/{thread_id}.json`。供 `check_progress.py` 计算步骤耗时。

### 6.7 反馈存储

- **文件**：[feedback/store.py](../src/agent/feedback/store.py)
- **触发**：用户通过前端反馈 API 评分
- **机制**：SQLite + WAL 模式存储 `(thread_id, message_id)` 的正/负反馈，含 `question` 和 `sql` 快照。不进入 LangGraph state，避免污染 LLM 上下文。

## 七、其他上下文相关技术

### 7.1 工具超时保护

- **文件**：[path_resolver.py](../src/agent/utils/path_resolver.py)
- **触发**：每次工具调用
- **机制**：`wrap_tool()` 为每个工具设置超时上限——`run_sql` 300s、文件工具 60s、默认 120s。超时返回友好错误消息而非崩溃，防止上下文"卡住"。

### 7.2 ECharts 轻量化 HTML

- **文件**：[path_resolver.py](../src/agent/utils/path_resolver.py)
- **触发**：每次 ECharts 图表生成（`outputType="option"`）
- **机制**：`_build_echarts_html()` 将 option JSON 注入 CDN 模板，返回小型 iframe（几 KB vs 内联 1.1MB echarts 库）。

### 7.3 Windows 路径补丁

- **文件**：[filesystem_backend_patch.py](../src/agent/utils/filesystem_backend_patch.py)
- **触发**：模块导入时
- **机制**：修复 Windows `\\?\` 扩展长度前缀在 `FilesystemBackend._resolve_path` 中的不一致，防止误报越界错误导致 agent 崩溃丢上下文。

### 7.4 模型配置存储

- **文件**：[model_config_store.py](../src/agent/settings/model_config_store.py)
- **触发**：配置读写
- **机制**：JSON 文件 + AES-256-GCM 加密 API Key + 原子写入（`tempfile` + `os.replace`）。每模型含 `context_window`/`max_tokens`。前端可 CRUD 无需重启。

### 7.5 自定义沙箱后端

- **文件**：[custom_opensandbox.py](../src/agent/backends/custom_opensandbox.py)
- **触发**：代码执行时
- **机制**：基于 OpenSandbox 的隔离执行环境，代码执行结果作为消息返回，与上下文管理间接相关。
