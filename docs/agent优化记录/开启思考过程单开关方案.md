# 开启思考过程单开关方案

> 2026-08-14 · 状态：已实施并验证

## 背景与需求

用户希望前端一个开关同时控制「模型思考」与「思考展示」，1:1 映射：

- **开** → 后端真正开启模型思考（reasoning_content 流出）且前端展示思考块；
- **关** → 后端关闭思考（模型直接回答、更快更省）且前端不显示思考块。

为此**移除**之前独立的「显示思考过程」（showThinking）开关——它只控制前端显隐、后端永远在思考，省不了成本。

需求本质是把"展示开关"升级为"后端真实开关"，前端一个开关贯穿前后端。

## 核心机制

### 为什么能 per-run 换模型（关键架构事实）

- 后端模型在 import 时绑定进编译图（`create_deep_agent(model=deepseek_model, ...)`，图只建一次），`create_deep_agent` 只收 `str | BaseChatModel | None`，**不支持 callable 动态解析**。
- 但 langchain 的 agent 工厂在**执行时才**从 `request.model` 派生最终调用模型：`_execute_model_sync(request)` 内部 `request.model.bind_tools(final_tools, **model_settings)`（langchain/agents/factory.py）。
- 因此中间件在 `wrap_model_call(request, handler)` 里**替换 `request.model`**，工具绑定/响应格式等绑定发生在替换之后，**不受影响**。`ModelRequest` 是可变 dataclass，提供 `override(model=...)`。

### 为什么不能 `.bind()` 只给 ChatQwen 换思考

ChatQwen 的思考开关 `enable_thinking` 是 **pydantic 字段**，经 `_default_params` 懒注入 `extra_body`（langchain_qwq/chat_models.py:823-846）。若 `.bind(enable_thinking=...)` 会作为顶层 payload key 发出（base.py:1777 `payload={**self._default_params, **kwargs}`），OpenAI client 不认。**必须重建 ChatQwen 实例**传入构造参数。因此中间件走 `create_model(enable_thinking=...)` 工厂重建。

### 两个供应商的思考开关（均实测生效）

| 供应商 | 开关字段 | 请求体形式 |
|--------|---------|-----------|
| DeepSeek（ChatDeepSeek） | `extra_body={"thinking": {"type": "enabled"/"disabled"}}` | 嵌套 dict |
| Qwen（ChatQwen） | `enable_thinking=True/False`（构造参数） | 顶层布尔 `"enable_thinking"` |

默认值（不传开关）= 两模型默认思考开。

## 链路

1. **前端**：设置弹窗「开启思考过程」开关 → localStorage `enableThinking`（默认 true）。
2. **前端**：每次 run 把 `enable_thinking: "true"/"false"` 注入 `config.configurable`（与 query_keywords / db_name 同通道，useChat.ts:688-697）。
3. **后端**：`ThinkingToggleMiddleware.wrap_model_call` 读 `configurable.enable_thinking`（必须走 `langgraph.config.get_config()`，`request.runtime.config` 恒空），存在时 `create_model(enable_thinking=bool)` 重建模型并 `override(model=...)`；缺失时不动（走 import 默认）。
4. **模型层**：qwen → ChatQwen 捕获 `delta.reasoning_content` 进 `additional_kwargs`；deepseek → ChatDeepSeek 原生捕获。
5. **前端展示**：ChatMessage 去掉显示门控，ThinkingBlock 纯靠 `message.additional_kwargs.reasoning_content` 是否到达渲染——关思考时后端不产 reasoning，前端自然不显示，**1:1 映射天然成立**。

1. **py_compile**：model.py / thinking_toggle.py / main_agent.py 通过。

3. **tsc --noEmit**：本次改动文件 0 报错（其余存量 `@ts-expect-error` / `artifact` 非本次引入）。

   | enable_thinking | reasoning_len | content_len | 判定 |

   | `"true"`（开） | 159（逐 token） | 215 | ✅ 有思考 |

   开思考时正文前多 ~3s 思考期（符合预期）。

   注：messages 事件里 ai 分片 `type` 是类名 `AIMessageChunk`（非 `ai`），验证脚本须同时接受两种取值。

5. 浏览器视觉确认（思考块实时滚动 + 完成自动折叠 + 开关显隐）由用户实测。

## 已知局限

- **作用于下一次 run**：开关改配置后，当前正在跑的 run 不受影响。
- **子 agent 不覆盖**：nl2sql 异步子 agent 是独立图/独立模型，其思考不进主流（沿用现有架构局限）；主 agent 最终回复的思考才由本开关控制。
- **历史消息**：开思考时生成的回答，其思考块已持久化进 checkpoint，关掉开关后历史消息仍显示思考块（折叠态，可点开），属预期。
