# 报告内嵌交互式图表方案

> 日期：2026-08-11
> 状态：已实施并实证验证
> 涉及项目：nl2sql 后端 (`D:\code_work_space\llm\nl2sql`) + 前端 (`D:\code_work_space\llm\huice\008\harness-deep-agents-ui`)
> 现象：生成的报告 Markdown 里嵌入的 echarts 图表未正常渲染

---

## 1. 问题

生成的报告（如 `各类型作品数量分布_2026-08-11_09-54-00.md`）附录里写的是：

```markdown
### 图表
![各类型作品数量分布](./各类型作品数量分布_20260811_095356.html)
```

**根因**：用 Markdown **图片语法**引用一个 `.html` 文件。图片语法只能渲染位图（jpg/png），渲染不了 HTML 文件，
所以 VS Code / Typora / 聊天前端里都显示为坏图（或死链"打开图表"按钮）。

## 2. 关键洞察

`generate_echarts`（`outputType=option`）工具返回的**就是一个自包含的可交互图表**——
`<iframe src="data:text/html;base64,...">`。base64 里是完整 echarts 页面（echarts.js + 数据 + 配置），
浏览器 / markdown 预览器直接执行即可交互（悬停 tooltip、缩放、图例切换）。

所以解决方案是：**报告附录直接内嵌这个 iframe，而不是用图片语法引用外部 .html 文件。**
一个载体（`data:text/html;base64` iframe）同时满足报告文件与前端聊天两处交互渲染，不引入任何新机制。

## 3. 解决方案

### 3.1 报告文件 — 附录内嵌可交互 iframe（前端零改动）

改 prompt/skill 规范（`report-export` 技能 + `echarts.md` + 主 prompt），让报告附录内嵌工具返回的 iframe：

```markdown
### 图表
{generate_echarts 工具返回的完整 <iframe> 标签，原样粘贴、一字不改}

> 💡 可交互图表：鼠标悬停查看数值、可缩放。
> 图表文件（可分享）：/workspace/report/<图表文件名>.html
```

- **iframe 必须原样复制**工具返回的完整标签（含 src 的 base64 和 height），禁止手写 base64、禁止只取 src。
- 若工具返回 `<img>`（png）或 SVG，说明没用 `outputType=option`，需重跑。

### 3.2 前端聊天 — 复用既有 `chartAttachmentHtml` 机制

前端**零改动**。`ChatInterface` 扫描消息/工具结果里的交互 iframe → 附到报告消息上方 →
`ChatMessage` 渲染。`generate_echarts` 本就在 `chartToolNames` 里，工具结果正是该 iframe，天然命中。

### 3.3 明确不做

- **不加 `rehype-raw`**（react-markdown）：会让任意 AI 生成的原始 HTML 进 DOM，XSS 风险；
  且会让聊天正文里的 base64 iframe 被重复渲染。
- **不加文件服务路由**（`/api/report/...`）：iframe 自包含，浏览器直接渲染，无需 HTTP 文件端点。
