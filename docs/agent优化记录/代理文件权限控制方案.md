# 代理文件读写安全控制方案（deepagents FilesystemPermission）

> 日期：2026-08-12
> 状态：已实施并验证（规则模块 + 两处 agent 接线完成；单元断言/启动门槛直测/E2E 全部通过）
> 涉及项目：nl2sql 后端（`D:\code_work_space\llm\nl2sql`），主 agent（chat_agent）与子 agent（nl2sql_agent），前端不涉及
> 相关机制：deepagents 0.6.12 `FilesystemPermission`（VFS 声明式权限）

---

## 1. 背景与目标

主 agent 与子 agent 都由 `create_deep_agent` 构建，deepagents 自动注入 6 个文件工具
（`ls / read_file / write_file / edit_file / glob / grep`，主 agent 另有 `execute`），但此前**从未传过
`permissions` 参数——文件读写全放行**，agent 可随意改写 `src/agent` 下的提示词/技能/记忆等代码与配置。

**目标**：基于 deepagents 的 `FilesystemPermission` 声明式权限规则（虚拟文件系统），约束 agent：
- **只读**：`D:\code_work_space\llm\nl2sql`（agent 侧实际映射为 VFS 根 `src/agent`，见 §3）
- **可读写**：仅 `src/agent\workspace\{report,tmp,nl2sql_process_data}` 三个子目录

零新增依赖、不改 langgraph/deepagents 源码、不改前端。

## 2. 已确认的设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| VFS 根作用域 | **保持 `src/agent`**（不重设到项目根） | agent 可读面 = `src/agent` 全部（其实际需要的那部分）；根外（`.env` 含 DeepSeek 密钥、`docs`、`src/mcp_server`、`.venv`）由 `virtual_mode=True` 路径锚定天然不可达，更安全；三个可写目录与虚拟路径 1:1 映射，改动最小 |
| `execute` 绕过 | **保留并记录为已知局限** | deepagents 框架明确不支持 execute 的权限控制；提示词里 execute 仅一个失效的 mkdir 兜底，实际使用面小 |

## 3. 需求路径 → VFS 映射

VFS 根 = `D:\code_work_space\llm\nl2sql\src\agent`（`FilesystemBackend(root_dir=src/agent, virtual_mode=True)`）：

| 真实路径 | 虚拟路径 | 权限 |
|---|---|---|
| `D:\code_work_space\llm\nl2sql\src\agent`（整棵，含 prompt/skills/memory/workspace） | `/` | 只读 |
| `...\src\agent\workspace\report` | `/workspace/report/**` | 可读写 |
| `...\src\agent\workspace\tmp` | `/workspace/tmp/**` | 可读写 |
| `...\src\agent\workspace\nl2sql_process_data` | `/workspace/nl2sql_process_data/**` | 可读写 |

## 4. 权限规则（核心实现）

`src/agent/settings/file_permissions.py`（单一事实来源，两处 agent 共用）：

```python
from deepagents import FilesystemPermission

FILE_PERMISSIONS: list[FilesystemPermission] = [
    # 1) 只读整个 VFS 根（显式声明；当前默认 allow 等价，防御默认值变化）
    FilesystemPermission(operations=["read"], paths=["/**"], mode="allow"),
    # 2) 仅这三个 workspace 子目录可写
    FilesystemPermission(operations=["write"], paths=[
        "/workspace/report/**",
        "/workspace/tmp/**",
        "/workspace/nl2sql_process_data/**",
    ], mode="allow"),
    # 3) 其余路径写操作一律拒绝（default allow → 必须显式 deny 兜底）
    FilesystemPermission(operations=["write"], paths=["/**"], mode="deny"),
]
```

**顺序敏感**：deepagents `_check_fs_permission` 按声明顺序首条命中即胜、无命中默认放行——
必须「先 allow 三个写目录、再 deny /** 兜底」，顺序颠倒会导致三个目录也写不了。

## 5. 接入点

- 主 agent：[`src/agent/main_agent.py`](../../src/agent/main_agent.py) 的 `create_deep_agent(...)` 加 `permissions=FILE_PERMISSIONS`
- 子 agent：[`src/agent/nl2sql_agent.py`](../../src/agent/nl2sql_agent.py) 的 `create_deep_agent(...)` 同样加（**独立 graph，不会自动继承**主 agent 权限，必须单独传）

## 6. 机制依据（deepagents 0.6.12，已探明）

- `FilesystemPermission` dataclass（`operations ∈ read|write`，`edit_file` 归 write、`ls/glob/grep` 归 read；`paths` 为 `/` 开头的 glob）：`.venv/Lib/site-packages/deepagents/middleware/filesystem.py:90`
- 解析：声明顺序、首条命中、无命中放行：`filesystem.py:127`
- 权限在**工具层**校验（read/write 各 sync+async 一处）：`filesystem.py:976/1015/1168/1195/1235/1274/1329/1371/1422/1518/1600/1643`
- 注入：`create_deep_agent(permissions=...)` → `FilesystemMiddleware(_permissions=...)`：`graph.py:269`
- **启动门槛**：对「支持执行的后端 + 权限」有 `NotImplementedError` 前置校验（`filesystem.py:863-875`）。主 agent 的 `CompositeBackend(routes={"/": file_backend})` 因所有规则路径以 `/` 开头通过 `_all_paths_scoped_to_routes`（`filesystem.py:158`）；子 agent 后端不支持执行，条件整体为 False——两者均不触发（已用真实配置直测通过）。

## 7. 已知局限（本次不解决，已记录）

- **`execute` 不受权限控制**：主 agent shell 沙箱在 `workspace` 下，可读写 workspace 内任意位置（memory/skills/checkpoint 等），绕过「仅 3 目录可写」。保留并记录（见 §2）。
- **进程内直接写盘不走文件工具**：图表落盘（`src/agent/utils/path_resolver.py`）、skill_data（`src/agent/middlewares/skill_data.py`）、大结果落盘（`message_slimmer.py` → `/large_tool_results`）不经 `_check_fs_permission`。其中图表落盘与 skill_data 恰好落在允许的 report/nl2sql_process_data 内，无冲突；`large_tool_results` 属框架内部 offload，不拦也不破坏。
- **MCP 工具非文件工具**：`dbmcp_run_sql`（可执行任意 SQL）与图表 MCP 是独立写通道，不在文件权限模型内（如需控 DB 写需另行设计）。

2. **启动门槛直测**（已通过）：`d:\tmp\check_fs_gate.py` 用主/子 agent 真实后端配置构造 `FilesystemMiddleware`，无 NotImplementedError，7 工具正常挂载。

   - 子 agent 委派、图表落盘 report 等既有流程无回归（2026 启动日志无异常，前端正常轮询）

删除两处 `permissions=FILE_PERMISSIONS` 参数（或删除整个 `file_permissions.py`），重启 2026 即回到全放行。
