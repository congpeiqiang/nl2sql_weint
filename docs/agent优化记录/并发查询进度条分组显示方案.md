## 1. 背景与问题

并发查询的进度条在**长时间、多任务**场景下有两个体验问题：

| 问题 | 现象 |
|------|------|
| **进度条过长** | 每个查询任务一行（含全部步骤），查询多了（几十个）进度条无限变长，淹没主界面 |
| **看不到子任务状态** | 主智能体进度条（委派/图表/报告）和子任务步骤（knowledge-loader → run_sql）分属两块，无法直观看到"子任务执行到哪一步、多少比例" |

## 2. 方案设计（4 层分组）

进度条高度 = **运行中任务数 + 最近完成几个 + 1 行历史汇总**，与查询总数无关。

| 层 | 任务类型 | 显示策略 |
|----|---------|---------|
| 1 | **运行中**（running） | 完整卡片：标题 + 整体进度条（百分比）+ 子步骤 |
| 2 | **最近完成**（最近 3 个 success/error） | 单行（✓ 标题 + 耗时），可点击展开步骤 |
| 3 | **历史已完成**（早于最近 3 个） | 汇总一行"✅ 已完成 N 个查询"，点击展开列表 |
| 4 | **主步骤 + 子步骤统一** | 同卡片内：主智能体 3 步（委派/图表/报告）+ 子任务 6-7 步合并展示 |

### 2.1 最终形态

```
# 层1：运行中任务（完整卡片，含进度条）
📋 查询每个类型中评分最高的电影      [进行中]  5/6  ▓▓▓▓▓░░░░ 83%
│ 委派 nl2sql        ✓
│   schema-linking   ✓  (45s)
│   subproblem       ◐  (当前)
│   sql-generation   ○
│ 推荐并渲染图表      (待处理)
│ 生成分析报告        (待处理)

# 层2：最近完成（单行，可展开）
📋 查询职业生涯跨度最长的演员        [已完成]  ✓  (2m15s)  ▸

# 层3：历史汇总（替代逐条列出）
✅ 已完成 25 个查询 · 点击查看   ▸
```

## 3. 实现要点（`src/app/components/ChatInterface.tsx`）

### 3.1 分组计算

```tsx
const runningTasks = queryTasks.filter((t) => t.status === "running");
const doneTasks = queryTasks.filter((t) => t.status !== "running");
const recentDone = doneTasks.slice(0, 3);   // 最近完成的 3 个
const historyTasks = doneTasks.slice(3);    // 更早的历史
```

- `queryTasks` 已按 `created_at` 降序（最新置顶），所以 `slice(0,3)` 取的是**最近完成**的 3 个
- running 任务天然在列表最前（最新发起的）

### 3.2 进度条（层1）

```tsx
const progressOf = (qt) => {
  const done = qt.steps.filter((s) => s.status === "completed").length;
  return Math.round((done / qt.steps.length) * 100);
};
// 渲染：标题 + "进行中 X/Y" + 迷你进度条（div 宽度百分比）+ 子步骤
```

### 3.3 展开控制

```tsx
const [expandedTaskIds, setExpandedTaskIds] = useState<Set<string>>(new Set());
const [historyOpen, setHistoryOpen] = useState(false);
// running 任务默认展开；已完成任务点击展开/收起
const isExpanded = (taskId) => expandedTaskIds.has(taskId) || runningTasks.some((t) => t.task_id === taskId);
```

## 4. 数据源（沿用并发查询方案）

- **标题**：前端从消息提取（`polledTaskTitles`，task_id → 问题）
- **进度（steps）**：子线程 todos（稳定）+ steps_map 耗时增强
- **状态**：`active_queries[id]===true` → running，否则 `async_tasks[id].status`

## 5. 验证

1. 发 1 个查询 → 运行中卡片显示完整步骤 + 进度条
2. 发多个查询 → 运行中的完整显示，已完成的折叠单行
3. 发 5+ 个查询 → 最早的历史收进"✅ 已完成 N 个查询"汇总行
4. 点击已完成单行 → 展开步骤；点击历史汇总 → 展开列表
5. 进度条高度随"运行中数 + 常数"增长，不随历史总量增长

## 6. 边界 / 后续可优化

- **最近完成数量**（当前 3 个）可配置，调节"单行保留多少最近完成"
- **历史汇总**展开后的列表也可加滚动限制（任务极多时）
- 层4（主步骤 + 子步骤统一）当前是**概念上合并**（running 卡片含子步骤），
  如需把主智能体的"委派/图表/报告"状态也并入卡片内，需后端把主 todos 与任务关联
