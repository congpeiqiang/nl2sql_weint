## 1. 产品概述

### 1.1 产品定位

NL2SQL 多智能体数据查询与分析系统是一款面向企业数据分析场景的智能体产品。用户通过自然语言对话即可完成从数据查询、可视化图表到分析报告的全链路自动化，无需掌握 SQL 语法或数据分析工具。

### 1.2 核心价值

| 价值维度 | 说明 |
|---------|------|
| **降低数据查询门槛** | 自然语言输入，系统自动理解业务语义并生成精确 SQL |
| **提升分析效率** | 结构化推理 + 多策略路由，复杂查询准确率高 |
| **全链路自动化** | 查询 → 图表推荐 → 图表渲染 → 报告生成，用户零操作 |
| **透明可控** | 实时进度追踪，每步执行状态与耗时可视化 |
| **数据安全** | 私有化部署，数据不出内网 |

### 1.3 技术基础

系统基于以下学术研究与开源技术构建：

- **智能体框架**：DeepAgents（Harness Engineering 架构）
- **编排运行时**：LangGraph API
- **语义层引擎**：WrenAI
- **工具协议**：Model Context Protocol（MCP）

## 3. 核心技术

### 3.1 SQL-of-Thought 方法论

基于 2025 年学术论文的方法论，系统实现了以下核心设计原则：

| 原则 | 说明 |
|------|------|
| **分阶段推理** | 查询计划必须先于 SQL 生成，避免过早锚定 |
| **计划阶段禁出 SQL** | 查询计划阶段使用纯文本推理，确保思维链不受 SQL 语法干扰 |
| **分类学引导纠错** | 结构化错误分类诊断"为什么错"而非仅定位"哪里错" |
| **确定性输出** | LLM 调用使用确定性参数，确保结果可复现 |
| **纠错隔离** | 每轮纠错从新上下文开始，避免错误累积 |

### 3.2 三策略智能路由

系统根据查询复杂度自动选择最优执行路径：

| 策略 | 触发条件 | 典型耗时 |
|------|---------|---------|
| **标准管线** | 复杂多表 JOIN / 聚合 / 窗口函数 | 2-5 分钟 |
| **快速通道** | 单表 / 简单筛选 / COUNT 等基础操作 | 30-60 秒 |
| **Cube 通道** | 匹配预定义 Cube 指标 | 10-20 秒 |

### 3.3 MCP 协议集成

系统通过 Model Context Protocol (MCP) 实现智能体与外部工具的标准化集成，已集成 4 个 MCP Server：

| MCP Server | 功能 |
|-----------|------|
| WrenAI | 语义层查询、Schema 发现、Cube 指标、历史查询召回（18 个工具） |
| Semiotic | 图表推荐与渲染（~15 个工具） |
| ECharts | 图表生成，支持 多种图表类型 |
| DB Server | 多数据库 SQL 执行 |

### 3.4 技能系统

采用渐进式加载策略：系统提示词仅注入技能名称和简要描述，智能体按需加载完整技能文档，避免上下文膨胀。9 项技能完整内容约 15,000 tokens，提示词中仅占约 550 tokens。

## 4. SQL-of-Thought 推理管线

### 4.1 管线总览

```
Phase 1: 业务知识预处理
  Step 1 → 加载知识库文件，输出过滤后的业务规则/指标/陷阱

Phase 2: SQL-of-Thought 主流程
  Step 2~Step 6 → 执行nl2sql任务

Phase 3: 分类学纠错（条件触发）
  Step 7 → 错误分类 → 诊断 → 制定修复计划 → 生成修复 SQL
           最多 3 轮，每轮从新上下文开始
```

### 4.2 错误分类学体系

系统内置 9 大类 SQL 错误分类体系，覆盖 JOIN 错误、聚合错误、筛选错误、排序错误、子查询错误、类型错误、语法错误、逻辑错误和语义错误，确保能够精确定位并自动修复各类 SQL 生成问题。

### 4.3 性能优化

SQL 执行前自动进行性能审计，覆盖常见问题：SELECT *、缺少 LIMIT、笛卡尔积 JOIN、索引失效、NOT IN 含 NULL、DISTINCT 滥用、LIKE 前缀匹配、OR 未优化、LIMIT 无 ORDER BY、子查询未改写 JOIN 等。

## 5. 多智能体协作机制

### 5.1 架构设计

```
┌──────────────────────────────────────────┐
│           主智能体 (chat_agent)            │
│  意图识别 → 任务路由 → 结果聚合           │
│  工具: 图表MCP / 报告技能 / 文件系统       │
└────────────────────┬─────────────────────┘
                     │ start_async_task
                     ▼
┌──────────────────────────────────────────┐
│        NL2SQL 子智能体 (独立线程)          │
│  知识 → Schema → 子问题 → 计划 → SQL →    │
│  执行 → 纠错                              │
│  工具: WrenAI MCP                          │
└──────────────────────────────────────────┘
                     │
         ┌───────────┼───────────┐
         │    后台同步进程        │
         │  进度合并 → 主状态    │
         └───────────────────────┘
```

### 5.2 异步执行与进度追踪

1. **启动**：主智能体调用异步任务接口，子智能体在独立线程启动
2. **同步**：后台守护进程实时读取子智能体步骤，合并写入主智能体状态
3. **展示**：前端轮询主智能体状态，渲染进度条（步骤 + 状态 + 耗时）
4. **完成**：子智能体完成后，主智能体自动继续后续步骤

### 5.3 状态管理

主智能体扩展状态包含三个独立字段：主任务列表（todos）、查询标题（query_header）、子智能体步骤与耗时（subagent_steps），写入方各自独立，互不覆盖。

## 6. 知识库与语义层

### 6.1 WrenAI 语义层

系统通过 WrenAI 引擎构建业务语义层，将物理数据库表结构映射为业务概念：

```
物理层:  tables, columns, foreign_keys
   ↕ MDL (Model Definition Language)
语义层:  models, metrics, dimensions, relationships
```

核心能力覆盖 MDL 建模、Schema 发现、语义检索、历史查询召回、Cube 指标查询、SQL 方言转换及语法验证等。

### 6.2 知识库结构

```
knowledge/
├── rules/              # 业务规则、指标计算口径、字段映射
├── sql/                # 历史优质 NL→SQL 对、常见查询模式
└── caveats/            # 常见陷阱与注意事项
```

### 6.3 技能体系

| 类型 | 技能 | 功能 |
|------|------|------|
| 主智能体 | main-agent | 意图分类、子智能体选择、委派策略 |
| | report-export | 报告模板、标准 5 段式结构 |
| NL2SQL 子智能体 | sql-of-thought技能组 | 编排器，3 策略路由 |

## 7. 可视化与报告生成

### 7.1 图表引擎

支持双引擎（可切换）：

| 特性 | Semiotic | ECharts |
|------|---------|---------|
| 输出格式 | SVG | SVG / PNG |
| 图表类型 | BarChart, LineChart 等 | bar, line, pie, scatter, area |
| 智能推荐 | 支持 | 手动配置 |

### 7.2 报告模板

3 种内置 Markdown 报告模板：

| 模板 | 结构 |
|------|------|
| **数据查询报告** | 概览 → 数据表格 → SQL → 关键发现 |
| **分析报告** | 背景 → 分析结果 → SQL → 结论与建议 |
| **图表报告** | 数据概览 → 图表描述 → 详细数据 → SQL → 管线追踪 |

标准 5 段式结构：概览 → 核心数据（表格） → 生成的 SQL → 分析与解读 → 附录。

## 9. 安全与可靠性

### 9.1 数据安全

| 措施 | 说明 |
|------|------|
| **私有化部署** | 系统部署在企业内网，数据不出内网 |
| **SQL 预验证** | dry_run 预验证，防止危险 SQL 执行 |
| **权限隔离** | 数据库连接使用只读账号，禁止 DDL/DML |
| **元数据隔离** | 仅向 LLM 发送 Schema 元数据，不发送实际数据 |

### 9.2 沙箱执行环境

系统支持基于 Docker 的容器级沙箱隔离，为智能体的代码执行提供安全环境：

- **容器隔离**：每次执行在独立容器中，进程/文件/网络完全隔离
- **资源限制**：CPU 和内存硬限制，防止资源耗尽
- **超时销毁**：容器自动销毁，防止僵尸进程
- **网络管控**：默认拒绝出站 + 白名单机制
- **多语言支持**：预装 Python / Go / Node.js / Java 运行环境
- **路径防护**：文件操作限制，防止路径遍历攻击

### 9.3 可靠性

| 措施 | 说明 |
|------|------|
| **状态检查点** | 会话状态持久化，中断可恢复 |
| **自动纠错** | 最多 3 轮分类学纠错，提升 SQL 成功率 |
| **超时控制** | LLM 调用超时 + 重试机制 |
| **子智能体隔离** | 子智能体异常不影响主智能体 |
