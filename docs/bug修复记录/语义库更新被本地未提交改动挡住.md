# 「更新语义库」被本地未提交改动永久挡住（且文件名看不懂、没有出路）

**日期**：2026-09-15
**类型**：链路缺口（保存知识不提交 vs 更新护栏）+ 提示不可读（git quotepath）
**严重程度**：中（更新按钮在「改过没推送」的常见状态下变成死路；提示里的文件名是八进制转义，用户无法判断是哪个文件）

---

## 一、问题描述

生产环境 `witops-wrenai` 语义库，前端点「更新语义库 → 更新」直接失败：

```
pull-witops-wrenai 失败: 本地有未提交改动，已中止以免覆盖：
"knowledge/glossary/\346\234\257\350\257\255\350\241\250.md"（请先提交或撤销后重试）
```

在该语义库目录（容器内 `/app/data/workspace/witops-wrenai/`）确实存在
`knowledge/glossary/术语表.md`。

### 复现条件

1. 在平台「知识编辑器」里改过任一知识文件并点过保存（`POST …/knowledge/save`）；
2. **没有**点「推送 Git」（该动作才会 commit + push）；
3. 此后任何一次「更新语义库」都会被拒 —— 与远程有没有新提交无关。

---

## 二、根因分析

### 根因 1：平台的「保存知识」只写盘不提交，工作树天然是脏的

| 步骤 | 位置 | 是否提交 |
|---|---|---|
| UI 保存知识 → `POST /api/wren-projects/{name}/knowledge/save` | `KnowledgeEditor.tsx` 的 `handleSave` | — |
| 后端 `save_knowledge` 直接 `target.write_text(...)` | `wren_semantic.py`（自由 Markdown 分类） | **不 add、不 commit** |
| 唯一提交路径：「推送 Git」→ `git add -A` + commit + push | `wren_semantic.py::push_to_git` | 是 |

已核对写入者：`save_knowledge` 是 `knowledge/<分类>/*.md` 的**唯一**写入者
（`create_project` 只种子 `knowledge.yml` 与 `rules/general.md`；`ai_generate_knowledge`
只回内容不落盘；agent 侧与 skill 侧对 glossary 全是只读）。所以「保存知识」与
「提交」在用户心智里是一件事，在实现里是两件事。

### 根因 2：更新护栏「宁可拒绝也不覆盖」的正确行为，缺了配套出路

`git_repo.pull_ref` 在 checkout 到远程版本前先做脏树检查（`git diff --name-only` +
`--cached`，`target/` 例外、未跟踪文件不列）——这是**有意**的保护（2026-09-09 事故后
加的，见 `docs/bug修复记录/` 同目录相关记录）。问题在于三处配套缺失：

1. **前端点之前不预检**：`PullGitDialog` 只拉 `git-refs`，不拉 `git-status`
   （该端点早就算好了 `has_local_changes`），用户点了才知道会被拒；
2. **没有出路**：拒绝后前端只能显示一句话，没有「放弃本地改动」的入口，
   用户要么自己进容器 `git checkout --`，要么被卡死；
3. **文件名不可读**：`_run` 未传 `-c core.quotepath=false`，git 默认把非 ASCII
   路径 C-quote 成八进制（`"\346\234\257…"`）——上文的报错就是这么来的。

---

## 三、解决方案

### 后端

1. **`_run` 一律 `-c core.quotepath=false`**（`agent/utils/git_repo.py`）：
   所有 git 输出里的中文/空格路径原样可读。这是 2026-09-15 那条报错里
   `\346\234\257\350\257\255\350\241\250.md` 的成因，也影响 git-status / 推送等所有提示。

   顺带修掉一个更隐蔽的后果：`rebuild_required` 的判据是
   `p.startswith(("models/", "knowledge/"))`，而 C-quote 的输出**带引号**
   （`"knowledge/glossary/\346…"`）→ 前缀判断命不中 → **只有中文名知识文件变更时，
   「需点构建后生效」的提示会漏掉**（wrenai 读的是 `target/mdl.json`，漏提示等于让
   用户以为更新没生效）。测试 C10/C11 直接钉住了这一点。

2. **脏树判据集中到 `local_changes(cwd)`**，返回
   `{"blocking": [...], "generated": ["target/..."], "dirty": bool}`：
   `pull_ref` 与 `git-status` 端点共用同一份判据，避免两处口径漂移。
   `blocking` 非空才是真正拦住更新的集合（未跟踪文件不列，checkout 不覆盖它们）。

3. **`pull_ref(..., discard_local=False)`**：默认行为完全不变（拒绝）。前端显式传
   `discard_local=True`（用户已确认放弃）时，改为**先 `git stash push` 备份再更新**，
   返回 `stash_ref`（`stash@{0}（1a2b3c4）` 形式）与 `discarded_files`，更新成功的
   message 前缀写明「已放弃 N 个文件的本地改动（备份于 …，可 git stash 找回）」。
   未跟踪文件**不入 stash**（原地保留），因此不会把用户新加的知识文件卷走；
   stash 失败即中止，绝不在没备份的情况下继续。注意：`discard_local` **不能**绕过
   未推送提交护栏（那是 commit，不该被「放弃改动」吞掉）。

4. **结果结构化**：`_pull_fail(msg, dirty_files, blocked)` —— 失败结果带
   `blocked`（`dirty` / `unpushed`）与 `dirty_files`，前端不必解析中文字符串。

5. **端点接线**：`GET …/git-status` 新增 `local_changes` / `generated_changes`；
   `POST …/git-pull` 接受 `discard_local`（query `?discard_local=1` 或 body
   `{"discard_local": true}`）。`push_to_git` 里重复的布尔归一化抽成 `_truthy()`
   共用（语义逐字不变）。

### 前端（`harness-deep-agents-ui`）

1. `PullGitDialog` 打开即预检 `getGitStatus`（顺带修掉此前「`getGitStatus` 导入了
   但没用」的既存 lint 错误）：有 `local_changes` 时红色横幅列出**文件名**，
   并说明「建议先推送 Git；不想保留则勾选下方选项」。
2. 新增勾选框「放弃本地未提交改动并更新（先自动 git stash 备份，可用 git stash pop
   找回）」——未勾选时「更新」按钮置灰，勾选后才可点，`discardLocal` 随之传给后端。
3. 只有未跟踪文件/构建产物改动时，提示「不影响更新」，避免误报。
4. `KnowledgeEditor` 保存成功后的提示改为「已保存到本地（…）；尚未提交，点「推送
   Git」才会同步到远程」——从源头消除「保存了 = 提交了」的误解。

## 五、遗留与风险

- **stash 会累积**：每次「放弃并更新」留一条 stash，长期不清理会堆积（`git stash
  clear` / `drop`）。本轮不做自动回收——自动删备份与「可找回」的承诺冲突。
- **未推送提交护栏在「本地落后」时也会拦**：判据是 `本地分支 sha ≠ refs/remotes/origin/<b>`
  的**严格不等**（浅仓库无法用 `rev-list` 判祖先，见 `pull_ref` 注释）。因此若有人在
  容器里手动 `git fetch`（只动了远程跟踪 ref、没动本地分支），「更新」会报
  「可能有未推送提交」。解法仍是「推送 Git」或手动对齐；本轮不动这条判据。
- **前端预检是前端行为**：旧前端配新后端时不会预检，仍会吃一条 400 —— 但那条 message
  现在文件名可读、且给出了 stash 出路，可接受。
- 「更新」失败原因里只有 `dirty` 这条给出了「一键放弃」出路；`unpushed` 仍需用户
  自行「推送 Git」（这是有意的：不该用「放弃改动」的语义吞掉用户的 commit）。
