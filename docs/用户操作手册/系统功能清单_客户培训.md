# 智能数据助手 — 功能使用介绍（客户版）

> 用途：面向客户介绍"系统能做什么、怎么用"
> 版本：v2.6（2026-09-01）
> 维护说明：持续更新，新增功能请按章节补充并更新版本号与日期

---

## 一、一句话认识它

**智能数据助手 = 会查数据库的 AI 助手。**

您用中文提问，它自动去数据库里把数据找出来，帮您算好、画成图表、写成报告。
您不需要懂 SQL、不需要懂数据库，就像和同事聊天一样。

---

## 二、能做什么（功能介绍）

### 2.1 用大白话查数据

直接输入您想知道的问题，比如：

- "查询1990年代电影的平均评分"
- "票房最高的前10部电影"
- "每个月销售额是多少，趋势怎么样"
- "哪个类型的电影数量最多"

系统会自动理解您的意思，去数据库查询，返回结果。

### 2.2 自动画图表

查询结果会自动配上合适的图表：

- 柱状图、折线图、饼图、散点图等
- 图表是**可交互的**：鼠标悬停看具体数值、可缩放、可切换显示项
- 图表直接显示在对话里，一目了然

### 2.3 自动生成报告

查询 + 图表 + 分析解读，系统自动整合成一份 **Markdown 报告**，方便保存和分享。

### 2.4 多数据库查询

系统可连接多个数据库（如 aix_report、Chinook、imdb、clickhouse 等，支持 MySQL / ClickHouse / PostgreSQL）。
切换数据源后提问，即针对该库查询；数据库列表由管理员在「数据库配置管理」中维护（见 3.6）。

### 2.5 聊天式多轮对话

一个对话里可以连续问多个问题，系统会记住上下文。

### 2.6 多工作区（项目隔离）

如果您需要同时对接多个项目（比如"销售分析"和"库存管理"是两套独立的数据库和语义库），可以用**工作区**来隔离管理：

- 每个工作区是一个独立的文件夹，拥有自己的一套数据库配置、语义库、对话历史和报告
- 不同工作区之间**共享技能和记忆**（AI 的"知识库"），但**数据查询结果互不干扰**
- 新建工作区只需在服务器上创建一个空文件夹，再在系统中注册即可

### 2.7 离线效果对比（管理员 / 维护人员）

改了 AI 的配置（提示词、技能、语义库）之后，怎么知道效果是变好还是变差？「离线测试」用**历史积累的真实问题集**把新旧版本各跑一遍，自动打分对比，并给出"**是否可发布**"的判定（门禁），避免凭感觉升级、防止把已修好的问题弄坏。详见 3.11。

## 三、怎么用（操作指南）

### 3.1 开始使用

1. 打开系统网页（浏览器访问）
2. 首次使用会弹出配置窗口，填写 **部署地址** 和 **助手 ID**（由管理员提供）
3. 进入对话界面，在底部输入框提问即可

### 3.2 提问小技巧

| 好的问法 | 说明 |
|---------|------|
| "查询2020年以来电影数量" | 明确"查询""数量"等词，系统更易识别 |
| "对比1990和2000年代平均评分" | 带对比需求 |
| "按年份统计票房并画趋势图" | 明确提出要图 |

> 提示：提问中带上 **查询、统计、多少、排名、平均、趋势、分析、数量** 等词，系统会优先按数据查询处理。

### 3.3 等待过程中的进度条

提问后，对话上方会出现进度条，您可以实时看到：

- 📋 **当前问题**（您问的是什么）
- 🔍 **查询执行步骤**（系统正在做什么，每步耗时多少）
- **图表/报告** 进度

查询进行中，建议**等待本次查询完成**再问下一个查询，结果会更清晰。

### 3.4 查看图表和报告

- 图表直接显示在对话消息里，可交互
- 报告文件保存在系统工作区，可通过文件面板查看
- 生成的报告和图表也可由管理员在服务器目录中找到（`.html` / `.md` 文件）

### 3.5 切换数据库

在对话界面顶部的 **数据库：** 下拉框选择要查询的数据库，切换后提问即针对该库。

- 下拉框中每项标注了类型和通道：**直连**（普通数据库连接）/ **语义层**（已配置 Wren 语义建模）
- 选择会被记住（下次打开自动沿用），每次提问都按当前选中的库执行
- **切换后立即生效，无需重启系统**：在已配置的库之间切换，直接提问即可
- 例外（需管理员重启后端）：某库**首次配置语义层**、或**修改了某库的连接参数**后（见 3.6）

### 3.6 数据库配置管理（管理员）

点击数据库下拉框旁的 **⚙️ 按钮**，打开「数据库配置管理」窗口。在此维护系统能连接哪些数据库：

**查看已配置的数据库**：列表显示每个库的名称、类型、Host、库名、通道（语义层/直连），可编辑或删除。

**新增 / 编辑数据库**，填写：
- **名称（db_name）**：给数据库起个名字（如"生产MySQL"），作为下拉框和提问时使用的标识
- **类型**：MySQL / ClickHouse / PostgreSQL
- **Host / Port**：数据库地址和端口
- **数据库名**：物理库名
- **用户名 / 密码**：登录凭据（密码加密存储在后端，编辑时留空表示保留原密码）
- **Wren 项目（语义层）**：可选。选中后该库走 Wren 语义层查询（工具名 `wrenai_<库名>_*`）；下拉项由系统自动扫描服务器工作区里已就绪的 Wren 项目得出，留空则走直连

**测试连接**：保存前可点「测试连接」，验证地址和凭据是否正确。

> 注意事项：
> - 连接信息只保存在后端，密码加密存储，前端不落库
> - 新增的**直连**库配置后立即可用，无需重启
> - 某库**首次配置 Wren 语义层**后，需管理员**重启后端**才生效（新语义层服务才会启动）
> - 修改了某个已连接库的 Host/密码等参数后，也需重启后端才生效

### 3.7 语义库管理（管理员）

"语义库"是给 AI 用的**语义建模项目**——把数据库里的表、字段、关系按业务口径预先"翻译"好，AI 查询时按这套建模来理解，结果更准确、更稳定。

管理员点击数据库下拉框旁的 **⚙️ 按钮**打开设置弹窗，进入「**语义库**」选项卡，可维护系统里有哪些语义库、各自关联哪个数据库。

**查看语义库列表**：每行显示项目名、来源（git / 本地）、构建状态（已构建 / 未构建）、建模规模（模型 / 视图 / 关系数量），以及关联了哪些数据库。

#### 方式一：新建语义库（推荐，从零创建）

适用于**还没有现成的语义库项目**，需要从数据库表结构开始创建。

**Step 1 — 基本信息**：
- 选择**目标数据库**（下拉框列出已配置的库）
- 填写**项目名称**（语义库的目录名，建议用英文，如 `sales_analysis`）
- 填写**项目描述**（可选，用于备注）
- 点击「创建项目」，系统自动在服务器工作区下生成语义库项目骨架

**Step 2 — 提取表结构**：
- 点击「提取表结构」，系统自动连接目标数据库，列出所有表和字段
- 勾选需要建模的表（可全选或按需勾选），同时可预览表之间的关联关系
- 点击「生成模型文件」，系统自动将选中的表转为语义模型文件

**Step 3 — 填写业务知识**（可选但推荐）：
- 系统提供业务知识模板，帮助 AI 更好地理解业务含义：
  - **术语表**（glossary）：定义业务术语（如"活跃用户"）对应哪些字段
  - **指标定义**（metrics）：定义业务指标的计算公式（如"销售额 = SUM(amount)"）
  - **业务规则**（rules）：告诉 AI 查询时的注意事项（如"默认查最近 30 天"）
  - **SQL 示例**（sql）：提供典型查询场景的参考 SQL
  - **注意事项**（caveats）：数据质量、边界情况等提醒
- 每项模板可点击「打开」在系统资源管理器中查看和编辑文件，也可在界面中直接编辑保存
- 不填也不影响使用，AI 会按表结构自动理解

**Step 4 — 校验与构建**：
- 点击「校验」检查语义库是否有效
- 点击「构建」生成查询所需的 MDL 文件
- 可反复执行，修改模型或知识后可重新构建

**Step 5 — 应用与上传**：
- **应用至项目**：将语义库关联到选中的数据库，后续查询即走语义层通道
- **上传至 Git**（可选）：填写远程仓库地址、分支、标签（可选）和提交信息，将语义库推送到 Git 仓库保存版本

#### 方式二：从 Git 拉取语义库

适用于**已有现成的语义库项目**托管在 Git 上。

**从 Git 拉取语义库**，填写：
- **仓库地址**：http/https 的 git 仓库地址
- **分支 / 标签**：如 main、v1.0.0（可选，默认拉默认分支）
- **项目目录名**：落地后的目录名（可选，默认取仓库名）
- **关联数据库**：选中某个库后，系统会用**该库的本地连接信息**生成连接并自动"构建"（生成查询所需的 MDL 文件）

> 说明：语义库的连接凭据**不会从 Git 仓库读取**，而是用您选择的「关联数据库」的本地连接信息（已加密存储在系统里）。仓库里自带的连接文件在生产环境会被忽略。

#### 方式三：关联本地目录

如果语义库项目已在服务器上，直接填「项目目录绝对路径」并选择「关联数据库」即可。

#### 通用操作

**对每个语义库可执行**：
- **校验**：检查语义库是否有效，显示模型 / 视图 / 关系数量
- **构建**：重新生成查询所需的 MDL 文件
- **删除**：解绑所有关联并删除本地项目目录（**不可恢复**，操作前会二次确认）

> 重要提示：
> - **新增 / 删除**语义库后，需管理员**重启后端**才生效（新的语义层服务才会启动）
> - **校验、构建**无需重启，立即生效

### 3.8 自定义查询关键词（可选）

点击输入框旁的 **齿轮按钮 ⚙️**，可自定义"哪些词会被当成数据查询"。一般用户无需修改，使用默认即可。

### 3.9 会话管理

- 左侧列表可查看历史对话
- 可新建对话、切换对话、删除对话
- 关闭网页后对话记录自动保留，下次打开可继续

### 3.10 工作区管理（管理员）

工作区用于隔离不同项目的数据库配置、对话历史和报告。进入「设置」界面，点击「工作区」选项卡即可管理。

**查看工作区列表**：显示所有已注册的工作区，当前活跃的工作区有标记。

**注册新工作区**：
1. 先在服务器上创建一个**空文件夹**作为工作区目录（如 `D:\projects\sales-analysis\`）
2. 在界面中填写：
   - **名称**：工作区显示名（如"销售分析项目"）
   - **路径**：服务器上刚创建的文件夹完整路径

**切换工作区**：
- 点击目标工作区的「激活」按钮
- **切换后即时生效**（数据库配置、语义库、对话历史等都会切到新工作区）

**删除工作区**：
- 取消注册即可（不会删除服务器上的文件，只是系统不再使用该工作区）
- 默认工作区不可删除

> **重要提示**：
> - 切换工作区后所有对话历史、数据库配置都会切换到新工作区。如需回到之前的工作区，再次激活即可。
> - 工作区切换不影响前端界面设置（如部署地址、助手 ID 等）。

### 3.11 离线测试（管理员 / 维护人员）

「离线测试」回答一个关键问题：**改了 AI（换了提示词、更新了技能、升级了语义库）之后，效果到底是变好了还是变差了？**

它用**历史积累的真实问题集**当"考题"——比如之前"答错"的问题（badcase）、客户点赞的"正确问题"（goodcase）——让新旧版本各跑一遍，自动打分对比，并判定"新版本能否发布"，避免凭感觉升级。

#### 入口

首页顶部点击「**离线测试**」进入。左侧配置实验、查看历史；右侧显示运行进度和结果。

#### Step 1 — 数据集与参数（卡片默认折叠，点击标题展开）

- **数据集（多选）**：勾选要用来"考试"的问题集。系统列出全部数据集，常见的两类：
  - **badcase**：历史"答错"的问题（回归重点，防止修好的问题再变坏）
  - **goodcase**：客户点赞、查询正确的问题（防止新版本把本来好的弄坏）
  - 支持同时多选；每项右侧数字 = 该数据集当前有多少条问题（显示"?"表示读取失败）
- **条数上限**：0 = 全部。数据集较大时建议设置上限，跑得更快
- **门禁阈值（±）**：允许新版本相对旧版本评分下降多少以内（默认 0.05）
- **启用 LLM 判分**：用大模型判"业务是否正确"，更准但更慢（默认关）

#### Step 2 — 对比臂

每个"臂" = 一个版本组合，可独立指定：

- **臂名**：自定义，如 `ref`（当前线上）、`cand`（待验证的新版本）
- **Prompt 版本**：Langfuse 中管理的提示词版本（留空 = 生产默认）
- **Skill 版本**：技能脚本的 git 版本（留空 = 当前磁盘技能）
- **语义库版本**：语义建模的 git 版本（留空 = 当前 HEAD）

> 建议第一个臂设为"当前线上"作为**基准（ref）**，后续臂为要验证的候选版本。点「添加臂」可加更多臂。

#### Step 3 — 运行

点「**运行离线实验**」，右侧出现进度卡，实时显示每个臂跑到第几条。运行中可以先去忙别的，之后在左侧「历史实验」里点这条（带"运行中"徽章）即可回看进度。

#### 结果怎么看

- **核心评分对比**：两个版本的各维度评分及差值，绿 = 变好、红 = 回退。核心维度：
  - 业务正确分、SQL 合法性、执行成功率、语义匹配
- **门禁判定（PASS / FAIL）**：
  - 有两个及以上臂时才判定，**第一个臂为基准、第二个臂为候选**
  - **PASS** = 新版本无明显回退（差评未超过阈值）→ **可以发布**
  - **FAIL** = 新版本核心指标回退超过阈值 → **不建议发布**
  - 双重门槛：整体指标 + 简单查询子集**都**要检查，防止"整体没变、简单查询悄悄变差"被掩盖
- **策略分层**：按查询实际走的处理通道（快通道 / 语义层 / 直连）分组统计，看差异集中在哪类查询
- **逐条明细**：每条考题的 SQL、结果、各维度得分；点开可看详情，并可跳转 Langfuse 查看完整处理过程

#### 历史实验

- 左侧「历史实验」列出所有跑过的实验，徽章显示状态：**运行中 / 完成 / 失败 / 中断**，完成的可看到 PASS / FAIL
- 点条目重新查看结果；鼠标悬停出现「**删除**」按钮，可删掉不再需要的实验（**不可恢复**，删除前有确认提示）
- 运行中的实验同样可以点开回看进度

> 注意：
> - **标准答案（Expected Output）**：只有 goodcase 这类**带金标**的数据集才有；badcase 本身就是"错题"，没有标准答案，属正常现象
> - 删除实验会连同明细文件一起删除，不可恢复，请谨慎操作
> - 修改了数据集装载等后端逻辑后，需管理员**重启后端**才生效

### 3.12 Skill 版本发布与撤销（管理员 / 维护人员）

离线测试的「Skill 版本」是技能在 git 里的快照。技能目录与系统代码在**同一个 git 仓库**中（`src/agent/shared/skills/`）：每次改动技能后，把它**单独**提交并打一个版本标签（tag），离线测试就能在「对比臂 → Skill 版本」里选择用哪个技能版本做 A/B 对比。

> **为什么要"单独"提交？** 系统代码里往往还堆着很多其它未提交的改动（文档、配置等）。技能打 tag 只需要技能这一部分的快照，所以用下面"指定路径提交"的方式，技能之外的任何东西都不会被带进去。

**一、发布技能版本（打 tag）**

```bash
# ① 查看技能目录当前有哪些改动（确认只包含想发布的）
git status --short -- src/agent/shared/skills/

# ② 只暂存技能目录
git add src/agent/shared/skills/

# ③ 指定路径提交：只提交技能目录，其它文件保持原样
git commit -m "skill: 更新 xxx" -- src/agent/shared/skills/

# ④ 打版本标签（在上一个技能版本号上递增，如已有 skills-v0.1.0 → 打 skills-v0.2.0）
git tag skills-v0.2.0
```

**二、验证**

```bash
# 标签存在且技能文件齐全（数量应大于等于上一版）
git ls-tree -r --name-only skills-v0.2.0 -- src/agent/shared/skills/ | wc -l
# 对比上一技能版本改动了哪些文件
git diff --stat skills-v0.1.0 skills-v0.2.0 -- src/agent/shared/skills/
```

发布后到「离线测试 → 对比臂 → Skill 版本」下拉选择新版本即可对比。

**三、撤销标签（打错了 / 不想要了）**

```bash
git tag -d skills-v0.2.0        # 本地删除
```

若该标签已推送到远程（`git push --tags`），远程也要删：

```bash
git push origin :refs/tags/skills-v0.2.0
```

**四、要点解析**

- **标签是"那一刻的整仓快照"**：技能标签的树 = 当时整个仓库代码 + 技能改动，并非只有技能目录。离线测试运行时只从标签里提取技能部分，不影响对比；但请不要把它理解成"纯技能文件包"。
- **技能与语义库共用同一套标签空间**：仓库里同时有技能标签（`skills-*`）和语义库标签（`v1.0.0`~`v6.0.0`）。系统按"标签里是否含技能/语义库内容"自动分流——技能标签只出现在「Skill 版本」下拉，语义库标签只出现在「语义库版本」下拉，不会混选。
- **标签默认只在本地**：要同步到服务器 / 团队其他成员，需 `git push origin <分支名> --tags`（通常随发版一起推）。
- **不要用普通 `git commit` 提交技能**：会把当时所有已暂存文件一起提交（可能误带其它开发中的内容）。务必用带 `-- src/agent/shared/skills/` 的指定路径提交。

## 四、常见问题

| 问题 | 说明 |
|------|------|
| 提问后没反应？ | 等待几秒，进度条会显示执行过程；复杂查询可能需要较长时间 |
| 查询进行中再提问被提示等待？ | 系统为保护结果清晰，建议等当前查询完成再问下一个 |
| 想画图但没出图？ | 提问时明确说"画图""图表""趋势图"等 |
| 换一个数据库？ | 在界面顶部"数据库："下拉框选择后再提问，切换立即生效 |
| 下拉框里没有想要的库？ | 该库未配置，需管理员在「数据库配置管理」中新增连接（见 3.6） |
| 配了语义层但提问仍报找不到库？ | 首次配置语义层后需重启后端才生效，请联系管理员 |
| 数据不对或看不懂？ | 可追问系统"请详细说明"，或换个说法重新提问 |
| 工作区切换后数据库配置不见了？ | 正常现象，每个工作区有独立的数据库配置，切换后显示的是新工作区的配置 |
| 工作区切换后对话历史没了？ | 正常现象，对话历史按工作区隔离，切回原工作区即可看到之前的对话 |
| 切换工作区后多久生效？ | 即时生效 |
| 离线测试结果在哪里看？ | 首页顶部「离线测试」→ 右侧结果区；历史实验可随时回来查看 |
| 门禁显示 FAIL 是什么意思？ | 新版本相对基准回退超过阈值，不建议发布；可在逐条明细里定位是哪类查询变差 |
| 为什么有些数据集没有"标准答案"？ | badcase 是历史错题，本就没有标准答案；只有带金标的数据集（如 goodcase）才显示 Expected Output |
| 实验跑一半去忙别的，还能找回吗？ | 可以，左侧「历史实验」里"运行中"（徽章）的条目点开就是进度 |
| 删掉的离线实验能恢复吗？ | 不能，删除会连同明细文件一起删除，操作前有确认提示 |
