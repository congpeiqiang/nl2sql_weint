# 蓝绿发布 · 阶段 0 实测结论（2026-10-05）

> **这份文件回答一个问题：我们镜像里的 postgres 平台存储运行时是哪来的、怎么接的。**
> 下一个发版日不要靠记忆 —— 官方镜像 tag / digest / 抽包路径 / 启动顺序都在下面。
>
> 实测环境：部署机 192.168.25.64，一次性容器（已清理，未碰任何生产容器/卷）。
> 探针脚本留档在 `d:\tmp\stage0_probe*.sh`（本地，未入库）。

## 一句话结论

**可行，阶段 0 绿灯**；但方案原假设「只把 Python 运行时补进镜像」**不够** ——
官方 postgres 版是 **Python + Go 双进程**，所有 thread/run/assistant CRUD 都走 gRPC 打到 Go core，
**Go 二进制必须一起搬进我们的镜像，并由 `start_server.py` 在 `setup_environment()` 之后拉起**。

## 一、运行时从哪来（版本号 + 抽包路径）

| 项 | 值 |
|---|---|
| 官方镜像 | `docker.m.daocloud.io/langchain/langgraph-api:0.11.1-py3.13-wolfi` |
| digest | `sha256:29e2e0bc047efebb90a4c3de08fac98e7cfbf329003050c83139028dd5e5d411` |
| Python | 3.13.14（= 我们 `python:3.13-slim` 同 minor） |
| `langgraph_api` | **0.11.1**（与我们 venv 逐字同版，py3.13 变体存在，ABI 风险解除） |

| 发行名 | `langgraph_storage_postgres` **0.1.0**（`dist-info` 里叫这个；**导入名是 `langgraph_runtime_postgres`**） |

**⚑ 这个包不在任何公网 PyPI 上。** `langgraph-runtime-postgres` 404；
`langgraph-storage-postgres` 在 pypi.org 是个**空壳**（simple 页 0 文件、JSON API 404）
⇒ **只能在官方镜像里取**，没有 pip 安装这条路。

抽包路径（`COPY --from=<官方镜像>`）：

```
/storage/langgraph_runtime_postgres     # 纯 Python，但**只有 .pyc 没有 .py**（sourceless 包）
/storage/migrations                     # 64 个 .sql（61 个 .up + 3 个 .down）
/usr/bin/core-api-grpc                  # 70,520,418 B，静态链接 ELF（e_type=EXEC，无 PT_INTERP）
                                        # ⇒ 直接进 debian-slim 可跑（实测就是在本机 debian trixie 上起来的）
```

`/storage` 是怎么进 `sys.path` 的：官方镜像里是
`site-packages/_editable_impl_langgraph_storage_postgres.pth` 内容就一行 `/storage`
⇒ **我们镜像等价做法是 `ENV PYTHONPATH=/storage`**（或放一个 `.pth`）。

跑起来还缺的唯一依赖：**`redis` 客户端**（`langgraph_runtime_postgres/database.py:22`
硬 import）。官方镜像是 `redis 7.4.0`（纯 Python）。我们 venv 里没有 ⇒ 加进 `pyproject.toml`
即可（阿里云 PyPI 镜像有）。

## 二、Go core 是硬要求（这是对原方案的实质性修正）

- `langgraph_api/api/*.py` 全篇是这个模式：`if IS_POSTGRES_OR_GRPC_BACKEND: from langgraph_api.grpc.ops import …`
  （`IS_POSTGRES_OR_GRPC_BACKEND = _RUNTIME_EDITION == "postgres"`，见 `feature_flags.py:19`）
  ⇒ **postgres 版型下 ops = 对 Go core 的 gRPC 客户端**，没有纯 Python 回退路径。
- `langgraph_runtime_postgres` 里**没有 `ops` 模块**（只有
  `database / lifespan / queue / checkpoint / migrate / metrics / redis / retry / routes / store /
  long_query_monitor / custom_encryption_serializer`）—— 这正是「CRUD 不在 Python 侧」的旁证。
- 官方 `entrypoint.sh` 的原话：`ERROR: core-api-grpc command not found, the core-api-grpc binary
  must be included in the image`。

**进程形态**（实测可用，见 §四）：Go core 监听 `LSD_GRPC_SERVER_ADDRESS`（默认 `localhost:50051`），
Python 侧再起一个 **loopback gRPC 服务 127.0.0.1:50071**，把**自定义 checkpointer** 与加密回传给 core
（日志 `custom_checkpointer_enabled: True` / `Registered Checkpointer service`）。

### 启动顺序是**必须**的坑

`LANGSERVE_GRAPHS` 必须让 **core** 看到。若先起 core、再进 `start_server.py`
（那里才 `os.environ.setdefault("LANGSERVE_GRAPHS", …)`），core 的配置里
`"LangserveGraphsJSON":""` ⇒ 建助手时被拒：`NOT_FOUND: graph 'chat_agent' not found`，
表现为 **lifespan 起不来、服务退出**。**实测踩过一次。**

正确姿势（`start_server.py` 里在 `uvicorn.run(...)` 之前做）：

```python
# setup_environment() 之后（LANGSERVE_GRAPHS / DATABASE_URI / REDIS_URI 都已就位）
if os.environ.get("LANGGRAPH_RUNTIME_EDITION") == "postgres":
    subprocess.Popen(["core-api-grpc"], env=os.environ.copy())   # 继承全部 env
    # 退出时需一并回收（否则容器 SIGTERM 后要等超时才退出）
```

## 四、怎么复现（最小可跑配方）

```
docker build -t <我们的镜像> -f <Dockerfile>
  FROM nl2sql-app_langgraph-api:latest
  COPY --from=<官方镜像> /storage/langgraph_runtime_postgres /storage/langgraph_runtime_postgres
  COPY --from=<官方镜像> /storage/migrations               /storage/migrations
  COPY --from=<官方镜像> /usr/bin/core-api-grpc            /usr/bin/core-api-grpc
  ENV PYTHONPATH=/storage

容器 env：
  LANGGRAPH_RUNTIME_EDITION=postgres
  DATABASE_URI=postgresql://…@postgres:5432/nl2sql_platform
  REDIS_URI=redis://redis:6379/0
  MIGRATIONS_PATH=/storage/migrations
  LSD_GRPC_SERVER_ADDRESS=localhost:50051

启动顺序：core-api-grpc &（带上 LANGSERVE_GRAPHS）→ exec python start_server.py
```

## 五、留给后续阶段的已知问题

1. **迁移是开机自动跑的**（Python 侧，`DB_MIGRATION_BY_CORE_API=false` 为默认）。
   蓝绿下新色开机就会改共享库 schema，而旧色还在跑 ⇒ 要么走 expand-contract，
   要么在阶段 1 把它改成**受控步骤**（该 flag 是现成的杠杆）。**阶段 1 必须拍板。**
2. **版本上下界有轻微越界**：运行时声明 `psycopg[binary]<=3.3.3`、`psycopg-pool<=3.3.0`，
   我们 venv 是 `psycopg 3.3.4` / `psycopg_pool 3.3.1`。实测能跑，但要么对齐、要么记档。
3. **自定义 checkpointer 少三个可选方法**（`adelete_for_runs` / `acopy_thread` / `aprone`）：
   官方适配层给 WARNING 并降级（回滚清理、线程复制、历史裁剪）。**inmem 版型下同样如此，非本次引入**。
4. **core 带 Datadog 埋点**：启动时对 `localhost:8126` 发一坨失败日志（`DD_TRACE_ENABLED=false`
   也不完全安静）。属噪音，不影响功能，但会污染启动日志的可读性。
5. `GET /threads` 返回 **405**（该路由在此版本只接受 POST / `/threads/search`）—— 不是错误。
6. 排空/优雅退出**未验**：core 是 `start_server.py` 的子进程，阶段 2 要确认
   SIGTERM 能把它一起收掉、且不影响现有 `drain.py` 的等待窗口。
