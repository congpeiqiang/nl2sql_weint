# 主智能体路由技能

## 概述

主智能体是系统的入口，负责理解用户意图并将任务委派给对应的子智能体。本技能定义意图识别规则和委派策略。

## 动态发现规则

> **技能和工具会更新，禁止依赖硬编码列表。** 被问到子智能体详情时，
> 必须从 YAML 配置文件实时读取：
>
> ```bash
> cat subagents/configs/nl2sql.yaml     # 读取配置
> ls subagents/configs/                 # 列出所有子智能体
> ```
> 回答时提取 `description`、`skills`、`tools` 字段。

## 核心职责

1. **意图识别** — 分析用户输入，判断任务类型
2. **子智能体选择** — 根据意图选择合适的子智能体
3. **委派执行** — 将任务委派给子智能体并收集结果
4. **结果呈现** — 以友好格式展示子智能体返回的结果

## 可用子智能体清单

### nl2sql — NL2SQL 数据查询专家

| 维度 | 详情 |
|------|------|
| **职责** | 将用户自然语言数据问题转换为 SQL 并执行，支持图表可视化 |
| **技能** | `sql-of-thought`（编排器）、`nl2sql-schema-linking`（表发现）、`nl2sql-subproblem`（分解）、`nl2sql-query-plan`（计划）、`nl2sql-sql-generation`（生成）、`nl2sql-correction`（纠错） |
| **工具** | `run_sql`（执行SQL）、`suggestCharts`（推荐图表）、`getSchema`（图表Schema）、`renderChart`（渲染图表） |
| **Shell** | `wren context show`（查看表模型）、`wren dry-plan`（验证SQL）、`wren query`（查询）、`python skills/sql-of-thought/scripts/gen_models_mysql.py`（生成模型） |

## 意图分类

### 数据查询 → 委派 `nl2sql`

**触发关键词：** 查询、统计、有多少、列出、排名、对比、计算、汇总、分析、数据、SQL、图表、可视化、报表

**示例：**
- "有多少电影" → nl2sql
- "统计演员数量" → nl2sql
- "分析客户购买行为" → nl2sql
- "画一张销售趋势图" → nl2sql

### 数据库管理 → 委派 `nl2sql`

**触发关键词：** 建表、导入数据、修改表结构、Schema、数据库配置、连接

**示例：**
- "切换到 Chinook 数据库" → nl2sql（传递 db_name）
- "查看数据库中有哪些表" → nl2sql

### 一般对话 → 直接回复

**触发关键词：** 你好、帮助、功能、你是谁、能做什么、谢谢

**示例：**
- "你好" → 直接回复
- "你能做什么" → 介绍功能

## 委派策略

### 单步委派
大多数数据查询只需委派给 nl2sql 一次：
```
用户: "查询销售额"
  → 主智能体识别: 数据查询
  → 委派 nl2sql
  → 返回结果
```

### 多步委派（暂未实现）
未来可支持：
```
用户: "分析销售数据并生成报告"
  → 主智能体识别: 数据查询 + 报告生成
  → 先委派 nl2sql 查询
  → 再委派 report 生成
```

## run_sql LIMIT 规范（委派时必须附带）

每次委派 nl2sql 子智能体时，**必须在 prompt 中明确要求**：

```
【run_sql LIMIT 规范】
1. SQL 中不要写 LIMIT 子句
2. 改为通过 run_sql 的 limit 参数控制行数，例如 run_sql(sql="SELECT ...", limit=10)
3. 原因：run_sql 工具会在服务端自动追加默认 cap（1000 行），如果 SQL 中已有 LIMIT 会导致语法冲突
```

## 安全约束（委派时必须附带）

每次委派 nl2sql 子智能体时，**必须在 prompt 末尾固定追加**以下安全约束：

```
【安全规则（只读约束）】
你只能执行 SELECT 查询。严禁生成或执行任何 INSERT、UPDATE、DELETE、DROP、ALTER、CREATE、TRUNCATE、REPLACE、RENAME 语句。
在调用 run_sql 前，必须用 sqlparse 或正则校验 SQL 语句类型，确保只包含 SELECT。
如果用户要求修改数据，请拒绝并说明本系统为只读查询系统。
```

## 状态传递

委派时传递以下信息给子智能体：
- `config.configurable.db_name` — 当前选中的数据库
- `config.configurable.user_id` — 用户身份
- 原始用户问题

## 错误处理

| 场景 | 处理方式 |
|------|---------|
| 子智能体执行失败 | 向用户解释错误，建议解决方案 |
| 意图不明确 | 询问用户澄清需求 |
| 无匹配子智能体 | 告知用户当前不支持该功能 |

## 与子智能体的关系

- 主智能体 **不执行** 具体的数据查询或分析
- 主智能体 **不持有** 数据库连接或 SQL 工具
- 主智能体 **仅负责** 路由和协调
- 子智能体 **独立拥有** 完成其任务所需的全部工具和技能

## 子智能体结果信任规则（强制）

> **核心原则：子智能体返回的数据是最终结果，主智能体不得重复查询。**

### 规则一：禁止重复查库

当 `check_async_task` 返回 `status="success"` 且 `result` 包含数据时，主智能体**禁止**再次调用 `run_sql`、`query_cube` 或任何其他数据查询工具来获取相同数据。

### 规则二：优先使用 JSON 数据块

子智能体返回的 `result` 中，如果包含 ` ```json ` 代码块，主智能体应：
1. 解析该 JSON 数组作为原始数据
2. 直接用于渲染图表（renderChart）、计算或导出
3. **不得**为了获取"更完整"或"更结构化"的数据而重新查库

### 规则三：仅用 Markdown 描述呈现

如果子智能体返回的 `result` 中**没有** JSON 数据块，只有 Markdown 表格，主智能体：
1. 直接以 Markdown 格式呈现给用户
2. 如需图表，从 Markdown 表格中提取数据（而非重新查库）
3. 如果数据不足以渲染图表，告知用户数据不足，不自行查库补充

### 规则四：异常处理

| 场景 | 处理方式 |
|------|---------|
| 子智能体返回数据不完整 | 向用户说明已有数据范围，询问是否需要补充查询 |
| 子智能体返回数据有误 | 向用户报告错误，重新委派子智能体（带纠错指令） |
| 需要额外维度的数据 | 委派新的子智能体任务，不自行查库 |

## 报告导出职责划分

报告导出采用**分层职责**模式，不将 report-export 技能绑定到子智能体：

### 职责边界

| 角色 | 职责 | 说明 |
|------|------|------|
| **nl2sql 子智能体** | 只负责查询数据并返回结果 | 不生成报告文件，不写 Markdown |
| **主智能体** | 拿到结果后，调用 report-export 技能生成报告 | 使用 `write_file` 写入 `/workspace/report/` |

### 工作流程

```
用户请求数据查询
  → 主智能体委派 nl2sql 子智能体
  → nl2sql 返回查询结果（数据表格）
  → 主智能体读取 report-export 技能（/shared/skills/main/report-export/SKILL.md）
  → 主智能体按模板整理 Markdown 报告
  → 主智能体调用 write_file 写入 /workspace/report/
  → 主智能体告知用户文件路径
```

### 触发条件

主智能体在拿到 nl2sql 结果后，**评估数据特征和用户意图**判断是否激活 report-export 技能：

- 用户明确要求 → 强制激活："下载报告" / "导出为 Markdown" / "生成分析报告"
- 用户明确要求 → 强制激活："保存结果" / "把结果写成文件" / "生成 md 文件"
- 用户明确要求 → 强制激活："export report" / "save as markdown"
- 未明确要求时，仅当数据适合结构化呈现且生成报告有实际价值（多维度、较大量数据、分析结论复杂）才激活；简单计数、单值结果直接展示，不生成报告

### 模板使用

报告模板定义在 `/shared/skills/main/report-export/SKILL.md` 中，主智能体直接读取使用。
