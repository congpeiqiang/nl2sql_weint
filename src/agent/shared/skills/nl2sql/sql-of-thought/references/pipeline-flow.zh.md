# SQL-of-Thought 流水线流程

## 完整流水线架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        用户输入                                       │
│              自然语言问题 (Q)                                          │
└─────────────────────┬───────────────────────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    阶段 1：流水线前置                                 │
│                  Schema 知识准备                                      │
│                                                                      │
│  ┌─────────────┐   ┌──────────────┐   ┌──────────────┐             │
│  │ ingest_     │──→│ compile_     │──→│ wren context show  │             │
│  │ (验证)      │
│  └─────────────┘   └──────────────┘   └──────────────┘             │
│                                                                      │
│  使用：wren context show-compiler MCP 服务器                                  │
│  目的：从数据库 Schema 构建 MDL                                       │
└─────────────────────┬───────────────────────────────────────────────┘
                      │（如果 MDL 已构建，跳过）
                      ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    阶段 2：顺序流水线                                  │
│                                                                      │
│  步骤 1：Schema Linking Agent                                        │
│  ┌─────────────────────────────────────────────────┐                │
│  │ 输入：Q + db_id                                 │                │
│  │ 过程：wren context show → wren context show               │                │
│  │       → CoT schema linking 推理                  │                │
│  │ 输出：裁剪后的 Schema (S)                         │                │
│  └────────────────────┬────────────────────────────┘                │
│                       │                                              │
│                       ▼                                              │
│  步骤 2：子问题分解 Agent                                             │
│  ┌─────────────────────────────────────────────────┐                │
│  │ 输入：Q + S                                     │                │
│  │ 过程：意图分析 → 子句映射                         │                │
│  │ 输出：JSON 子问题 (C)                             │                │
│  │   {WHERE, GROUP BY, JOIN, HAVING, ...}          │                │
│  └────────────────────┬────────────────────────────┘                │
│                       │                                              │
│                       ▼                                              │
│  步骤 3：查询计划 Agent（关键：不生成 SQL）                           │
│  ┌─────────────────────────────────────────────────┐                │
│  │ 输入：Q + S + C                                 │                │
│  │ 过程：CoT 推理 → 过程性步骤                       │                │
│  │ 输出：过程性计划 (P) — 此处不生成 SQL              │                │
│  └────────────────────┬────────────────────────────┘                │
│                       │                                              │
│                       ▼                                              │
│  步骤 4：SQL 生成 Agent                                              │
│  ┌─────────────────────────────────────────────────┐                │
│  │ 输入：Q + P + S                                 │                │
│  │ 过程：计划→SQL 映射 → 后处理                      │                │
│  │ 输出：可执行 SQL (Y)                              │                │
│  └────────────────────┬────────────────────────────┘                │
│                       │                                              │
│                       ▼                                              │
│  步骤 5：数据库执行                                                  │
│  ┌─────────────────────────────────────────────────┐                │
│  │ 过程：对数据库执行 SQL                            │                │
│  │ 决策：成功 → 结束                                │                │
│  │       错误 → 阶段 3                              │                │
│  └────────────────────┬────────────────────────────┘                │
│                       │                                              │
│            ┌──────────┴──────────┐                                   │
│            │                     │                                   │
│         成功                   错误                                  │
│            │                     │                                   │
│            ▼                     ▼                                   │
│    ┌─────────────┐    ┌─────────────────────────────────┐           │
│    │   返回结果   │    │    阶段 3：纠错循环               │           │
│    └─────────────┘    │                                   │           │
│                       │  步骤 6：纠错计划 Agent           │           │
│                       │  ┌───────────────────────────┐   │           │
│                       │  │ 输入：失败的 SQL + 错误信息  │   │           │
│                       │  │       + Q + S + 分类法     │   │           │
│                       │  │ 过程：基于分类法的 CoT 诊断  │   │           │
│                       │  │ 输出：纠错计划              │   │           │
│                       │  └──────────────┬────────────┘   │           │
│                       │                 │                 │           │
│                       │                 ▼                 │           │
│                       │  步骤 7：纠错 SQL Agent           │           │
│                       │  ┌───────────────────────────┐   │           │
│                       │  │ 输入：纠错计划             │   │           │
│                       │  │       + Q + S + 失败的    │   │           │
│                       │  │       SQL                 │   │           │
│                       │  │ 过程：重新生成 SQL         │   │           │
│                       │  │ 输出：纠正后的 SQL         │   │           │
│                       │  └──────────────┬────────────┘   │           │
│                       │                 │                 │           │
│                       │                 ▼                 │           │
│                       │  重新执行 → 检查                  │           │
│                       │  ┌───────────────────────────┐   │           │
│                       │  │ 成功 → 返回结果            │   │           │
│                       │  │ 错误 → 重复（最多 3 次）   │   │           │
│                       │  │ 3 次失败 → 终止            │   │           │
│                       │  └───────────────────────────┘   │           │
│                       └─────────────────────────────────┘           │
└─────────────────────────────────────────────────────────────────────┘
```

## 决策逻辑

### 何时进入纠错循环？

| 条件 | 操作 |
|------|------|
| SQL 执行成功并返回预期结果 | → 结束（返回结果） |
| SQL 抛出执行错误（语法、运行时） | → 进入纠错循环 |
| SQL 执行成功但返回逻辑错误的结果 | → 进入纠错循环 |
| 纠错尝试中重复出现相同的错误编码 | → 终止（陷入僵局） |
| 3 次纠错尝试用尽 | → 终止（达到最大尝试次数） |

### 何时跳过步骤？

| 条件 | 操作 |
|------|------|
| target/mdl.json 存在且 Schema 未变更 | → 跳过阶段 1 |
| 问题很简单（单表，无 JOIN/聚合） | → 步骤 2-3 可简化但不可跳过 |
| SQL 首次尝试即成功 | → 完全跳过阶段 3 |

## Agent 交互与数据流

```
Q ──→ Schema Linking ──→ S ──→ 子问题分解 ──→ C ──→ 查询计划 ──→ P ──→ SQL 生成 ──→ Y
                                                                      │
                                                                      ▼
                                                              数据库执行
                                                              │        │
                                                           成功      错误
                                                              │        │
                                                              ▼        ▼
                                                          返回结果   纠错循环：
                                                                      │
                                                                      ▼
                                                              Y_fail + 错误 + T
                                                                      │
                                                                      ▼
                                                              纠错计划 ──→ Plan_fix
                                                                      │
                                                                      ▼
                                                              纠错 SQL ──→ Y_corrected
                                                                      │
                                                                      ▼
                                                              数据库执行（重新检查）
```

## 关键形式化定义

整个流水线形式化为：

**Y = LLM(Q, S, C, P, T | θ)**

| 变量 | 含义 | 来源 |
|------|------|------|
| Q | 自然语言问题 | 用户输入 |
| S | 链接后的 Schema（裁剪后） | Schema Linking Agent |
| C | 子句级子问题（JSON） | 子问题分解 Agent |
| P | 过程性查询计划（CoT） | 查询计划 Agent |
| T | 错误分类法（31 个子类） | 纠错计划 Agent |
| θ | LLM 参数 | 模型选择 |
| Y | 最终可执行的 SQL 输出 | SQL Agent / 纠错 SQL Agent |
