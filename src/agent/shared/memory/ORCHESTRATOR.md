## 一、自动编排链路（按需评估）

数据查询类任务完整链路如下，其中图表和报告由模型根据数据特征和用户意图**按需评估**是否生成：

1. **nl2sql 查询（必选）** — 委派 nl2sql 子智能体获取结构化数据
2. **推荐图表（可选）** — suggestCharts 分析数据特征
3. **渲染图表（可选）** — renderChart / generate_echarts 渲染可视化
4. **保存图表到文件（条件必选）** — 若生成了图表，必须保存到 `/workspace/report/`
5. **report-export 生成报告（可选）** — 数据表 + 图表引用 + 分析解读 → Markdown 报告

### 执行时机
- **适合图表**：数据有可对比的趋势、分布、占比、排名等可视化价值
- **适合报告**：数据量大、多维度分析、用户明确要求、或结果适合结构化呈现
- **直接展示即可**：简单计数（"有几个表"、"多少条记录"）、单值结果（"最大值是X"）——不生成图表/报告

### 用户显式要求 → 强制生成
- 说"画图"、"可视化"、"图表" → **必须**生成图表
- 说"报告"、"导出"、"生成文档" → **必须**生成报告
- 说"画图并导出报告" → 两者都强制生成

### 最终回复呈现
数据结果 + 图表（如有） + 报告路径（如有）。

## 二、取消任务铁律（强制）

**禁止主动调用 `cancel_async_task`**，除非用户明确说"取消"、"停掉"、"不要了"、"终止"。

即使遇到以下情况也不得主动取消：
- run_sql 执行超时或长时间无响应
- 子智能体报错
- 你认为需要重试或换方案

**正确做法：** 向用户报告当前状态，等待用户指令。

## 三、查询超时处理（强制）

子智能体 run_sql 长时间无响应时：
1. **禁止主动取消任务**
2. **禁止主动重试或换方案**
3. **正确做法：** 向用户报告当前状态（已执行多久），询问是否要取消或缩小范围
4. 等用户明确给出指令后再行动

## 四、空结果警觉（强制）

子智能体可能对空结果产生**幻觉**，编造看似合理的数据（2026-08-15 实测）。

- 子智能体返回数据时，检查其 `latest_thinking` 是否有"返回0行"、"排查数据"等异常信号——有则实际查询可能为空
- 对关键查询可额外委派验证任务，用 `SELECT count(*)` 确认数据量 > 0
- 用户反馈"查询为空"时，立即触发排查，不默认子智能体结果正确
- 呈现结果时关注 `latest_thinking` 字段，可能暴露真实执行情况

## 五、禁止发散问题（强制）

**委派任务给 nl2sql 子智能体时，必须原样传达用户问题，禁止扩展或补充。** 用户问什么就委派什么。

- 用户问"有多少个表" → 只委派"查询表的个数"，**不要**补充"并查每个表的行数"
- 用户问"某表有哪些字段" → 只委派"列出字段"，**不要**补充"并统计字段分布"
- 用户问"某字段最大值" → 只委派"查最大值"，**不要**补充"顺便查最小值、平均值"

**委派原则：** 需要补充信息时，先拿到结果，再向用户确认是否需要。

## 六、图表保存原则

- 遵循引擎自带机制：echarts 自动落盘 SVG/HTML 到 `/workspace/report/`，PNG 自动复制到工作区
- 需要显式保存时调用 `chart-saver` 技能；**禁止**手动写 Python 脚本处理图表文件（如解码 base64 提取 SVG）
- 报告中的图表引用用**相对路径**；报告文件名须含完整时间戳 `{report-name}_{YYYY-MM-DD_HH-mm-ss}.md`
