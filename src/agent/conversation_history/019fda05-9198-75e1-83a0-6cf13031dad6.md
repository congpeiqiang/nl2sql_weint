    55	
    56	### LangGraph / LangChain apps (automatic)

   147	## AgentSeek Trace Structure
   148	
   149	Our templates produce traces with this typical hierarchy:
   150	
   151	```
   152	&lt;agent_name&gt; (root chain)
   153	├── SkillsMiddleware.before_agent
   154	├── PatchToolCallsMiddleware.before_agent
   155	├── MemoryMiddleware.before_agent
   156	├── model (chain) ← LLM turn
   157	│   ├── TodoListMiddleware.awrap_model_call
   158	│   ├── SkillsMiddleware.awrap_model_call
   159	│   ├── FilesystemMiddleware.awrap_model_call
   160	│   ├── SubAgentMiddleware.awrap_model_call
   161	│   ├── SummarizationMiddleware.awrap_model_call
   162	│   ├── AnthropicPromptCachingMiddleware.awrap_model_call
   163	│   ├── MemoryMiddleware.awrap_model_call
   164	│   └── ChatOpenAI (llm) ← actual LLM call (inputs/outputs here)
   165	├── TodoListMiddleware.after_model
   166	├── tools (chain) ← tool execution
   167	│   ├── FilesystemMiddleware.awrap_tool_call
   168	│   └── &lt;tool_name&gt; (tool) ← actual tool (inputs/outputs here)
   169	├── model (chain) ← next LLM turn
   170	│   └── ... (same middleware stack)
   171	└── TodoListMiddleware.after_model
   172	```
   173	
   174	Key points:
   175	- The **actual LLM call** is always the innermost `ChatOpenAI` run
   176	- **Tool results** are in the `&lt;tool_name&gt;` run (e.g., `generate_cover`, `execute`)
   177	- Middleware wrappers are transparent — they add latency but the IO you care about is at the leaf nodes
   178	
   179	## Gotchas
   180	
   181	### `--full` vs `--include-io` on individual runs
   182	
   183	**Problem:** `langsmith run get &lt;id&gt; --full` can return null for inputs/outputs, even though the data exists. Despite `--full` being documented as equivalent to `--include-metadata --include-io --include-feedback`, the underlying API behavior differs for individual run fetches in some CLI versions.
   184	
   185	**Solution:** Always use `--include-io` explicitly when inspecting specific runs:
   186	```bash
   187	# DO THIS
   188	langsmith run get &lt;run-id&gt; --include-io
   189	
   190	# NOT THIS (may return null IO despite docs saying it includes --include-io)
   191	langsmith run get &lt;run-id&gt; --full
   192	```
   193	
   194	`--full` works reliably on `trace export` and `run list`, but has inconsistent behavior on individual `run get` calls. If this is fixed in a future CLI version, `--include-io` still works correctly — it's always safe.
   195	
   196	### Null IO even with `--include-io`
   197	
   198	If inputs/outputs come back null even with `--include-io`, the project has IO logging disabled. Check for these environment variables in the template's `.env`:
   199	
   200	```bash
   201	LANGCHAIN_HIDE_INPUTS=true    # hides inputs from traces
   202	LANGCHAIN_HIDE_OUTPUTS=true   # hides outputs from traces
   203	```
   204	
   205	Remove or set to `false` to enable IO capture for debugging.
   206	
   207	### Project confusion
   208	
   209	LangGraph apps trace to the `"default"` project unless `LANGSMITH_PROJECT` is explicitly set. Always run `langsmith project list` first and check `last_run_start_time` to find where your traces actually landed.
   210

   212	
   213	- Add `--format pretty` for human-readable output during interactive debugging
   214	- Use `LANGSMITH_ENDPOINT` env var if connecting to a self-hosted LangSmith instance
   215	- The middleware ordering in the trace tree is configurable — your template may differ slightly from the diagram above

## 📡 追踪功能（Tracing）能干什么

当 `LANGSMITH_TRACING=true` 时，你的 **nl2sql 应用每次运行都会自动把执行过程上报到 LangSmith 云端**，形成一条条 **trace（追踪记录）**。它就像给应用装了一个"黑匣子记录仪"。

### 1️⃣ 可视化执行全流程
每次查询，LangSmith 会记录完整的调用树（run tree），你能看到：
```
nl2sql (根节点)
├── SkillsMiddleware.before_agent      ← 技能加载
├── MemoryMiddleware.before_agent      ← 记忆注入
├── model (LLM 调用)                    ← 每次大模型思考
│   ├── TodoListMiddleware.awrap_model_call
│   ├── SkillsMiddleware.awrap_model_call
│   └── ChatOpenAI (实际 LLM 请求)      ← 输入/输出在这里
├── tools (工具执行)
│   ├── run_sql (SQL 执行)              ← 工具输入/输出
│   ├── schema-linking (Schema 链接)
│   └── ...
└── model (下一轮 LLM 调用)
```

### 2️⃣ 调试问题（核心价值）
- **看 LLM 到底想了什么** — 每次模型调用的 prompt 和输出
- **看工具传了什么、返回了什么** — 比如 `run_sql` 执行的 SQL 和结果
- **定位卡在哪一步** — 是 SQL 生成错了？还是工具超时？还是中间件报错？

### 3️⃣ 性能分析
- 查看每个环节的**耗时**（LLM 调用、工具执行、中间件）
- 找出**慢的 trace**，定位性能瓶颈
- 对比不同查询的耗时差异

### 4️⃣ 成本与用量统计
- 统计 token 消耗、调用次数
- 按项目/时间维度分析用量

### 5️⃣ 可观测性 &amp; 监控
- 在 LangSmith 网页端（smith.langchain.com）实时查看运行状态
- 排查线上问题、回放历史执行

# Install script for the langsmith CLI.
#
# Usage:
#   curl -fsSL https://cli.langsmith.com/install.sh | sh
#
# Environment variables:
#   INSTALL_DIR   directory to install into (default: /usr/local/bin when writable,
#                 otherwise $HOME/.local/bin)

set -eu

# ---------------------------------------------------------------------------
# Configuration
# ---------------------------------------------------------------------------

REPO="langchain-ai/langsmith-cli"
CLI_NAME="langsmith"
BINARY_NAME="langsmith"
ARCHIVE_EXT="tar.gz"
CHECKSUMS_NAME="checksums.txt"
RELEASE_API_URL="https://api.github.com/repos/${REPO}/releases/latest"
DOWNLOAD_BASE_URL="https://github.com/${REPO}/releases/download"
SYSTEM_INSTALL_DIR="/usr/local/bin"
USER_INSTALL_SUBDIR=".local/bin"
FETCH_ATTEMPTS=3

# ---------------------------------------------------------------------------
# Functional core
#
# Pure helpers: every input arrives as an argument or on stdin, every result
# goes to stdout, and nothing here reads the environment or touches disk. The
# resolve_* helpers print nothing and return non-zero when a value is
# unsupported, leaving the error message to the caller.
# ---------------------------------------------------------------------------

# Map `uname -s` onto a goreleaser OS name.
resolve_os() {
  case "$(printf '%s' "$1" | tr '[:upper:]' '[:lower:]')" in
    linux) printf 'linux' ;;
    darwin) printf 'darwin' ;;
    *) return 1 ;;
  esac
}

# Map `uname -m` onto a goreleaser arch name.
resolve_arch() {
  case "$1" in
    x86_64 | amd64) printf 'amd64' ;;
    arm64 | aarch64) printf 'arm64' ;;
    *) return 1 ;;
  esac
}

# resolve_archive_name &lt;os&gt; &lt;arch&gt;
resolve_archive_name() {
  printf '%s_%s_%s.%s' "$CLI_NAME" "$1" "$2" "$ARCHIVE_EXT"
}

# resolve_install_dir &lt;override&gt; &lt;system_dir_writable: yes|no&gt; &lt;home&gt;
#
# An explicit override wins, then the system directory when the caller found it
# writable, then the per-user fallback.
resolve_install_dir() {
  if [ -n "$1" ]; then
    printf '%s' "$1"
  elif [ "$2" = yes ]; then
    printf '%s' "$SYSTEM_INSTALL_DIR"
  else
    printf '%s/%s' "$3" "$USER_INSTALL_SUBDIR"
  fi
}

# Read release JSON on stdin, print its tag_name.
resolve_tag_name() {
  sed -n 's/.*"tag_name"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' | head -n 1
}

# resolve_expected_checksum &lt;archive_name&gt;
#
# Reads checksums.txt on stdin and prints the hash recorded for the archive.
# Matches the whole file-name field: a bare prefix match would accept the hash
# of a different, longer asset name.
resolve_expected_checksum() {
  awk -v want="$1" '
    {
      name = $2
      sub(/^\*/, "", name)  # sha256sum marks binary mode with a leading *
      if (name == want) { print $1; exit }
    }
  '
}

# path_contains_dir &lt;dir&gt; &lt;path_value&gt;
path_contains_dir() {
  case ":$2:" in
    *":$1:"*) return 0 ;;
    *) return 1 ;;
  esac
}

# format_path_instructions &lt;dir&gt;
format_path_instructions() {
  printf '%s\n' \
    "" \
    "Add $1 to your PATH:" \
    "  export PATH=\"$1:\$PATH\"" \
    "" \
    "To make it permanent, add that line to your ~/.bashrc or ~/.zshrc"
}

# ---------------------------------------------------------------------------
# Imperative shell
#
# Everything below reads the environment, talks to the network, or writes to
# disk.
# ---------------------------------------------------------------------------

log() { printf '%s\n' "$*"; }
warn() { printf '%s\n' "$*" &gt;&amp;2; }
die() {
  warn "$*"
  exit 1
}

get_platform_name() { uname -s; }
get_machine_name() { uname -m; }

# GITHUB_TOKEN, then an authenticated gh, then anonymous.
fetch_release_json() {
  if [ -n "${GITHUB_TOKEN:-}" ]; then
    curl -fsSL -H 'Accept: application/vnd.github+json' \
      -H "Authorization: Bearer ${GITHUB_TOKEN}" "$RELEASE_API_URL"
  elif command -v gh &gt;/dev/null 2&gt;&amp;1; then
    gh api -H 'Accept: application/vnd.github+json' \
      "repos/${REPO}/releases/latest" 2&gt;/dev/null ||
      curl -fsSL -H 'Accept: application/vnd.github+json' "$RELEASE_API_URL"
  else
    curl -fsSL -H 'Accept: application/vnd.github+json' "$RELEASE_API_URL"
  fi
}

# Print the latest release tag, or return non-zero once the retries are spent.
fetch_latest_version() {
  local attempt tag
  attempt=1
  while [ "$attempt" -le "$FETCH_ATTEMPTS" ]; do
    tag="$(fetch_release_json 2&gt;/dev/null | resolve_tag_name || true)"
    if [ -n "$tag" ]; then
      printf '%s' "$tag"
      return 0
    fi
    [ "$attempt" -lt "$FETCH_ATTEMPTS" ] &amp;&amp; sleep "$attempt"
    attempt=$((attempt + 1))
  done
  return 1
}

# download_file &lt;url&gt; &lt;dest&gt;
download_file() {
  # -f so an HTTP error page is never saved as if it were the archive.
  curl -fsSL -o "$2" "$1"
}

# file_sha256 &lt;path&gt;
file_sha256() {
  if command -v sha256sum &gt;/dev/null 2&gt;&amp;1; then
    sha256sum "$1" | awk '{print $1}'
  elif command -v shasum &gt;/dev/null 2&gt;&amp;1; then
    shasum -a 256 "$1" | awk '{print $1}'
  else
    return 1
  fi
}

# verify_checksum &lt;archive_path&gt; &lt;archive_name&gt; &lt;checksums_path&gt;
verify_checksum() {
  local expected actual
  expected="$(resolve_expected_checksum "$2" &lt;"$3")"
  if [ -z "$expected" ]; then
    warn "Warning: $2 is not listed in ${CHECKSUMS_NAME}; skipping verification"
    return 0
  fi

  if ! actual="$(file_sha256 "$1")"; then
    warn "Warning: cannot verify checksum (no sha256sum or shasum found)"
    return 0
  fi

  if [ "$actual" != "$expected" ]; then
    warn "Checksum verification failed for $2"
    warn "  Expected: ${expected}"
    warn "  Actual:   ${actual}"
    exit 1
  fi
}

# install_binary &lt;source_path&gt; &lt;install_dir&gt;
install_binary() {
  mkdir -p "$2"
  mv "$1" "$2/${BINARY_NAME}"
  chmod +x "$2/${BINARY_NAME}"
}

main() {

  machine="$(get_machine_name)"

  install_dir="$(resolve_install_dir "${INSTALL_DIR:-}" "$system_writable" "${HOME:-}")"

      warn "Failed to determine latest version (GitHub API unreachable or rate-limited)."
      die "Set GITHUB_TOKEN, run 'gh auth login', or set VERSION to install a specific release."
    fi
  fi

  archive_url="${DOWNLOAD_BASE_URL}/${release_tag}/${archive_name}"
  checksums_url="${DOWNLOAD_BASE_URL}/${release_tag}/${CHECKSUMS_NAME}"

  TMP_DIR="$(mktemp -d)"
  trap 'rm -rf "$TMP_DIR"' EXIT INT TERM

  tar -xzf "$archive_path" -C "$extract_dir"

  source_binary="${extract_dir}/${BINARY_NAME}"
  [ -f "$source_binary" ] || die "Archive did not contain ${BINARY_NAME}"

  install_binary "$source_binary" "$install_dir"
  log "Installed ${CLI_NAME} to ${install_dir}/${BINARY_NAME}"

  path_contains_dir "$install_dir" "${PATH:-}" || format_path_instructions "$install_dir"

  log ""
  log "Run: ${CLI_NAME} --version"
}

main "$@"
