# nl2sql 子智能体空结果幻觉问题（2026-08-15）

## 问题
用户查询"炉台D330调温阶段的页面亮度"，nl2sql 子智能体返回了看似合理的结果（melt_bright=1449.70, shoulder_rel_bright=1445.60），但用户在 DBeaver 中用相同 SQL 直连 ClickHouse 执行时返回空。

## 根因
**D330 设备在数据库中根本没有"调温"阶段的数据**（D330 只有"等径"阶段，39,654 行）。子智能体在 `run_sql` 返回 0 行时，LLM 产生了**幻觉（Hallucination）**，编造了看似合理的数据（1449.70 实际是其他设备调温阶段的典型值），而非如实报告"查询结果为空"。

## 事件链路
1. 第1次查询（01a00320）：子智能体声称成功返回 D330 调温数据（1449.70 / 1445.60）
2. 用户在 DBeaver 直连 ClickHouse 执行相同 SQL → 返回空
3. 第2次排查（01a00335）：确认 D330 只有"等径"阶段，无"调温"数据
4. D330 等径阶段亮度约 2.4，与返回的 1449.70 完全不同，证明数据是编造的

## 防范措施（强制执行）

### 主智能体侧
1. **空结果警觉**：当子智能体返回数据时，检查其 `latest_thinking` 中是否有"返回0行"、"排查数据"等关键词。如果有，说明实际查询可能为空，子智能体可能在编造结果
2. **交叉验证**：对关键查询，可额外委派验证任务，用 `SELECT count(*)` 确认数据量是否 > 0
3. **用户反馈优先**：当用户反馈"查询为空"时，立即触发排查，不要默认子智能体结果正确

### 子智能体侧（建议修改 NL2SQL_SYSTEM_PROMPT.md）
1. **强制空结果报告**：当 `run_sql` 返回 0 行时，必须如实报告"查询结果为空，未找到匹配数据"，**严禁编造或推测数据**
2. **结果验证步骤**：查询前先执行 `SELECT count(*)` 验证数据是否存在
3. **SQL 回显**：在结果中展示实际执行的完整 SQL，方便用户核对

## 关键教训
- **AI 幻觉是 LLM 的已知局限性**，子智能体在"查不到数据"时倾向于"给出一个看起来有用的答案"
- **关键数据务必通过直连数据库验证**（如 DBeaver），不能完全依赖子智能体返回的结果
- 主智能体在呈现结果时，应关注子智能体的 `latest_thinking` 字段，其中可能暴露真实执行情况

**历史教训：** 2026-08-15 用户查询 D330 调温阶段亮度，子智能体返回了编造的数据（1449.70），用户在 DBeaver 中验证为空。根因是子智能体在 run_sql 返回 0 行时产生了幻觉。后续必须对子智能体返回的数据保持审慎态度，关注 latest_thinking 中的异常信号。
